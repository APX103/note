1. 系统架构：谁在哪块板上

两块 WeAct ESP32-S3 通过乐鑫的 ESP-NOW（免连接点对点协议，单程 1–4ms）相连。 设计原则：所有智能都在鼠标端，接收端是哑桥——这样有线版验证过的算法一行不改就能搬过来。

系统架构：算法全部在鼠标端，接收端只做「无线包 → HID 报文」的翻译

传感器选型的插曲：项目最初的主角是 BNO085（Hillcrest 血统、LG 遥控器同源芯片）， 但手上那颗因一次误接（GND→3.3V + SCL→GND）导致 SCL 引脚内部 ESD 二极管烧熔对地短路—— SDA 和 INT 都活着、固件还会做协议握手，唯独 SCL 永远是 0V。遂换微雪 ICM-20948 + 自研融合。BNO085 支持仍保留在固件里（sensor bno 切换）。

2. 姿态融合：Madgwick 6 轴 AHRS

目标是持续获得姿态四元数 q（约定：v_{world} = q ⊗ v_{body} ⊗ q^*， 世界系 Z 轴 = 重力反方向向上）。6 轴（陀螺+加计）融合的性质决定了后面所有设计：

  • pitch / roll 不漂：加速度计直接「看见」重力方向，是绝对参考。实测 5 分钟漂移 0.018 / 0.002 °/min——噪声地板。
  • yaw 慢漂：绕重力轴的旋转在 6 轴方案里无绝对参考，纯陀螺积分，实测 0.56°/min。对策见 §4/§5。

2.1 算法骨架（~100 行，零依赖）

Madgwick 的思想：陀螺管快速跟踪，加计管长期纠偏。每步两件事——

① 陀螺外推：  q̇gyro = ½ q ⊗ [0, ω]   (ω = 陀螺角速度，已扣除零偏)
② 重力对齐：预测的机体系重力方向   h(q) = (2(zx−wy),   2(wx+zy),   1−2(x²+y²))
与加计实测 â 求误差 e = h − â，对 q 求梯度 ∇ = JTe，沿负梯度方向修正（步长 β） 
// madgwick.h —— 核心一步（完整实现见 code/madgwick.h）
// 陀螺积分项
float dqw = 0.5f * (-x*gx - y*gy - z*gz);  // … dqx/dqy/dqz 同理
// 加计梯度修正：e = h(q) - a，梯度 ∇=Jᵀe，归一化后按 β 步长回拉
if (al > 0.3f) {                              // 加计有效（不在自由落体/大机动）
  float ex = hx - ax, ey = hy - ay, ez = hz - az;  // 重力方向误差
  float gwv = -2*y*ex + 2*x*ey,  gxv = 2*z*ex + 2*w*ey - 4*x*ez, // Jᵀe
        gyv = -2*w*ex + 2*z*ey - 4*y*ez, gzv = 2*x*ex + 2*y*ey;
  float gn = sqrtf(gwv*gwv + gxv*gxv + gyv*gyv + gzv*gzv);
  if (gn > 1e-6f) { float s = beta / gn;      // β=0.12：信任加计的强度
    dqw -= gwv*s; dqx -= gxv*s; dqy -= gyv*s; dqz -= gzv*s; }
}
q = qnorm(q + qDot*dt);                              // 归一化防发散

2.2 开机零偏标定

上电静置 1.5 秒，平均 150 帧陀螺得零偏（典型 0.3–0.6 dps）后全程扣除。 这是 yaw 漂移大小的第一决定因素——标定期间板子必须真的静止。

教训 #1（假速度）：项目早期用「四元数帧间差分」当角速度， 静止时读数 10–13°/s——那不是运动，是噪声地板（差分把逐帧噪声整流成了正速度）。 它骗过了静止检测（冻结从未触发过），在积分模式里更把噪声积成光标狂漂。 正解：角速度永远直接读陀螺，噪声低两个数量级；四元数只用来做坐标变换。

3. 指针算法：无限积分（核心）

最终形态是「无限积分 + 重力系分解」——与 LG Magic Remote / Hillcrest 商用空鼠同族。 一句话：光标速度 = 设备角速度 × 灵敏度，永无边界；屏幕边缘的停靠交给操作系统。

3.1 为什么必须「无限」——鼠标协议的本质

USB 鼠标是纯增量协议：设备只发 dx/dy，操作系统才是位置的积分器。 所以设备侧任何「位置」概念都只是自说自话的影子模型，它和真实光标之间隔着 一个不可观测的偏移（开机时光标在哪由 Windows 决定）。由此得出两条铁律：

① 模型必须无界积分，永不钳制——钳制模型 = 在屏幕中间凭空造墙（§4 详述）；
② 屏幕边缘行为完全交给 OS：真实光标到边后系统丢弃继续的增量，回转一度、负增量立刻生效——与实体鼠标完全一致，零死区。

3.2 重力系分解：roll 免疫的数学

裸用机体系陀螺积分有个著名问题：手腕内旋（roll）会串扰到光标 XY。 解法是先把角速度旋到世界系再取分量：

ωw = R(q) · ωbody     yawRate = ωw · ẑ    （水平：绕竖直轴的分量）
elevRate = ωw · unit(d × ẑ)    （垂直：绕「当前指向的水平垂直轴」的分量）

因为 ẑ 由重力锚定（不随手腕内旋转动），roll 只改变 d 的方位、不改变 ω 在这两个轴上的投影语义 → 手腕怎么拧，上下左右语义不变。 这正是 Hillcrest 专利 US7158118B2「倾角补偿」要做的事，ray-cast 时代我们靠几何实现，积分模式靠世界系分解实现。

// pointer.cpp · onQuatRate() —— 无限积分核心（完整版见 code/pointer.cpp）
Vec3 w_w = qrot(q, gyroBody);                  // 陀螺角速度 → 世界系（°/s）
float yawRate  = w_w.z;                        // 绕竖直轴 = 水平移动
Vec3  elevAxis = vnorm(vcross(horiz(d), Vec3{0,0,1}));
float elevRate = vdot(w_w, elevAxis);           // 绕水平垂轴 = 垂直移动

yawRate  = softdb(yawRate);                    // ±0.5°/s 软死区：消化陀螺白噪
elevRate = softdb(elevRate);
if (par->invX) yawRate = -yawRate;
if (par->invY) elevRate = -elevRate;

float gainX = (par->scrW - 1) / par->fovH;   // FOV=灵敏度：fov 75° ⇔ 转75°走一个屏宽
float gainY = (par->scrH - 1) / par->fovV;
Xf += yawRate  * dt * gainX;                   // 无界积分 —— 绝不 clamp！
Yf += -elevRate * dt * gainY;

3.3 FOV 的最终语义：纯灵敏度

项目早期 FOV 是「指向窗口」（±FOV/2 映射到屏幕边），撞出各种墙感后被推翻。 最终语义只剩一条：灵敏度 = 屏宽 / fovH  (px/°)。 fov 50 = 转 50° 扫满全屏（灵敏），fov 90 = 转 90° 才扫满（细腻）。 数字有清晰物理含义，用户调参不用猜。

3.4 曾用方案：ray-cast 绝对指点（保留为 mode abs）

「指哪打哪」的几何实现：姿态四元数构造指向射线，与虚拟屏幕平面求交得光标位置， roll 天然免疫。它是理解指针问题的绝佳教材，但屏幕有限 + 模型/OS 偏移使它必然带边界感， 最终让位于无限积分。代码保留可切换，调研与推导见仓库 docs/。

4. 空气墙剖析：本项目的中心教训

用户反复报告「缓慢摆动会遇到确定性的墙：一个方向卡死、垂直方向自由」。 三轮误诊（FOV 窗口太近 → tanh 软边界 → 解冻阈值）后，真凶落网：

空气墙机理：模型与真实光标之间隔着开机即存在的未知偏移。 模型先撞自己的钳制 → dx=0 → 真实光标在屏幕中间被冻住；另一轴未到界 → 仍自由。
教训 #2（空气墙）：在增量协议里给自己的影子模型加边界钳制， 等于把墙建在了「模型坐标系」而非真实屏幕上——偏移多少，墙就离真实边缘差多少。 修复只需删掉两行 clamp：模型无界积分，屏幕边缘交给 OS。 （用户从头到尾的直觉「鼠标就该是无限 dx/dy」是完全正确的架构判断。）

5. 静止冻结与点击冻结

5.1 静止冻结（状态机）

静止检测：speedEma = EMA(‖ωgyro|)   进入冻结：< 1.2°/s 持续 900ms   解冻：EMA > 2.0°/s 或瞬时 ‖ω‖ > 2.5°/s

冻结期间不积分 → 静止时陀螺零偏残余（<0.5°/s 死区之下本就为零，双保险） 完全无法变成光标漂移；解冻用「瞬时值或」条件保证从静止开始的缓慢移动也立刻响应。

教训 #3（解冻阈值）：解冻阈值 6°/s 是给「假速度时代」（静止读 13°/s）定的； 换真陀螺后忘了收紧，结果静止后 2–5°/s 的轻推永远够不着解冻线——「它不动了」。 教训：换数据源时，围绕旧数据标定的所有阈值都要重新审计。

5.2 点击冻结（学 Hillcrest 专利）

按键按下瞬间手会下压抖动，光标一滑点击就变拖拽。对策（US7535456B2 思想）： 按下 → 冻结光标（只发按键、不发位移）；按住超时 且 姿态转过大角度 → 解冻转拖拽； 否则松键完成一次「按哪点哪」的干净点击。

6. One-Euro 滤波与手感调音

光标位置层套 One-Euro：低速强低通（静止稳如老狗）、高速弱低通（甩动跟手）， 截止频率随速度自适应：fc = fc_min + β·|dX/dt|。 参数串口热调（euro 1.0 0.007）——「粘」还是「跟手」，一个 β 解决。 外加 1px 静止死区。

7. 无线链路：airlink over ESP-NOW

// airlink.h —— 10/14 字节，两端各持一份拷贝（Arduino 目录限制）
typedef struct {
  uint16_t magic;   // 0xA179
  uint16_t seq;     // 去重
  int16_t  dx, dy;  // 位移增量（核心载荷）
  uint8_t  buttons; // 每包全量重发，丢包不怕
  uint8_t  flags;   // ABS=带绝对坐标 / WARP=瞬移
  int16_t  absX, absY;
} airlink_pkt_t;   // + crc8(poly 0x31) 尾字节
机制设计为什么
位移包有增量即发（≤250Hz），静止静默省射频 + 省电
心跳包500ms 一发，带模型绝对坐标丢包造成的两端模型偏差 >2px 自动补差
按键每包全量重发丢包最不能容忍的是按键丢失
配对鼠标端广播；接收端锁第一个合法源 MAC，断链 10s 解锁零配置、防串台
信道双端显式钉死信道 1未关联 STA 的默认信道受 NVS 历史影响，可能各在各道（教训 #5）

8. RTOS 任务架构

Arduino-ESP32 底层本就是 FreeRTOS，关键在于把时间关键管线从 Arduino 主循环里拆出来：

xTaskCreatePinnedToCore(pipelineTask, "pipe", 8192, nullptr, 20, nullptr, 1);
// 优先级 20（Arduino loop=1），核心 1（WiFi 协议栈在核 0）
// pipelineTask: 按键 → IMU读取 → 融合 → 指针 → 无线发送，1ms 节拍
// loop(): 串口调参 shell、遥测打印、LED —— 永远不敢再挡采样的路

附加降温措施：CPU 240→160MHz（融合 0.02ms/次毫无压力）+ WiFi 发射 19.5→10dBm，芯片从烫手降到 ~65°C。
