Agent SSH Tool 插件设计方案

面向通用 Agent 的远程机器控制抽象设计 —— 以 Kimi CLI 为例场景

1. 设计目标

为 Agent 提供一套安全、异步、可观测、可交互的远程机器控制能力，满足：

  • 基础能力：SSH 登录、执行命令、文件传输
  • 任务能力：任务排队、前台/后台任务、状态机、超时/取消/重试
  • 可观测：日志实时回传、结构化存储、执行回放
  • 智能：错误分类、根因分析、修复建议
  • 抽象性：不绑定具体 Agent 实现、编程语言或部署形态

2. 设计原则

原则说明
Agent 与执行引擎解耦Agent 只通过统一 API/协议与 SSH Tool 交互，不直接持有 SSH 连接
一切皆任务登录、执行命令、传文件、交互式会话都抽象为 Task
默认异步所有远程操作都是异步的，Agent 通过 task_id 查询或订阅结果
前后台统一模型前台任务和后台任务共用同一套状态机和执行引擎，仅调用语义不同
连接可复用对同一主机维护会话池，减少频繁建连开销
安全优先凭证不落地、最小权限、操作审计、会话隔离

4. 核心抽象

4.1 Task（任务）

一次对远程机器的操作请求，是系统的最小调度单元。

Task:
  task_id: string          # 全局唯一
  task_type: enum          # exec / shell / upload / download / interactive / ping
  host: HostRef            # 主机引用
  command?: string         # 执行内容
  interpreter?: string     # shell / python / powershell / cmd
  environment: map         # 环境变量
  working_dir?: string     # 工作目录
  mode: enum               # foreground / background
  priority: int            # 优先级，数值越小越优先
  timeout_ms: int          # 任务超时
  max_retries: int         # 失败重试次数
  created_by: AgentRef     # 调用者标识
  state: TaskState         # 当前状态
  session_id?: string      # 关联的 SSH 会话
  parent_task_id?: string  # 父任务（用于任务链）
  metadata: map            # Agent 透传的上下文

4.2 Host（主机）

Host:
  host_id: string
  hostname: string         # IP 或域名
  port: int                # 默认 22
  username: string
  credential_ref: string   # 凭证引用，不直接存密码/密钥
  labels: map              # 标签，用于批量选择
  max_sessions: int        # 该主机最大并发会话数

4.3 Session（会话）

Session:
  session_id: string
  host_id: string
  state: idle / busy / closed
  channel_type: exec / shell / sftp
  created_at: timestamp
  last_used_at: timestamp

4.4 Credential（凭证）

Credential:
  credential_id: string
  type: password / private_key / ssh_agent / token
  encrypted_data: bytes
  allowed_hosts: list      # 可选的主机白名单
  expires_at?: timestamp

5. 任务状态机

所有任务共用同一套状态机：

Pending → Queued → Preparing → Connecting → Running
                                              │
                    ┌─────────┬──────────────┼──────────────┐
                    ▼         ▼              ▼              ▼
              Succeeded  Streaming   AwaitingInteraction  Failed → Retry
                                                    │
                                                    ▼
                                              Cancelled / Timeout
状态含义
Pending已创建，尚未进入队列
Queued在队列中等待调度
Preparing分配 Worker、加载凭证、检查权限
Connecting建立 SSH 连接
Running命令正在执行
Streaming持续有输出（可与 Running 合并，也可独立用于流式任务）
AwaitingInteraction命令等待用户输入，需要交互式会话接管
Succeeded成功结束
Failed失败，可能可重试
Cancelled被主动取消
Timeout执行超时

状态迁移规则：

  • 状态迁移只能沿允许的边进行
  • 每次状态变更产生 TaskEvent，写入事件流
  • 终态（Succeeded/Failed/Cancelled/Timeout）不可再变更
  • 失败时根据错误类型决定是否进入 Retry 还是 Failed

6. 前台任务 vs 后台任务

两者共享同一个 Task 模型和状态机，区别主要在调用方语义和生命周期管理。

6.1 前台任务（Foreground）

  • Agent 调用后阻塞等待（或伪阻塞，内部长轮询/WebSocket）
  • 实时输出流直接推送给 Agent
  • 用户可在 Agent 侧看到“正在执行……”
  • 支持超时自动取消
  • 支持在运行中升级为交互式会话

6.2 后台任务（Background）

  • Agent 调用后立即返回 task_id
  • Agent 后续通过 query 或 subscribe 获取状态
  • 适合长时间运行、批量任务、定时任务
  • 用户可随时切到交互式终端接管

6.3 统一调度

调度器不区分前后台，只按优先级、资源、依赖关系调度。Agent 通过 mode 字段表达期望的调用语义。

7. 任务队列与调度

7.1 队列设计

采用多级优先级队列 + 主机级并发限制：

Global Queue
    ├── Priority 0 (urgent)
    ├── Priority 1 (normal)
    └── Priority 2 (background/batch)

Per-Host Semaphore
    ├── max_sessions per host
    └── max_foreground_sessions per host (可选)

7.2 调度策略

  1. 优先级优先：同优先级按 FIFO
  2. 主机资源限制：每台主机的并发会话数受限，避免压垮目标机
  3. 任务去重：相同主机 + 相同命令 + 短时间内的任务可合并或排队
  4. 依赖控制：支持 depends_on，前置任务失败则当前任务自动失败
  5. 公平调度：防止某 Agent 或某主机的任务独占队列

7.3 取消机制

  • Agent 调用 cancel(task_id)
  • 调度器从队列移除未开始的任务
  • 对已 Running 的任务：发送 SIGINT/SIGTERM，超时未结束则 SIGKILL 或关闭 channel，可选 kill_tree 清理子进程

8. 执行引擎

8.1 执行模式

模式适用场景技术方式
exec单条命令，拿 exit codeSSHClient.exec_command
shell需要环境变量、工作目录、连续命令invoke_shell + 脚本文件
interactive需要用户交互invoke_shell + PTY + WebSocket
sftp文件上传下载open_sftp

8.2 Worker 模型

  • Worker 池负责消费队列中的任务
  • 每个 Worker 同一时间只执行一个 Task
  • Worker 从 Session Manager 申请 Session，用完后归还
  • Worker 持续将输出写入 Log Backend，将状态变更写入 State Backend

9. 日志回传

9.1 日志类型

类型内容

stderr标准错误

metadata环境、主机、耗时等元信息
interaction用户输入/输出（交互式会话）

9.2 回传方式

  • 实时流：WebSocket / SSE / gRPC streaming
  • 轮询兜底：HTTP 分页查询
  • 持久化：结构化存储，支持按 task_id 检索和回放

10. 错误分析与诊断

10.1 错误分类体系

类别说明示例
CONNECTION连接失败网络不通、端口拒绝、DNS 失败
AUTHENTICATION认证失败密码错误、密钥失效、用户不存在
AUTHORIZATION权限不足sudo 失败、文件不可读
COMMAND命令本身错误命令不存在、退出码非零
TIMEOUT执行超时命令挂起、等待输入
RESOURCE资源不足磁盘满、内存不足
ENVIRONMENT环境缺失依赖未安装、变量未设置
UNKNOWN未知错误其他异常

10.2 自动诊断

错误发生时，Error Analyzer 根据输出和退出码生成：

  • error_code：机器可读错误码
  • error_message：人类可读摘要
  • root_cause_hints：可能根因
  • suggested_actions：建议修复动作
  • is_retryable：是否可重试

10.3 与 Agent 协作

Agent 收到错误摘要后，可以：

  1. 自动按建议修复后重试
  2. 向用户展示错误并询问是否继续
  3. 打开交互式终端让用户手动处理

11. 交互式会话（可选增强）

当任务进入 AwaitingInteraction 状态，或 Agent 主动请求时：

  1. 为该 Session 启动 WebSocket 桥接
  2. 用户通过 Agent 提供的界面操作远程终端
  3. 用户输入通过 WebSocket → SSH channel
  4. 远程输出通过 SSH channel → WebSocket → 用户界面
  5. 交互过程同样记录到日志
  6. 用户退出后，任务状态回归 Running 或进入终态

12. API 设计（抽象接口）

12.1 任务管理

SubmitTask(request) -> TaskHandle
  - 提交任务，返回 task_id

CancelTask(task_id) -> Result
  - 取消任务

GetTask(task_id) -> Task
  - 查询任务状态和元数据

ListTasks(filter) -> List<Task>
  - 按状态、主机、时间等筛选

AttachInteractive(task_id) -> WebSocketUrl
  - 附加交互式终端

12.2 输出订阅

SubscribeOutput(task_id) -> Stream<LogEntry>
  - 实时订阅输出流

GetOutput(task_id, offset, limit) -> List<LogEntry>
  - 分页获取历史输出

12.3 主机与凭证

RegisterHost(host) -> host_id
  - 注册主机

RegisterCredential(credential) -> credential_id
  - 注册凭证

TestConnection(host_id) -> Result
  - 连通性测试

13. 安全设计

  1. 凭证隔离：Agent 不直接接触私钥/密码，只引用 credential_id
  2. 加密存储：凭证加密后存入 Vault 或加密 KV
  3. 最小权限：SSH 用户只给必要权限，建议使用专用低权限账号
  4. 审计日志：记录谁、在什么时间、对哪台机器、做了什么
  5. 命令审查：可选危险命令拦截或确认
  6. 会话超时：空闲会话自动关闭
  7. 主机密钥策略：首次连接可配置为严格校验或自动接受

14. 与具体 Agent 集成的抽象边界

层面Agent 负责SSH Tool 负责
意图理解决定执行什么命令、是否需要交互不解释意图，只执行
上下文管理维护对话状态、用户状态维护任务状态机
用户交互展示输出、收集输入、渲染终端提供输出流和交互通道
任务调度发起任务、查询结果排队、调度、执行
错误处理基于诊断结果做决策分类错误、给出建议
凭证安全不保存凭证，只引用安全存储和使用凭证

15. 最小实现路径（MVP）

  1. Phase 1：基础执行 — SSH 连接封装、exec 任务、前台/后台任务区分、基础状态机
  2. Phase 2：可观测 — 日志实时回传、状态查询 API、错误分类
  3. Phase 3：队列与调度 — 任务队列、并发控制、取消/超时/重试
  4. Phase 4：交互增强 — 交互式 Web 终端、错误诊断建议、用户接管流程

16. 总结

这份方案的核心是：把每一次远程操作抽象为受状态机驱动的任务，由独立的执行引擎异步完成，Agent 通过标准化接口发起和观察任务。

关键设计要点：

  • Task 是核心抽象：登录、命令、文件、交互都是任务
  • 前后台统一模型：区别在于调用语义，不在于底层实现
  • 状态机驱动：所有任务生命周期可观测、可审计
  • 队列调度：优先级 + 主机并发限制 + 取消/超时/重试
  • 日志与错误分析：实时回传 + 结构化存储 + 自动诊断
  • 交互是增强项：Agent 可自动执行，遇到需要时再交给人
