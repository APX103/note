AI PCB / OPEN-SOURCE EDA · 2026-10

自带模型画 PCB：
开源 AI 工具链调研

想用 AI 画 PCB，但 Flux.ai 是付费云服务、Protoflow 是本地 App 却锁死自家模型不许换——本文调研开源世界里「自带模型（BYO）+ 免费开源 + 产物可回 KiCad 手改」的现实路线。结论：别等产品，用一条组合链，2026 年的 KiCad 生态刚好把零件凑齐了。

00 / TL;DR结论速览与拍板

开源世界里不存在「一个开箱即用、还让你自带模型的 Flux.ai」——闭源 SaaS 的商业逻辑就是模型即护城河（Flux 卖 Copilot 订阅、Protoflow 卖自家推理、Quilter 卖云端布局），指望它们开放 BYO 不现实。但把「AI 画 PCB」拆开看——原理图生成、设计审查、布局布线、制造导出四层——开源生态在 2026 年刚好每一层都有可用件，拼起来就是一条全开源、零费用、模型随便换、产物是原生 KiCad 的链路。

拍板主链：

环节工具AI 角色
原理图生成circuit-synth（Python → 直出 .kicad 工程）你的 agent 写 Python，工具本身不碰模型
Agent 接入 KiCadkicad-mcp-pro（MCP 服务器：ERC/DRC/DFM/BOM/Gerber）模型无关协议，ZCode / Claude Code / Codex 随便接
设计审查kicad-happy（EMC / SPICE / DFM / 选料，1.5k★）skills + 纯 Python 脚本，任何 agent 可用
布局KiCad 本体人工主场（AI 全自动布局开源界尚无等价物）
自动布线freerouting（DSN 进出 KiCad）传统算法非 AI，但开源免费能打
校验闭环kicad-cli ERC / DRCagent 的反馈信号，改完自动复验

诚实的边界：「一句话出整板、AI 全自动布局布线」这种 Flux/Quilter 式体验，开源界没有等价物。开源现实是「AI 管原理图生成、审查迭代、BOM 选料；人管布局」。如果接受这个分工，下面整条链今天就能跑。

01 / CRITERIA需求判定：四个硬指标

从需求出发定了四个硬指标，外加两个软指标：

  • 开源：许可证宽松（MIT 最佳），代码可审计、可自救；
  • 免费：核心能力不按板收费、不限次数；
  • 自带模型（BYO）：AI 推理不在厂商云端，或至少模型完全可替换；
  • 可导出 KiCad：产物是 .kicad 工程/网表，随时回 KiCad 手改——这是「AI 生成的玩意必须能被人接管」的底线；
  • 软指标①：分层覆盖——原理图、PCB、审查、布线各自覆盖到什么程度；
  • 软指标②：macOS Apple Silicon——日常开发机，全链 Python/Node 均无障碍。

「自带模型」在开源世界有两种实现形态，都成立：

形态原理代表
MCP（模型无关协议）服务器只暴露工具（读改 KiCad 文件、跑 DRC），用什么模型是客户端的事——ZCode、Claude Code、Codex CLI、Copilot 各自带着自己的模型来连kicad-mcp-pro、mcp-kicad-sch-api
代码生成（工具不含 AI）工具本身是个编译器/生成器，AI 的角色由外部 coding agent 写代码来完成；换 agent = 换模型，零耦合circuit-synth、tscircuit、atopile

注意一个关键区别：Protoflow 式的「App 内置 AI 面板但锁模型」两头不占——既没有云端服务的规模，又剥夺了 BYO 的自由。而 MCP / 代码生成这两条路，模型永远是你的。

02 / THE OUT LIST出局名单：Flux / Protoflow 们为什么不行

工具形态出局理由
Flux.ai云端 SaaSCopilot 绑自家云；免费档额度极小，正式用必付费；不开源
Protoflow本地 App锁死模型，只能用官方推荐的（本次调研的起因，实测确认）；免费与否已无关紧要——BYO 是硬指标
Quilter云端 AI 布局闭源，按板收费；「AI 全自动布局」确实是它最强，但模型和引擎都在别人云上
DeepPCB（InstaDeep）云端 AI 布线有免费档、Gerber 进出对 KiCad 友好，但闭源、不碰模型；自称 27,721 块板 95.6% 达到 95%+ 完成率
CELUS / JITX商业代码式 EDA代码生成电路的先驱，但都是企业级收费闭源产品

顺带一个有意思的事实：Protoflow 官网自己的对比文章也承认 KiCad 10 是 2026 年最好的免费开源 EDA，自家卖点是「导出到 KiCad」——也就是说连闭源玩家都把 KiCad 当作事实底座。那我们直接把 AI 接到 KiCad 上，跳过中间商。

03 / ROUTE A路线 A：circuit-synth —— Python 写电路，产物是原生 KiCad 工程

circuit-synth（github.com/circuit-synth/circuit-synth，MIT，287★ / 1,207 commits，活跃）是本次调研最贴合需求的单件：用 Python 代码定义电路，一键生成原生 KiCad 工程。要 Python 3.12+ 和 KiCad 8+（BOM/PDF/Gerber 走 kicad-cli）。

核心机制

# pip install circuit-synth   →   uv run cs-new-project my_board（自带 ESP32-C6 示例）
from circuit_synth import *

@circuit(name="regulator_3v3")
def regulator():
    vbus  = Net("VBUS")
    v3v3  = Net("3V3")
    gnd   = Net("GND")
    ic = Component(symbol="Regulator_Linear:AMS1117-3.3", ref="U", value="AMS1117-3.3")
    c1 = Component(symbol="Device:C", ref="C", value="10uF")
    ic["VI"] += vbus;  ic["VO"] += v3v3;  ic["GND"] += gnd   # 引脚连网络
    c1[1]    += v3v3;  c1[2]      += gnd

regulator().generate_kicad_project("my_board")   # ← 直出 .kicad_pro/.kicad_sch/.kicad_pcb
  • 产物就是标准 KiCad 工程：生成后直接在 KiCad 里打开布局，手改、版本控制、发厂全按既有习惯——「可回 KiCad 手改」满分；
  • 双向同步：可导入已有 .kicad_sch 修改再导出；生成时自动重写 ref（C → C1/C2），Python 与 KiCad 两侧不漂移；
  • 附赠 generate_bom() / generate_pdf_schematic() / generate_gerbers()（依赖 kicad-cli），还有 FMEA 可靠性分析与 SPICE 仿真接口；
  • 内置 7 个制造级电路模式（buck/boost、LiPo 充电、RS485 等）可抄作业，元件搜索接 JLCPCB / DigiKey。

AI 层：官方 Claude Code 集成，但不锁 Claude

官方为 Claude Code 准备了整套配置（circuit-architect / simulation-expert 等 subagent、/generate-validated-circuit 等斜杠命令、skills），但核心生成器不含任何 LLM——它就是个 Python 库。任何能写 Python 的 coding agent（ZCode/GLM、Codex、Copilot……）都能驱动它，模型完全是你自己的。这是「BYO + 导出 KiCad」两个硬指标的双满分。

定位边界：circuit-synth 解决的是原理图/网表层（哪颗芯片、怎么连），布局布线仍回 KiCad 做——恰好匹配「AI 生成 + 人手改」的分工预期。

04 / ROUTE B路线 B：MCP 直控 KiCad —— 让你自己的 Agent 操控真 KiCad

MCP（Model Context Protocol）是 BYO 的正解：服务器只负责暴露工具（读写 KiCad 文件、跑 ERC/DRC、导 Gerber），模型由客户端自带。换模型 = 换个客户端接进来，服务器一行不改。2026 年 KiCad 的 MCP 生态已经从玩具变成了正经工具：

项目规模 / 许可能力状态
kicad-mcp-proMIT · 141★ · 1,287 commits · v4.3.0原理图/PCB 审查、ERC/DRC（KiCad 原生引擎）、DFM、BOM 分析、Gerber 导出、发布流程；信号完整性/EMC/热为一阶闭式估算（~5–10% 精度，非签核级）活跃，主推
mcp-kicad-sch-apicircuit-synth 同门把 kicad-sch-api 库暴露成 MCP 工具：agent 创建/修改/分析原理图活跃
mixelpixx/KiCAD-MCP-Server小项目Claude 辅助 KiCad PCB 自动化的基础 MCP较小
实时布线 MCP（r/KiCad）社区新出agent 在活体 KiCad 会话里用 Push & Shove 布线，已有走线自动避让方向确认中

kicad-mcp-pro 的工程化程度值得单独说：默认启动为受限只读 profile（24 个审查工具），写文件/制造输出/专家模式要显式开启——对「AI 别乱动我的板子」是正确的设计；传输支持 stdio 和 Streamable HTTP；安装一条命令 uvx kicad-mcp-pro；官方给了 Claude Code / Codex CLI / VS Code Copilot / OpenCode 四家客户端的配置示例，任何 MCP 客户端（含 ZCode）同理可接；正在开发 KiCad 10 的 IPC 插件。接入配置长这样（各家客户端通用结构）：

{
  "mcpServers": {
    "kicad": {
      "command": "uvx",
      "args": ["kicad-mcp-pro", "--transport", "stdio"]
    }
  }
}

搭档：kicad-happy（审查层）

kicad-happy（MIT，1.5k★，813 commits，v2.3.1）是这批项目里热度最高的：11 个 skills 覆盖 kicad 解析审查 / SPICE 自动测试台（ngspice/LTspice/Xyce，含蒙特卡洛）/ EMC 预合规（44 条规则，FCC/CISPR）/ 数据手册提取 / BOM 全周期 / DigiKey·Mouser·LCSC 选料 / JLCPCB·PCBWay 下单准备。关键卖点：它既是 Claude Code / Codex / Copilot CLI / Gemini / opencode 的 skills，也能当独立 Python 脚本跑（纯 Python 3.10+，零强制依赖，甚至不用装 KiCad），还配了 5,800+ 开源 KiCad 项目的回归语料。定位是「下单前抓真 bug」，与生成类工具完美互补。

05 / ROUTE C路线 C：tscircuit / atopile —— 代码式 EDA 新势力

两条「代码生成电路」的新势力路线，都不含内置 AI、但都对 coding agent 极度友好（官方口号就是让 agent 写它们的代码）：

维度tscircuitatopile
仓库 / 许可tscircuit/tscircuit · MIT · 2.9k★ · 5,880 commitsatopile/atopile · MIT · 4.0k★ · 2,843 commits
语言形态TypeScript/React JSX：<resistor>、<chip>、<trace>，React Fiber 渲染成电路/PCB/3D声明式 .ato 语言：模块、接口、单位、公差、断言（assertions）
KiCad 关系导出 Gerbers/PnP/BOM + KiCad 库导出（符号/封装/3D）；circuit-json-to-kicad 官方库可转 .kicad_pcb——可行但属转换路径，非一等公民原生协作：编译器直接生成/更新 .kicad_pcb，place & route 就在 KiCad 里做（KiCad 可后装，不装只影响预览）
AI 角色CLI 完全本地（tsci dev → localhost:3020 预览）；README 明说「tell your agent to use tscircuit」；云端 playground/AI 是独立可选服务仓库自带 CLAUDE.md / AGENTS.md / .cursor 配置，明确为 coding agent 优化；无内置 AI 接口——agent 写 .ato 即 AI
成熟度提醒目前需手写元件坐标（类 CSS Grid 自动布局在开发中，见 autorouting.com）；适合快速原型/小板更偏资深硬件工程师的「硬件代码化」长期路线；有模块注册表 packages.atopile.io

另有老牌 SKiDL（Python 写电路 → KiCad 网表，MIT）：思路是 circuit-synth 的前辈，如今直接用 circuit-synth 即可，不单独推荐。

怎么选：要「AI 生成 + 回 KiCad 手改」就 A（circuit-synth）；写惯前端/想快速原型小板可以试 tscircuit；想长期把硬件当代码管理选 atopile。三者不互斥——B（MCP + kicad-happy）是所有路线共享的 agent 接入层和审查层。

06 / FOUNDATION配套底座与研究前沿

  • freerouting（自动布线）：github.com/freerouting/freerouting，开源 autorouter，与 KiCad 的官方配合流程成熟（DSN 导出 → 布线 → 回导 → 人工修铜），也支持 Fusion/Target3001。KiCad 至今没有内置 autorouter，它是开源默认答案。注意它是传统算法不是 AI——但开源免费、本地可跑。
  • KiCad 10（2026-03 发布，10.0.1 于 04-15）：新增高高速信号调谐、设计变体、pin/gate 交换、图形化 DRC 规则编辑器；更关键的是 IPC API 取代老 SWIG Python 绑定（kicad-python 已上 PyPI，语言无关、可连活体会话）——这是「agent 直控 KiCad」的地基，上面的 MCP 们正是踩着它建的。坑：IPC API 的出图/导出要 KiCad 11 才补齐，眼下导出统一走 kicad-cli。
  • KiCadRoutingTools：KiCad 社区 2026-02 冒出的自动布线插件（alpha），保持关注。
  • 研究前沿：PCBWorld（BSD-3）把 KiCad 自家的 Push&Shove 布线器包成 Gymnasium 强化学习环境、用 KiCad DRC 打分（arXiv:2607.05915）——「RL 学布线」在开源侧刚起步；另有 KiClaude（浏览器原生 AI KiCad，早期 roadmap）。
  • macOS Apple Silicon：整条链（circuit-synth / kicad-mcp-pro / kicad-happy / tscircuit / KiCad 10 / freerouting jar）全是 Python/Node/Java 生态，arm64 无障碍。

07 / VERDICT落地拍板：推荐工作流

把零件串成一条「你的 agent 全程参与、关键处人来拍板」的流水线：

需求描述（自然语言）
   │  你的 agent（ZCode/GLM 或 Claude Code——模型随你换）
   ▼
① circuit-synth 写 Python → .kicad_sch          ……生成层（AI 主场）
   │  kicad-cli sch erc
   ▼
② KiCad 里人工布局                                ……人工主场（AI 全自动布局尚无开源等价物）
   │  导出 DSN
   ▼
③ freerouting 自动布线 → 回导 KiCad 修铜          ……布线层
   │  kicad-cli pcb drc
   ▼
④ kicad-happy 终审：EMC / DFM / SPICE / LCSC 选料 ……审查层（AI 第二主场）
   ▼
Gerber + PnP + BOM → JLCPCB 下单

上手路径（约两小时）：

  1. pip install circuit-synth → cs-new-project demo → 跑通 ESP32-C6 示例，在 KiCad 里打开生成的工程，感受「Python → 原生 KiCad」；
  2. agent 接入：给 ZCode / Claude Code 的 MCP 配置加一条 uvx kicad-mcp-pro（§4 有配置片段），再 clone kicad-happy 的 skills 装进 agent；
  3. 拿一块真实小板（比如下一块星闪/ESP32 载板）走完 ①→④ 全流程，验证分工手感；
  4. 若主攻快速原型，试 tscircuit 的 tsci dev；若走硬件代码化长线，试 atopile。

再强调一次别指望的：一句话全自动出整板。Quilter/Flux 收费收的正是这个能力，开源侧 freerouting 只解决布线、布局仍归人。但反过来，「AI 生成原理图 + AI 审查 + AI 选料 + 人布局」这条链，每一环都比纯手工快，而且每一环的模型都是你自己的。
