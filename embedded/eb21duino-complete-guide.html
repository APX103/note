EB21duino（BS21 星闪）完全攻略

2026-10-12 · 硬件档案 → 三重陷阱破案 → 烧录配方（已验证）→ 诊断工具箱 → 排错速查 · 附出厂固件尸检报告
TL;DR：板子是好的。 烧录一句话：hsflash 挂在 COM10 等 → 拔功耗跳帽 2 秒再插回（这是唯一可靠的复位方法）→ flashboot 开机 250ms 窗口自动抓住握手 → 全镜像烧写 → 自动重启。RST_KEY 按键在本板上无效，别再按了。

一、板子是什么

利尔达（Lierda）EB21duino 开发板（正式型号 L-NLEEB21-G5PP4-DK01，Arduino UNO 板型），载 EB21 模组（海思 BS21 芯片，BLE 5.4 + 星闪 SLE 1.0，RISC-V 32bit @64MHz 带浮点，1MB Flash / 160KB RAM——flash 容量由 flashboot 开机横幅实证 flash length:0x100000）。出厂角色：星闪鼠标 dongle（接收器）——插电脑 USB 就是一个 SLE 鼠标接收器。

项目规格 / 说明
芯片海思 BS21（EB21 模组封装），SLE 1.0 + BLE 5.4，USB 2.0 HS/FS device
Flashbootbs21e 1.0.19（开机横幅实证），上电后约 250ms 内在 UART_L0@115200 监听串口下载，随后跳转 App（Jump to addr = 0x9011B300）
SDK海思 fbb_bs2x（本机 D:\work\fbb_bs2x，工作 clone 在 D:\work\AirMouse-SLE）
官方文档D:\work\fbb_bs2x\vendor\Lierda-EB21\hardware\ 三份 PDF：开发板硬件说明书 Rev1.5、EB21duino 原理图 Rev0.1、EB21 模组硬件参考设计手册 Rev1.2
USB 烧录/DFU❌ 本板 flashboot 不支持 USB DFU（复位时无任何新 USB 设备枚举，实测）；手册里唯一烧录接口是 SWD（未用上，串口跳帽法已够）

二、硬件全档案（接口 / 灯 / 按键 / 跳帽）

2.1 两个 Type-C（都可供电，可同时插）

口里面接的枚举结果用途
Type-C1（UART）Silabs CP2105 双通道 USB 转串口 → 模组 UARTCOM9（Enhanced，标"AT"）+ COM10（Standard，UART_L0）COM10 = 烧录 + 日志口（115200）；COM9 在本板上无响应（出厂固件不用它）
Type-C2（USB）经 ESD/0Ω 直连 BS21 原生 USB（USB_DP=模组 pin14，USB_DN=pin15）取决于固件（出厂固件枚举为 SLE_MOUSE HID 设备）跑 USB 功能（HID 鼠标等）时插，必须用数据线（充电线无数据）
烧录只需要插 Type-C1（串口供电 + 烧录 + 日志三合一）。Type-C2 是给固件的 USB 功能用的。

2.2 灯（两个）

灯驱动含义
红灯（电源）LDO 直接驱动常亮 = 5V 供电正常。红灯亮 ≠ 模组有电（模组电要走功耗跳帽）
绿灯（编程指示）GPIO P0.30 直推，高电平点亮用于 PWM 调试；SDK blinky 样例设 SAMPLE_BLINKY_PIN=30 就是闪它（500ms 周期）

2.3 按键（只有一个）与跳帽

元件手册说法本板实测
RST_KEY（唯一按键）按 1ms 以上复位模组（说明书 §3.3）无效！确认按键 + 60 秒串口监听 = 0 字节开机横幅，USB 也不重新枚举。芯片从未被它复位过。烧录失败一整晚的元凶。可能是按键坏或板改版没接（图注写 PWR 的锅也算它）
功耗测试接口（2pin 跳帽）串电流表测功耗；短接 = 模组正常供电（§3.1.2：不短接模组无法工作）短接着 = 正常；拔掉 = 模组断电（CP2105 由串口线供电不受影响，COM10 保持在线）→ 这就是可靠的手动复位方法
记住这两个事实，能省一晚上：① RST_KEY 别信，用拔插功耗跳帽复位；② 红灯常亮但串口全静默时，第一件事检查功耗跳帽在不在。

2.4 模组引脚速查（EB21 模组，1.26mm 邮票口引出）

功能引脚备注
USB_DP / USB_DNpin14 / pin15→ 板上 Type-C2
SWCLK / SWDIO / nRESETpin12 / pin13 / pin11→ 板上 SWD 烧录接口（手册唯一官方烧录口，暂未用）
UART_L0（烧录+日志）→ CP2105 Standard = COM10115200
nRESET上拉 + RST_KEY 按键 + 排针引出排针上引出意味着可以飞线外接复位按键
GPIO两侧 2×26Pin 2.54mm 排针全引出P0.30 = 绿灯已被占用

三、三重陷阱（2026-10-11 "变砖" 乌龙破案记）

10-11 晚 BurnTool 各种尝试后板子"全波特率无响应"，一度判死刑"flashboot 写坏=砖，需售后或 SWD 救砖"。10-12 凌晨全部推翻，真相是三个独立陷阱叠加：

  1. 陷阱一：RST_KEY 不复位芯片。所有"按复位触发握手"的尝试里芯片根本没重启，flashboot 的 250ms 监听窗口从未打开过。
  2. 陷阱二：手册 Rev1.2（2024-08）删除了"串口烧录"章节。于是所有人（包括之前的 agent）默认串口烧录不存在 → 去试 USB DFU → 但 Type-C2 的线没插/用的充电线 → 无 DFU 设备 → 加深"砖"的误判。
  3. 陷阱三：出厂固件是生产版 SLE dongle，不打日志。串口监听全静默（其实 COM10 有全字节回显——透传固件的特征——但当时没识别出来），误以为芯片死了。

破案钥匙是冷启动横幅抓取（§5.3 工具）：拔插串口线 + 毫秒级轮询抢开 COM10，抓到 Jump to addr = 0x9011B300 / Debug uart init succ! flash length:0x100000, version: bs21e 1.0.19——flashboot 活着、串口 115200、只听 250ms。之后把"复位"换成"拔插功耗跳帽"，烧录一发入魂。

工具教训：BurnTool（cfbb 版）CLI 模式无任何报错，只会静默失败，别用它调试；统一用 hsflash（有清晰报错）：D:\hispark\tools\hsflash\hsflash.exe（hs-flash 26.09.1）。

4.1 前置条件

  • Type-C1 串口线插电脑（COM10 出现），Type-C2 无需插
  • 功耗跳帽短接在位（正常工作状态）
  • 固件包就绪：*.fwpkg（编译见 §6；标准全量包 bs21e_all_in_one.fwpkg）
  • 没有别的程序占用 COM10（python 监听脚本记得关）

5.2 多波特率扫描（抓"乱码信标"）

# CP2105 支持档：115200 / 921600（750000、2000000 会报错31不支持）
# 对端固件跑什么波特率，就在那档收到数据
import serial, time
for baud in [115200, 921600, 57600]:
    s = serial.Serial('COM10', baud, timeout=0.5)
    t0=time.time(); buf=b''
    while time.time()-t0 < 4: buf += s.read(256)
    s.close(); print(baud, repr(buf[:60]))

5.3 冷启动横幅抓取（破案神器：判断 flashboot 死活）

# 原理：等 COM10 消失(拔线)→20ms轮询抢在重现第一毫秒打开→抓开机横幅
# 用法：跑起来后 拔串口线→等3秒→只插回串口线（让芯片冷启动）
import serial, time
import serial.tools.list_ports
def ok(): return any(p.device=='COM10' for p in serial.tools.list_ports.comports())
while ok(): time.sleep(0.05)                      # 等拔线
while not ok(): time.sleep(0.02)                  # 等(重)插线,高频轮询
s = serial.Serial('COM10', 115200, timeout=0.05)  # 抢开!
t0=time.time()
while time.time()-t0 < 10:
    b = s.read(512)
    if b: print(f'+{time.time()-t0:.3f}s', repr(b[:120]))
判读：有 Jump to addr / Debug uart init succ / version: bs21e ... = flashboot 活着且串口正常 → 烧录通道可用；什么都没有 = 检查功耗跳帽、换线、再怀疑 flashboot。

5.4 USB 设备监视（复位是否真的发生 / DFU 是否出现）

powershell: Get-PnpDevice -PresentOnly | ? InstanceId -match 'VID_1111'   # 模组USB设备(SLE_MOUSE族)
# 或循环监视新设备到达：
while (...) { Get-PnpDevice -PresentOnly | ? { -not $known[$_.InstanceId] } ... }

判读：按复位/拔跳帽时若芯片真重启，USB 设备（如 SLE_MOUSE）会消失重现；持续无变化 = 复位没发生（本板 RST_KEY 就是这样实锤的）。注意 0.6s 轮询可能漏掉极快的重枚举，实锤复位请用 §5.3 的横幅法。

5.5 AT 指令探测（透传/AT 类固件）

# AT 固件是"你问它才答"，被动监听全静默不代表死！
# 本板出厂固件：COM9 无响应；COM10 全字节回显(透传环回特征)但 AT/+++ 均不解析
s = serial.Serial('COM10', 115200, timeout=0.3)
for cmd in [b'AT\r\n', b'AT+VER\r\n', b'+++']:
    s.write(cmd); time.sleep(1.0); print(cmd, repr(s.read(256)))
