ESP-MOSAICO / ESP32-S31 MAGNETIC DEV KIT

磁吸积木遇上 AI Coding：
ESP-Mosaico 调研

ESP-Mosaico 是乐鑫 2026 年 8-9 月刚发布的可扩展智能交互开发套件，首发搭载全新芯片 ESP32-S31（RISC-V 双核、Wi-Fi 6、片内 16MB PSRAM）。它的玩法核心是多板磁吸拼接——每块板带 480×480 方形 AMOLED 触摸屏、六轴 IMU 和双磁力计，板子吸在一起的瞬间能自动识别彼此方位并组成拓扑；软件上主打 AI Agent / Vibe Coding 开发工作流。本文调研其芯片规格、硬件全景、模块扩展系统、开源生态与购买渠道，并评估对我们现有 ESP32-S3 项目的参考价值。

00 / TL;DR结论速览

ESP-Mosaico 是乐鑫为"AI Coding + 磁吸拼接硬件"打造的第一块官方开发板，也是 ESP32-S31 芯片的首发平台。硬件上它是 CoreBoard + BaseBoard 双板结构：核心板集成 SoC、2.16 寸 480×480 方形 AMOLED 触摸屏、ES8311 音频、BMI270 IMU、两颗 BMM150 磁力计（磁吸识别的核心）、16MB NOR + 128MB NAND、65mAh 电池与完整电源管理；底板提供喇叭、左右两个 2×10P 模块槽（带 EEPROM 热插拔识别）和调试焊盘。软件生态出乎意料地完整：esp-mosaico 独立 GitHub 组织下 BSP（9 组件 + 17 例程）、Agent 开发工作区 Vibe、基于 ESP-Claw 的出厂固件全部开源。

拍板：这块板的看点不在"又一块 ESP32 开发板"，而在三点——① ESP32-S31 芯片预览（RISC-V + Wi-Fi 6 + 双无线电，但数据手册还是 PRELIMINARY v0.5）；② 双磁力计磁吸拼接方案（对我们的多设备 ESP-NOW 项目是现成参考）；③ 官方 AI Agent 开发工作流（ESP-Claw Chat Coding 框架 + Vibe 工作区，出厂就带 CLAUDE.md/AGENTS.md）。风险同样明确：芯片未定稿、每日限量抢购、IDF 需 6.2+ 且目标名要 --preview 解锁。值得关注，暂不押注

一句话：Mosaico 是乐鑫对"下一代 ESP32 该长什么样"的一次公开彩排——芯片、板卡、拼接玩法、AI Agent 工作流四件套一起亮相；即使不买板，它的双磁力计拼接软件栈和 480×480 QSPI AMOLED 驱动也值得抄作业。

01 / WHAT & WHY定位与发布背景

按官方文档的自我定义："面向磁吸扩展、运动感知、方形触摸显示与边缘多媒体场景的可扩展智能交互开发套件"。对应四类目标应用：磁吸扩展玩具（magtile 类）、运动感知交互、方形触摸屏 HMI、边缘语音/多媒体。发布节奏可以从公开物料还原：

  • 2026-04：ESP-Claw 框架仓库（espressif/esp-claw）创建，"Chat Coding" AI Agent 框架先行铺垫；
  • 2026-08-18：ESP-Mosaico CoreBoard V1.0 原理图定稿归档（dl.espressif.com PDF 文件名自带日期）；
  • 2026-09：官方发布新闻（espressif.com/zh-hans/news/ESP_Mosaico_Release）宣布开售，淘宝官方店上架；esp-mosaico 组织四仓库持续活跃推送（最近一次 2026-09-21）。

官方新闻的关键词是"为 Coding Agent 设计的开发板"：多机拼接（乐高式硬件组合）、打通 AI Coding 从软件到硬件落地的链路、适配主流 AI 编程工具、支持从 Chat Coding 到 Vibe Coding 的工作流。换句话说，乐鑫把"用 AI Agent 写固件"当成了这块板的一等公民场景——这在全球 MCU 厂商里属于相当激进的产品定位。

背景板：同期 esp-dev-kits 文档树里还出现了 esp32-s31-function-coreboard-1 和 esp32-s31-korvo-1 两块兄弟板——S31 芯片的官方评估路线是成体系的，Mosaico 是其中"玩法旗舰"。

02 / CHIPESP32-S31 芯片实勘

ESP32-S31 是乐鑫新系列，数据手册目前为 PRELIMINARY v0.5 预发布版（documentation.espressif.com），规格可能在正式版前调整。Mosaico 板载型号 ESP32-S31NRV16（16MB 片内 PSRAM；另有 NRV32 = 32MB 版本），工作温度 -40~85°C。

计算与内存

  • HP 主核：32 位 RISC-V 双核，最高 320 MHz，RV32IMAFC + Zc/Zb 扩展 + 自定义 AI/DSP 与硬件循环指令；Sv32 MMU、每核 FPU、分支预测；CoreMark 约 2195（6.86/MHz，双核）；
  • LP 低功耗核：单核 RISC-V，最高 40 MHz，负责深睡域任务；
  • 内存：320KB ROM / 512KB HP SRAM / 32KB LP SRAM；片内 1.8V Octal DDR PSRAM（250 MHz），支持 flash 与 PSRAM 并发访问；片外 flash 最高可挂 256MB（SPI/Dual/Quad/QPI）；
  • 调试：RISC-V trace encoder；首个带 Secure Debug Controller（SDC）的乐鑫芯片。

无线与外设

  • 三无线电：Wi-Fi 6（802.11ax，20MHz 非 AP，OFDMA/TWT/MU-MIMO beamformee）+ 完整 802.11b/g/n 至 150Mbps；蓝牙 5.4 双模（LE：Mesh 1.1 / LE Audio / Direction Finding，同时保留 BR/EDR Classic 至 3Mbps EDR）；802.15.4（Zigbee 3.0 / Thread 1.4 / Matter）。发射 +21dBm，BLE 125Kbps 灵敏度 -105dBm；
  • 接口外设：USB 2.0 High-Speed OTG + USB Serial/JTAG、LCD/摄像头控制器、JPEG 编解码、PPA 像素加速器、2D-DMA（带色彩空间转换）、ASRC、CORDIC、BitScrambler、PARLIO；
  • 模拟：2× 12-bit SAR ADC（16 通道）、2× DAC、14 通道触摸传感器、模拟比较器、温度传感器；
  • 数字：4× UART + LP UART、6× SPI + LP SPI、2× I2C + LP I2C、2× I2S、千兆 EMAC、CAN FD、双槽 SDIO host、4× MCPWM、2× LED PWM、RMT、4× 54-bit 定时器；
  • 封装：QFN80 8×8mm，60 个 GPIO（其中 8 个 LP GPIO 深睡可用）。

03 / HARDWARE硬件架构全景

ESP-Mosaico 采用 CoreBoard + BaseBoard 双板结构，通过 60-pin 0.5mm 板对板连接器扣合：核心板是"SoC + 屏 + 传感器 + 电源"的最小系统（可以理解为下一代的"核心模组 + 外围"设计），底板承载喇叭、电池和扩展排针。官方文档覆盖 V1.0 硬件，BSP 已支持 v1.0/v1.1/v1.2 三个修订（硬件版本写入 eFuse USER_DATA，BSP 上电读取自动适配，未烧录版本返回 ESP_ERR_NOT_SUPPORTED）。

电源架构与电源域控制

供电三入口：Type-C 5V、底板背面扩展焊盘、电池；Type-C 接 USB sink 设备时自动切换为 source 模式对外输出 5V/500mA，负载超 1A 自动关断并延时恢复。左右模块槽也提供 3V/5V 输出（受 GPIO60 控制）与 VIN 输入（可为电池充电）。电源域由三个 GPIO 精细控制：

信号GPIO行为
VCC_3V3 / VCC_PWGPIO60系统 3.3V 轨开关，低有效；BSP 使能时做软启动斜坡
CODEC_3V3GPIO56codec 供电开关，高有效（独立 LDO 降噪）

烧录与调试链路（有个坑）

原生芯片只支持 download 模式烧录，ROM 本身不提供自动下载和日志输出——出厂固件集成了 CDC 虚拟串口后才支持自动下载与串口日志。因此首次烧录失败时要按住 BOOT 再上电进 download 模式。旁路方案：左模块槽引出 USB Serial/JTAG、右模块槽引出 UART TX0/RX0，两者都能烧录调试。烧录后 CDC 控制台受 CONFIG_BSP_USB_CONSOLE / CONFIG_BSP_USB_AUTO_DOWNLOAD 等 Kconfig 控制；芯片复位时 USB 会短暂掉线，IDF Monitor 一般能自动重连。

# BSP 推荐的最小开发循环
idf.py --preview set-target esp32s31
idf.py -p /dev/ttyACM0 flash monitor
# monitor 挂接而不重启应用时：
idf.py monitor --no-reset

04 / MAGNETIC & MODULES磁吸拼接与模块扩展

双磁力计：磁吸拼接的感知基础

每块 Mosaico 板缘布置两颗 BMM150 磁力计（I2C 0x11 / 0x12）配合板间磁铁。两块板磁吸接触时，两颗磁力计的磁场读数差异被 mosaico_interaction 组件用于磁性分类、方位判定与多板拓扑重建，再经 mosaico_peer_link（ESP-NOW 传输 + 接触会话协商 + 拓扑传播）和 mosaico_network（多设备拓扑路由与应用消息）把物理拼接变成逻辑组网——官方 demo 里有多屏"能量接力"和双屏乒乓球。磁校准 profile 与机械安装强相关：换磁铁、改外壳、装配公差变化都要重新校准（BSP 硬件注意事项原文），说明该方案对结构设计敏感，抄作业时要连结构一起抄。

模块槽：EEPROM 热插拔识别

底板左右各一个 2×10P、2.54mm 间距排针槽（左 H2 / 右 H1），模块上带 EEPROM：左槽 0x50（GPIO14 拉低选址）、右槽 0x51（GPIO39 拉高选址，且与左槽 180° 反装——同一模块物理上可以插任意一侧）。BSP 通过 mosaico_module_mgr 做模块发现、描述符校验与槽位独占式生命周期管理。官方已开源三种扩展模块：

摇杆模块双轴摇杆 + 五按键，非阻塞校准左 / 右皆可

复用陷阱（自研扩展必读）：① 右槽 5 个引脚（GPIO49/52/54/37/40）与板载音频 I2S 复用——要用右槽扩展就不能同时用 ES8311/喇叭/麦克风；② 摄像头模块占用 DVP 引脚时，GPIO14 被复用为 DVP D4，该槽 EEPROM 识别暂停；③ 部分摄像头信号与 USB Serial/JTAG 冲突，摄像头例程必须走 UART 烧录；④ 两槽共享 I2C 等资源，槽位在模块驱动存活期间独占；⑤ 模块 EEPROM 编程属于产线操作，不在公开例程工作流内。

06 / AI AGENT WORKFLOWESP-Claw 与 Vibe：AI Agent 开发工作流

ESP-Claw：设备端 Chat Coding 框架

ESP-Claw（2026-04 创建，2.1k★，官网 esp-claw.com）是乐鑫的 "Chat Coding" IoT AI Agent 框架，自我定位受 OpenClaw 概念启发、用 C 重实现：把对话、记忆、技能、Lua 扩展、MCP client/server 的 Agent Runtime 跑在 ESP32 系列芯片上，"感知—决策—执行"闭环本地完成。配套在线烧录页（esp-claw.com/en/flash）降低了尝鲜门槛。Mosaico 的出厂固件就跑在 ESP-Claw 上（esp-mosaico-claw 仓库，含 Mosaic UI、天气/相机/相册/蓝牙音乐应用、Wi-Fi 配网、网页配置、即时通讯、语音识别与固件更新检查），编译入口：

source /path/to/esp-idf/export.sh    # IDF 6.x + esp32s31 支持
python -m pip install -r requirements.txt
git submodule update --init --recursive
idf.py bmgr -c ./boards -b esp_mosaico
idf.py build && idf.py -p PORT flash monitor

Vibe：Agent 主导的开发工作区

esp-mosaico-vibe 是最有意思的一个仓库——官方定义是 "Agent-led development workspace"：用户描述应用与预期行为，AI Agent 基于参考工程、模拟器与 ESP-Iris 设备工具完成开发；用户只负责定目标、做必要的物理操作（插拔/按键）、在设备上验收结果。仓库根目录直接带 CLAUDE.md 和 AGENTS.md，工作流围绕 mosaico.py CLI 展开：

python mosaico.py project init my_app   # 建工程（无需装 IDF/接设备）
python mosaico.py doctor               # 体检依赖并解析满足 esp32s31 的 IDF
python mosaico.py recover              # 空机/校验失败时先走恢复
python mosaico.py iris system-update --project projects/my_app  # 烧系统
python mosaico.py iris logs --project projects/my_app --timeout 20
python mosaico.py iris run --project projects/my_app  # 打开 Gateway Web 工作台

开发与观测分三条线：GSP Hello World（GSP UI 框架，PC/设备共享 UI 逻辑 + GSP 模拟器，基于 espressif/esp-gsp 1.4.0）；Raylib 游戏线（共享 C 渲染代码 + 确定性 Host 回放）；设备持续观测（ESP-Iris + Gateway Web 工作台，管理会话与设备所有权）。改动分区表/换应用走 system-update，纯代码改动走 app-update，并保留 Recovery 恢复路径防止变砖。

为什么值得注意：这是头一回看到芯片厂把"AI Agent 怎么开发嵌入式"做进官方产品交付物——CLAUDE.md/AGENTS.md、Host 模拟回放、Web 网关观测、防变砖 Recovery，全是给 Agent 设计的地板。对我们自己做 agent-ssh-tool / wandlink 这类"Agent 操作物理设备"的项目，这套交互契约是现成的抄作业对象。

08 / VERDICT参考价值与风险

对我们现有项目的直接价值

  • 多设备 ESP-NOW 拼接（对讲机/魔杖方向）：mosaico_peer_link（接触会话协商+拓扑传播）与 mosaico_network（多跳路由+应用消息）是我们 espnow-intercom 多机拓扑问题的完整官方参考实现，且是 ESP-IDF C 代码可直接读；双磁力计磁吸识别方案（含校准敏感性教训）适合 wandlink 的"设备物理对接"场景。
  • 480×480 QSPI AMOLED（esp32-s3-amoled 液晶开发方向）：esp_lcd_co5300 组件覆盖 SPI/QSPI/DSI 三种接口与 Sleep-In/Deep Standby 低功耗态——对我们 StickS3/自制 AMOLED 板的屏驱和功耗优化直接可抄。
  • 语音玩具（kids-voice-toy）：voice_wake_cmd（唤醒词+命令词+TTS）与 gmf_audio_player 例程 = 现成的工程级参考；ES8311 + 独立 LDO 降噪的音频硬件布局也值得对标。
  • Agent 工作流（vibecoding-wand / agent-ssh-tool）：Vibe 的 mosaico.py CLI + Iris/Gateway 观测 + Recovery 防变砖 + CLAUDE.md 契约，是"Agent 安全操作物理设备"的最佳实践范本。
  • 芯片选型前瞻：S31 = S3 的 RISC-V 继任者（Wi-Fi 6 / 双模 BT / HS USB / 千兆 EMAC）。S3 项目保持现状，但新项目架构设计时可以按"未来平移 S31"预留（避免依赖 Xtensa 专有二进制库）。

风险与不押注的理由

  • 芯片 PRELIMINARY v0.5：规格未定稿，量产选型此刻入场等于跟乐鑫一起踩坑；IDF 目标还要 --preview 解锁。
  • RISC-V 生态迁移成本：ESP-SR、bt-lib 等在 S31 上是平行世界（esp32s31-bt-lib 刚起步），Xtensa 上的存量优化与社区经验不能直接复用。
  • 供货紧俏 + 涨价：限量抢购、原价上调，说明产能爬坡中，批量拿货短期不现实。
  • 磁吸校准对结构敏感：自研拼接硬件需要连磁铁布置、外壳、装配公差一起复刻校准流程，不是纯软件问题。

行动建议：① 不急着买板——先把 esp-mosaico-bsp 和 esp-mosaico-vibe 当参考代码库读（已克隆到本地 work/）；② 若多机拼接/AMOLED 低功耗某块卡壳，直接翻对应组件源码抄实现；③ S31 正式版数据手册发布、IDF 去掉 preview 标记、淘宝现货常态化——三个信号满足两个再考虑入手实物。
