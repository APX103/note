FOC 算法落地 STM32G431：机器人关节驱动从原理到代码架构

调研报告 · 2026-09-23 · 讲清三件事：FOC 在算什么、G431 拿什么算、代码怎么搭

§0 为什么是 FOC + G431

机器人关节的要害是力矩要平滑、响应要快、体积要小。六步换相（方波驱动）每 60° 电角换一次相，力矩纹波大、低速有顿挫、有换相噪声——用在关节上就是"齿轮感"和异响。FOC（Field-Oriented Control，磁场定向控制）把三相电流当成一个可以连续旋转、连续调幅的电流矢量来控制，力矩恒定无纹波、低速到零速都平稳、电流利用率最高，所以关节驱动清一色 FOC。

而 STM32G431 的选型逻辑一句话：FOC 电流环需要的整条信号链——放大（运放 PGA）、采样（双 ADC 同步）、保护（比较器→刹车）、运算（CORDIC/FMAC 数学加速器 + M4F 浮点）、输出（TIM1 互补 PWM）、通信（FDCAN）——全部在一颗芯片里，几乎不需要外加模拟器件。本文按"原理 → 算法 → G431 硬件映射 → 代码架构"四层展开，原理求简，实践求细。

§1 FOC 原理：最短路径讲透

1.1 电机里到底发生了什么

PMSM（永磁同步电机）转子上是永磁体，定子三相绕组通电产生旋转磁场，两个磁场相互作用出力矩。力矩正比于两个磁场磁通密的叉积：

T ∝ |Br × Bs| ∝ sinθgap  ← 两磁场夹角 90° 时力矩最大

所以 FOC 的全部目标就一句话：不管转子转到哪个角度，都让定子电流产生的磁场方向始终垂直于转子磁场。垂直 ⇒ 每安培出力矩最大且恒定；偏离 90° ⇒ 同样电流出力变小且波动。六步换相的问题是磁场夹角在 60°~120° 之间来回摆，纹波就来自这里；FOC 让夹角锁死在 90°，纹波消失。

1.2 三个坐标系：abc → αβ → dq

直接控制三相交流量（三个 120° 错开的正弦波）很别扭，FOC 的思路是换坐标系，把"交流"变"直流"：

  • abc：三相定子坐标系，三个随时间变化的正弦电流——物理真实存在，但难控制。
  • αβ：两相静止坐标系（Clarke 变换得到）。α 对齐 A 相绕组轴，β 领先 90°。两个量仍是交流，但少了一个变量，且与 PWM 合成（SVPWM）天然同平面。
  • dq：两相旋转坐标系（Park 变换得到），d 轴对准转子磁场方向、q 轴领先 90°（正是目标垂直方向）。站在这个跟着转子转的坐标系里看，定子电流是两个直流量：id（与转子磁场同向，励磁分量）和 iq（垂直，力矩分量）。
图 1 · 坐标系与矢量：转子转到哪，θe 由编码器实时给出，电流矢量被控制指向 q 轴

1.3 直流电机类比（记住这个就懂了 FOC）

变换到 dq 系之后，PMSM 在数学上变成一台解耦的直流电机：iq 就是"电枢电流"，直接比例于力矩；id 就是"励磁电流"，对表贴式转子（SPM）我们把它压到 0（不增力矩只会浪费电流和发热），高速弱磁时才给负值。于是整个控制问题退化为：用两个 PI 控制两个直流量，再变换回三相去执行。这就是 FOC 的全部。

1.4 完整控制环路

外环（位置/速度）输出 iq 指令，电流环负责让实际 id/iq 跟上指令。环路里每个框就是一个算法模块，§2 逐个讲怎么算，§3 讲 G431 拿什么算：

d,iq vd,vq vα,vβ i*_q θₑ → Park / 反Park 相电流反馈
图 2 · FOC 级联控制框图：内环电流（10–40 kHz）→ 中环速度 → 外环位置（~1 kHz）

§2 FOC 是怎么算的：逐模块公式速讲

以下公式全部是"每拍执行一次"的离散运算，没有任何迭代或收敛问题——这是 FOC 看似神秘、实则工程友好的原因。

2.1 电流采样

三相电流之和恒为零，采两相即可推出第三相。主流方案两种：低侧采样（两个电阻串在下管源极到地，便宜，但必须在下管导通窗口内采样，见 §3.2）和相线 inline 采样（电阻+差分运放串在相线，任意时刻可采，成本高）。G431 的双 ADC 同步采样两相，正好匹配两电阻方案。

2.2 Clarke 变换（abc → αβ，降维）

iα = ia
iβ = (ia + 2·ib) / √3   ≈ (iₐ + 2iᵦ) × 0.5774，等幅值形式
ic = −ia − ib

计算量：2 次乘 1 次除（√3 提前折算成系数）加几次加法，浮点约 15 个周期。就这么多。

2.3 Park 变换（αβ → dq，旋转到转子视角）

id =  iα·cosθe + iβ·sinθe
iq = −iα·sinθe + iβ·cosθe
θₑ = p·θₘ + θ₀　（电角度 = 极对数 × 机械角度 + 标定零点，编码器给出）

这是整个 FOC 里唯一需要三角函数的地方之一（sinθ、cosθ 成对出现）。计算量：4 乘 2 加很便宜，贵的是那对 sin/cos——这正是 §3.3 CORDIC 登场的原因。物理含义：把电流矢量投影到"转子磁场方向（d）"和"垂直方向（q）"上，投影结果在稳态是直流量。

2.4 dq 系 PI 调节（把直流误差变成电压指令）

vd = KP,d·(id* − id) + ∫KI,d·(id* − id)dt   i*ₕ = 0（SPM 压 d 轴）
vq = KP,q·(iq* − iq) + ∫KI,q·(iq* − iq)dt   i*q 来自速度环
输出限幅：|v| = √(v²d+v²q) ≤ Vdc/√3   电压限幅圆 + 积分钳位抗饱和

被控对象是绕组的 R–L 一阶惯性，PI 参数有闭式解（带宽法，§4.6）。教科书上还有交叉解耦前馈项（vd −= ωeLqiq 等），关节电机转速不高、交叉项小，绝大多数关节实现直接忽略，靠 PI 的积分顶掉。

2.5 反 Park 变换（dq → αβ，转回定子平面）

vα = vd·cosθe − vq·sinθe
vβ = vd·sinθe + vq·cosθe

与 Park 用同一对 sin/cos（CORDIC 一次调用两个都给出），4 乘 2 加。至此，"转子视角的直流指令"已经变回"定子平面的旋转电压矢量 (vα, vβ)"，剩下的问题是：三相逆变器只有 6 个开关，怎么输出一个任意方向、任意幅值的电压矢量？——SVPWM。

2.6 SVPWM（αβ 电压 → 三相占空比）

三相半桥共 8 种开关组合：6 个有效矢量（幅值 2Vdc/3，方向互差 60°）+ 2 个零矢量。SVPWM 的原理是用相邻两个有效矢量 + 零矢量按时间加权，在一个 PWM 周期里"平均出"目标矢量，七段式对称排布使谐波最小。其线性区可达 |v| ≤ Vdc/√3，比正弦 PWM（Vdc/2）多 15% 母线利用率——同样母线电压出更大力矩。

教科书做法要判扇区、解三角方程；工程实现用等价的 min–max 注入法，零分支判断，是嵌入式实现的标准姿势：

Va = vα;  Vb = (−vα + √3·vβ)/2;  Vc = (−vα − √3·vβ)/2  ← 投影回三相幅值
offset = −( max(Va,Vb,Vc) + min(Va,Vb,Vc) ) / 2  ← 共模注入，等效七段式
dutyx = 1/2 + (Vx + offset) / Vdc   x = a,b,c，写入 TIM1 的 CCR 寄存器

2.7 级联环路：电流环外面套两层

环路频率输入 → 输出整定要点
电流环10–40 kHz（PWM 同频）iq 指令 → vdq带宽法闭式解，机器人关节通常 0.5–2 kHz 带宽

力矩由 iq 唯一决定：T = 3/2·p·λf·iq（p 极对数，λf 转子磁链）。所以关节控制器本质上就是一个"力矩接口"：上层发 iq（或等价的 kp/kd/前馈参数），底层保证电流又快又准。

3.1 信号链总指挥：TIM1（一切都由它同步）

FOC 实时性的灵魂是"采样时刻与 PWM 相位精确锁定"。TIM1 配成中央对齐模式（计数器上数到峰值再下数到零，一个 PWM 周期 = 上数 + 下数），同时承担四个角色：发互补 PWM（带死区）、在计数器谷底硬件触发 ADC、接受比较器触发的刹车（BRK）、CCR 预装载双缓冲（本周期写入的占空比在下个更新事件才生效，杜绝毛刺）。20 kHz 时 ARR ≈ 4249（170 MHz ÷ 2 ÷ 20 kHz − 1）。

图 3 · 一个 PWM 周期内的时间轴：谷底采样 → ISR 计算 → 下个更新事件装载新占空比

为什么钉在谷底：低侧采样方案里，谷底对应三相下管全部导通、相电流全部流过采样电阻的时刻；且此刻离任何开关沿最远，开关噪声对 ADC 的串扰最小。这个"何时采样"的决策由 TIM1 触发 ADC 在硬件层面完成，与软件执行无关——软件晚一点进中断只影响控制延迟，不会破坏采样时刻的准确。这就是 G431 方案"力矩干净"的底层原因。

3.2 片内运放 PGA + 双 ADC：电流采样的前半程

采样电阻上的电压通常是毫伏级（例如 1 mΩ 电阻走 20 A 只有 20 mV），必须放大后才能喂给 ADC。G431 的做法：运放编成 PGA 模式（增益 2/4/8/16 由软件切换），同相端接采样电阻，输出在芯片内部直接路由到 ADC 输入通道——零外部运放、零模拟 PCB 走线，这在布板空间以毫米计的关节里是实打实的好处。两路相电流分别由 ADC1/ADC2 在同一触发沿同步采样（同时刻、同孔径，两相电流才可比），0.25 µs 完成转换。慢信号（母线电压、NTC 温度、基准分压）用硬件过采样升到 16-bit，CPU 拿到的已经是平均完的值。

3.3 CORDIC：三角函数从"贵"变"免费"（G431 最特别的东西）

CORDIC（坐标旋转数字计算机）的原理一句话：用一连串固定的微小旋转去逼近目标角，每步只需移位和加法——硬件实现极其便宜，却把三角函数/反三角函数变成了几个周期的外设调用。G431 把它做成了独立协处理器，对 FOC 的意义分三层：

  1. 一次调用出一对 sin/cos。Park 和反 Park 需要同一对 sinθe、cosθe，CORDIC 的调用约定是：往 WDATA 写入角度（注意格式：θ/π 的 Q1.31 定点，不是弧度原值），RDATA 顺序读出 cos、sin 两个 Q1.31 结果。整个电流环只需这一次三角函数调用。
  2. 省下的周期很可观。软件浮点 sinf()+cosf() 在 M4F 上是上百周期的库函数调用；CORDIC 满配置几十个周期出双结果，且精度随迭代次数可配。更重要的是它是独立外设：启动后 CPU 可以转身去算 Clarke/PI，回头再取结果——流水线并行，不占 FPU。
  3. atan2（phase 模式）是无感 FOC 的钥匙。观测器（反电动势/磁链）从 αβ 电压电流里估计转子角度，最后一步全是从 atan2 出角度；有感 FOC 也用它做电流矢量角监控、编码器标定校验。CORDIC 的 phase 模式同样几十周期。

诚实的工程账：Park 变换本身（4 乘 2 加）在 M4F 的 FPU 上只要十几个周期，用不用 CORDIC 都算得动；CORDIC 的真正价值是把 sin/cos/atan2 这类"贵函数"从电流环时间预算里拿掉，给观测器、保护、通信腾 CPU。20 kHz 电流环 G431 游刃有余，上到 40 kHz 依然从容。

3.4 FMAC：滤波白嫖一个 MAC 阵列

FMAC 是"滤波器专用小 DSP"：256 字内部 SRAM 划成输入/输出/系数三段，硬件执行 FIR/IIR 的乘累加，可挂 DMA 持续供数。FOC 里的正确用法：放慢环、别放电流环——电流反馈若经低通滤波会引入相位滞后，直接吃掉电流环相位裕度。典型用途是速度估计滤波（差分编码器计数噪声大）、母线电压前馈滤波（Vdc 波动实时折算进 SVPWM）、无感观测器的低通环节。这些滤波从 CPU 的周期预算里整体消失，且不占 FPU。

3.5 保护：比较器 → TIM1 刹车，独立于软件

4 个片内比较器的一路接电流信号（PGA 输出），阈值写 DAC 由软件设定（等效过流门限 = 阈值 ÷ 增益 ÷ 采样电阻）。比较器翻转直接路由到 TIM1 的 BRK 输入，同一个 PWM 周期内封锁六路输出——从过流发生到关断是纳秒级硬件路径，不依赖中断响应，CPU 死循环、栈溢出、看门狗打架时照样关得掉。软件侧再叠一层慢保护（堵转限时、过温、过压欠压）在主循环里巡检。关节会堵转、会摔，这条硬件底线是选 G431 的隐性理由。

4.2 实时骨架：一个中断扛电流环，主循环扛一切慢的

整个系统的实时结构极其简单——没有 RTOS 的必要（用了也只是给慢任务分时）：

  • ADC 转换完成中断（最高抢占优先级）＝ 电流环：读两相电流 → 偏置校正 → Clarke → CORDIC 取 sin/cos → Park → PI(d,q) → 反 Park → SVPWM → 写 CCR → 退出。整个 ISR 执行时间常数化（§3.6），必须在一个 PWM 周期内收尾。
  • 主循环（或 RTOS 线程）：1 kHz 跑速度/位置环和 CAN 协议，算出新的 iq* 后原子交换交给电流环（单写者单读者，一个 volatile float 就够）；100 Hz 跑温度/母线巡检与故障状态机。
  • 中断优先级从高到低：ADC(电流环) → 编码器定时器 → SysTick → CAN → 其它通信。任何中断都不允许比电流环高，包括你的调试打印。

4.5 整定顺序与调参闭式解

  1. 不接电机：跑 PWM+ADC，示波器/上位机看死区、触发时刻、电流底噪。
  2. 开环 I/F：旋转电压矢量拖动电机空转，验证相序、SVPWM、电流采样链路（这一步电流环还没闭）。
  3. 电角度标定（§4.3 ALIGN）。
  4. 电流环：用带宽法一步到位——KP = 2π·fbw·L，KI = 2π·fbw·R，fbw 取 PWM 频率的 1/10~1/20（R、L 用万用表+LCR 表或 ST Motor Profiler 自动辨识）。iq 阶跃看响应，超调 >20% 就降 fbw。
  5. 速度环 → 位置环：带宽依次降 5–10 倍，从外向内不许反超内环。
  6. 带上关节负载复验：堵转力矩、温升、CAN 指令到力矩的延迟。

4.6 踩坑速查（每条都是真实事故风格）

① DMA 访问不了 CCM SRAM——把 ADC 的 DMA 缓冲放进 CCMRAM，采到的全是旧数据或 HardFault；CCM 只放代码和纯 CPU 数据。
② CORDIC 角度格式是 θ/π 的 Q1.31，不是弧度；直接喂浮点弧度转的定点会得到"看似有波形、实则角度随机"的灵异现场。
③ M4F 的 FPU 是单精度——代码里混进 double（比如 3.14 字面量传参）瞬间掉到软浮点，ISR 周期翻几倍；全链路强制 float + 3.14f。
④ 电角度 ≠ 机械角度：θe = p·θm + θ₀ 忘乘极对数，现象是"电机嗡嗡抖动不转"；θ₀ 没标定，现象是"能转但力矩软、电流大"。多极对数下标定点还要防 360°/p 的机械周期混叠。
⑤ 低侧采样的窗口：占空比接近 100% 时下管导通窗口消失，谷底采到的是开关噪声——重载工况突然电流波形发毛，先查最小脉宽限制。
⑥ FPU 惰性压栈是隐形开销：任何用了 FPU 的中断都有 ~26 字压栈成本，频繁的低优先级浮点中断会偷电流环的时间；慢任务里少用浮点，或降频。
⑦ 电流环里别滤电流（§3.4）；同理别在 ISR 里 printf。

FOC 的原理一页纸：换个跟着转子转的坐标系（Clarke+Park），三相交流变两个直流量的 PI 问题，再变回去（反 Park）用 SVPWM 执行——目标是让电流矢量永远垂直于转子磁场。
G431 的答案一页纸：TIM1 中央对齐 PWM 在谷底硬件触发双 ADC 同步采样片内 PGA 放大过的相电流；比较器→BRK 硬件过流；Clarke/Park/PI/SVPWM 的乘加交给 170 MHz M4F，sin/cos/atan2 交给 CORDIC 协处理器，滤波交给 FMAC；一个 20 kHz 中断 ≈350 周期干完电流环，剩 95% 算力跑速度/位置环和 CAN——这颗芯片就是为这个数据流而生的。
代码骨架一句话：驱动/算法/应用三层 + 一个最高优先级中断扛电流环 + 主循环扛一切慢的 + 一个把顺序走对的上电状态机。
