HH-M03（BS21E 星闪模组）完全攻略

2026-10-12 · 引脚档案 → 复位按键之谜 → 烧录终局方案（猎手+拔插）→ SLE 协议栈启动的正确开关 · AirMouse-SLE 鼠标端实战沉淀
TL;DR：①烧录只拔插 USB 线，永远别按 RST 键（这板按键疑似没接，与 EB21duino 同病）；②拔插会打崩 CH340 端口，hsflash 不会自愈——用猎手脚本盯端口秒重启工具；③烧录中断后 loader 常驻下载模式，直跑 hsflash 即可续烧；④SLE 起不来先查 protocol/Kconfig 的 choice 有没有选 SUPPORT_SLE_PERIPHERAL。

一、板子是什么

润和 HH-M03 星闪模组（海思 BS21E，BLE5.4+SLE1.0，RISC-V 32bit @64MHz 带FPU，1MB Flash/160KB RAM），插在 CH340 载板上（串口 COM8 @115200，烧录+日志三合一）。在 AirMouse-SLE 项目中担任鼠标端（EB21duino 是 dongle 端）。资料：D:\work\NearLink\document\HH-M03\HH-M03 模组规格说明书-20241111.pdf。

二、引脚速查（模组 39 针，载板排针全引出）

功能引脚备注
LEDIO31 = LED_OUTpin 表明确标注；输出高电平亮（未实测载板是否焊了灯，串口日志为准）
I2C0（IMU用）IO25=CLK，IO26=DATAM3 计划接 ICM-20948
QDEC（编码器用）IO29=A，IO30=B硬件正交解码器，M3 接灵敏度旋钮
按键IO14（载板）HANDOFF 实测是按键输入
UART_L0（烧录+日志）IO15=RX，IO16=TX→ CH340 → COM8
USBIO7=D-，IO8=D+载板未连到 USB 口（用户查过原理图），此板无 USB 功能
SWDSWD_CLK(33)，SWD_DAT(34)调试口
nRESET❌ 39 针里没有引出！无法飞线外接复位键，只能拔插供电重启

三、复位按键之谜（重要！）

RST 键疑似没接到模组 nRESET（与 EB21duino 同款病）：按了电源灯不灭（这个正常，复位≠断电）、程序无感、烧录命中率 0。整个通宵的烧录失败几乎都耗在这上面。正确做法：拔插 USB 线 = 100% 硬重启模组。

注意一个陷阱：曾两次观察到"按复位后 COM8 掉线"，一度误以为按键有效——实为碰线/USB 抖动。判断复位是否生效的金标准是串口开机横幅（Jump to addr / Debug uart init succ / version: bs21e x.x.x），不是端口掉线。

四、烧录终局方案（已实证 100% 烧成过）

4.1 原理

  • flashboot 上电后约 1 秒内在 COM8@115200 监听串口下载，随后跳转 App
  • 坑：拔插瞬间 CH340 从系统消失 → 正在等待的 hsflash 句柄死掉且不会重开 → 错过窗口
  • 猎手脚本补这一刀：20ms 轮询 COM8，端口消失杀 hsflash，端口回来（~300-600ms）秒重启 hsflash 抢窗口尾巴

4.2.1 猎手脚本完整源码（v3，实时输出版）

副本：hh-m03-burn-hunter.py（与本页同目录）；原始路径 D:\work\AirMouse-SLE-research\hhm03_burn_hunter.py。改固件路径/串口只要动开头的 FW 和 PORT 常量——EB21duino 换成 COM10 + 跳帽拔插同样可用。

import subprocess, time, sys, threading, serial.tools.list_ports

HSFLASH = r"D:\hispark\tools\hsflash\hsflash.exe"
FW = r"D:\work\AirMouse-SLE\src\output\bs21e\fwpkg\standard-bs21e-1100e\bs21e_all_in_one.fwpkg"
PORT = "COM8"

def ts(): return time.strftime("%H:%M:%S")

def com_present():
    return any(p.device == PORT for p in serial.tools.list_ports.comports())

def spawn():
    proc = subprocess.Popen([HSFLASH, "write", "-c", "bs21e", "-p", PORT,
                             "-b", "115200", "-f", FW],
                            stdout=subprocess.PIPE, stderr=subprocess.STDOUT,
                            text=True, bufsize=1)
    state = {"lines": [], "success": False}
    def reader():
        try:
            for line in proc.stdout:
                line = line.rstrip()
                if not line: continue
                state["lines"].append(line); state["lines"] = state["lines"][-20:]
                s = line.strip()
                if "%" in s:   # 进度条行压缩: 只在整10%透传
                    try:
                        pct = int(s.split("%")[0].strip(" [=-]").split("-")[-1].strip(" []=-"))
                        if pct % 10 == 0: print(f"  [hsflash] ...{pct}%", flush=True)
                    except Exception: pass
                else:
                    print(f"  [hsflash] {line}", flush=True)
                if "successfully" in line.lower() and "burn" in line.lower():
                    state["success"] = True
        except Exception: pass
    threading.Thread(target=reader, daemon=True).start()
    return proc, state

def main():
    print(f"[hunter v3] {ts()} 等待 {PORT} ...", flush=True)
    t0 = time.time()
    while not com_present():
        time.sleep(0.02)
        if time.time() - t0 > 120: print("[hunter] 2分钟没等到端口, 退出"); return 1
    print(f"[hunter] {ts()} 端口在位。", flush=True)
    print("[hunter] >>> 现在可以拔插 HH-M03 的 USB 线了(等2秒再插回), 可重复 <<<", flush=True)
    rounds = 0
    t_end = time.time() + 900   # 15分钟, 只限制开新回合, 绝不打断进行中的烧录
    while True:
        if time.time() > t_end: return 1
        rounds += 1
        print(f"[hunter] {ts()} ---- 回合 {rounds}: 启动 hsflash ----", flush=True)
        proc, state = spawn()
        while True:
            if proc.poll() is not None: break
            if not com_present():
                proc.kill(); proc.wait()
                t1 = time.time()
                while not com_present():
                    time.sleep(0.01)
                    if time.time() - t1 > 15: break
                print(f"[hunter] {ts()} 端口重现({(time.time()-t1)*1000:.0f}ms) → 重启hsflash抢窗口", flush=True)
                break
            if state["success"]:
                proc.wait(timeout=30); break
            time.sleep(0.02)
        if state["success"]:
            print(f"[hunter] {ts()} *** BURN SUCCESS ***", flush=True); return 0
        time.sleep(0.05)

if __name__ == "__main__":
    sys.exit(main())

五、SLE 协议栈启动的正确开关（大坑）

enable_sle() 返回成功但回调永不到来 / SLE 起不来的第一嫌疑：src/protocol/Kconfig 里有个 choice "Select sle ble support"，默认选 SUPPORT_SLE_BLE_CENTRAL_DEFAULT（空转项，不编 SLE 应用栈）。必须显式选角色：
# 鼠标端(server/广播方):
python build/script/usr_config.py --command setconfig --chip bs21e --target standard-bs21e-1100e \
    SAMPLE_ENABLE=y ENABLE_PRODUCTS_SAMPLE=y SAMPLE_SUPPORT_AIRMOUSE_SLE=y AIRMOUSE_SLE_MOUSE=y \
    SUPPORT_SLE_PERIPHERAL=y
# dongle端(client/扫描方)对应选 SUPPORT_SLE_CENTRAL
python build.py standard-bs21e-1100e -c   # 切choice后必须clean build

症状对照：固件跑着但 alive: sle=FAIL = 协议栈没编进去；修好后 alive: sle=OK announce=ON。SLE 服务端最小代码模板见 AirMouse-SLE/src/application/samples/products/airmouse_sle/airmouse_mouse.c（广播名 sle_airmouse，UUID 0xA179/0xA17A，广播/连接参数抄官方 rcu 样例）。

六、SLE 双板联调坑史（2026-10-13 凌晨，一晚四连修）

链路：HH-M03(v8) 100Hz发矩形dx/dy → SLE → EB21duino(v3) 收包转USB HID。整晚逐环点亮，每个坑都有日志实证：

版本坑症状与修法
v5广播载荷缺TLVsle_set_announce_data拒绝空载荷——必须带"发现等级+接入模式"两个TLV(各3字节)，名字放扫描响应。修前 sle=FAIL，修后 announce=ON
v6conn_id=0 误判未连接第一条连接的id就是0！用conn_id != 0当连接判据→发送器永远不发。经典零值bug。修法：独立link_up布尔，回调里维护
v7缺CCCD描述符没有CCCD预使能，ssaps_notify_indicate全被拒(tx_ok=0/3360)。修法：特征挂{0x01,0x00}的CCCD描述符(官方air_mouse同款)。修后 tx=1145包被接受
v8/dongle v3配对残留每次全量烧录重置NV→身份变化→旧配对互不认。修法：两端开机sle_remove_all_pairs()。⚠️ 修后配对仍失败，见残局

6.1 残局：配对失败 0x8000600d（唯一未通环节）

现状：连接→pair complete status:0x8000600d失败→掉线(reason 0x1b/0x10)→重连，无限抖动。配对失败时tx被栈接受但对端rx=0（通知没真正送达，推测SMP失败/加密未建立）。清配对记录无效。其余全通：dongle USB已枚举为HID鼠标，光标输出通路就绪——配对一通即是全链贯通。

下次嫌疑清单（按优先级）：

  1. mouse广播 own_addr 全零 {0,0,0,0,0,0}——dongle看到对端是00:..:00，SMP可能拒绝（sle_uart样例也用全零但官方rcu用真地址，存疑）
  2. dongle在 enable回调里调 sle_remove_all_pairs 的时机（官方client不在那时清）
  3. 杀手锏对照实验：官方 sle_uart 双板样例原样烧入两板——它配对能成=我们的代码问题；也败=板子/环境问题，一测定位

6.2 联调方法论沉淀

  • 双口串口同时监听（python双线程）是定位抖动类问题的神器：dongle侧和mouse侧的事件时间线一拼，半开连接/单侧事件缺失一眼看穿
  • 日志参数错位排查：conn=0x9015b9ee这种闪存地址出现在整数位置=printf格式串少了占位符（%s比参数少）
  • 烧录换NV身份：fwpkg全量包含NV——每次重烧=设备身份重置，配对类问题先想到这个
  • 两端固件版本戳（alive[v8]/AT+AMVER答dongle[v3]）避免了至少三次"烧没烧上"的罗生门
