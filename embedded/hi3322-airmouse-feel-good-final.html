终态一句话：3322 + ICM20948 + EB21duino 三件套，上电即用，转手腕/摆臂屏幕光标实时跟随，拔插 dongle 自动重连，用户实测手感满意。信号链：陀螺−零偏 → 一阶滤波(τ≈1ms) → 静止门 → ×50px/deg → SLE(双端压缩连接参数) → USB HID——零姿态计算，CPU 5%，EKF 版留在备胎分支。

1 · 为什么放弃 EKF 姿态差分（三次滞后追凶的结果）

M3-M4 期间光标映射用的是"EKF 四元数→欧拉角→逐拍差分"。用户实测始终"非常不跟手"（0.5~1s 级滞后），追凶三轮：

#嫌疑判决依据
1EKF 加计观测滞后有罪（部分）快速转动时陀螺积分与低通后重力矢量"打架"，姿态输出永远慢半拍；叠加输入低通（0.1→0.5 后仍有 10ms+）与差分链
2motionless 冻结（导航级静止检测外泄到光标）有罪（大头之一）检测器的运动阈值 5°/s+迟滞窗口（为 ZUPT 设计）——小幅摆腕 2~3°/s 达不到解冻阈值，"摆了半秒才动"。修法：光标冻结交给死区（0.03°/拍≈3°/s 等效），motionless 只留给 EKF 内部
3SLE 传输慢无罪（但顺手修了）实测 100~1700ms"延迟"最终被证明是测量尺子的量化 bug（§3）；不过连接调度参数双端压缩后体感确实更好

结论（用户提出，实测验证）：空鼠不需要绝对姿态——陀螺角速度本身就是角位移的直接测量（∫ω·dt）。速率直出只欠一个零偏补偿，于是：

// 终版映射（sle_client.c，AIM_USE_GYRO_DIRECT=1）
corr = gyro − gyro_bias                 // 零偏：静止(<1°/s 持续0.3s)时 EMA(0.02) 缓慢跟踪
lpf  += 0.8×(corr − lpf)                // 一阶滤波 τ≈1ms
静止门内：输出 0 + 学零偏；否则：
dx = −ωz(dps) × 50 px/deg × 10ms        // 绕Z→dx（实测定稿，反号）
dy = +ωx(dps) × 50 px/deg × 10ms        // 绕X→dy（实测再反号定稿）

EKF（quat-zupt-ekf 七态）完整保留在固件里编译但不再驱动光标——stable/m4-gain50 分支可一键切回，未来做"姿态锚定/走廊混合"时再请它出山。

2 · 延迟大追凶全案（方法论教科书）

2.1 分段测量法

固件内埋"甩动打点"（角速度>150°/s 单发 [SNAP]），Mac 双端毫秒时间戳监听（3322 @750000 + dongle 日志口 @115200），拼时间线切三段：传感器+固件段 / SLE 空口段 / USB HID 段。甩动 5~12 次取分布。

2.2 三个反转

  1. 算法嫌疑：直出版一样"慢" → 算法洗清；
  2. 连接参数嫌疑：实测 100~1700ms 随机抖动，像"包等连接事件窗口"→ 双端压参数（见 §2.3），但复测依旧 13~1600ms；
  3. 尺子反转：发现 dongle 统计打印每 100 包一行——我监听计数跳变的"量化粒度"恰好 0~1s，与"延迟"分布完全重合。之前量的全是打印聚合周期，链路本身是快的。用户插回 USB HID 实测手感好 = 终审判决。
测量方法论铁律：聚合打印（每 N 包/行）做时间戳测量自带 0~N/rate 秒量化误差，必须用事件驱动的瞬时标记（ dongle 侧保留的 [BURST] 静→动首包瞬时打印就是修正后的尺子，零开销常驻）。另：两个瞬时标记必须语义对称（首包发送 ↔ 首包到达），错配（峰值时刻↔首包到达）会配对到下一次事件、秒级错位。

2.3 SLE 连接参数的正确姿势（踩坑实录）

做法结果
bs_sle_config(SLE_CONFIG_CONNECT_SET_DEFAULT_PARAM, ...) 全局默认PAIR 直接 timeout 破坏配对（回退验证实锤）
3322 侧：preset ADD（SLE_CONFIG_CONNECT_PRESET_PARAM，mode_id=1，interval 8-16 slot）+ 连接后 bs_sle_set_connect_param(dev_id, 1)（ssf_connection.h:860）✅ 不破坏配对
dongle 侧：连接回调 CONNECTED 分支 sle_update_connect_param（sle_connection_manager.h:979，server 主动发起，interval 8-16 slot）✅ 双管齐下

注意 SLE interval 单位是 slot（sle_connection_manager.h 注释），不是 BLE 的 1.25ms。

3 · 200Hz 实验（唯一一次算力翻车）

EKF 是 double 精度，RV32F 只有单精度硬件——200Hz 节拍下软浮点计算超 5ms/拍预算，CPU 饱和→看门狗复位循环（连心跳都没有），dongle 侧还叠半开连接致重连失败（0x80006016/0x8000600a）。回滚 100Hz 即愈。将来提速的正确路径：EKF 单精度 float 化（计算量降 5-10×，用 quat-zupt-ekf 差分框架重验证）——直出架构下已无此需求。
