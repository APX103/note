1 · 背景与目标架构

现有可用系统（已在家中跑通）：AirMouse-SLE 项目（Windows 机 D:\work\AirMouse-SLE，SDK clone 自 fbb_bs2x）——鼠标端 HH-M03（润和 BS21E 模组）⇄（星闪 SLE 1.0）⇄ dongle 端 EB21duino（利尔达 BS21 板，出厂固件即 SLE 鼠标接收器，插电脑 USB 枚举为 HID）。

商单约束：产品必须用 Hi3322（谛听 HiDiTing V100）做主控。因此目标架构 = 把鼠标端从 HH-M03/BS21E 换成 3322，dongle 端不变：

3322 (HiDiTing V100, SLE 2.0)          EB21duino (BS21, SLE 1.0)
┌─────────────────────────┐   星闪空口   ┌──────────────────────┐
│ IMU 采样 → 姿态解算      │ ──────────→ │ SLE Central 接收      │
│ → 光标增量打包           │  SSAP 写/通知 │ → 翻译成 USB HID report│──→ 电脑
│ (SLE Central 角色)       │             │ (出厂固件已实现)       │
└─────────────────────────┘             └──────────────────────┘

3322 拿到的增益：双 RISC-V（BCPU ≤64MHz + MCPU ≤266MHz）+ 50 GOPS NPU + 2.3MB SRAM + 16MB PSRAM（hispark-hi3322/index.md）——算力和内存远超 BS21E（单核 RISC-V 64MHz / 160KB RAM），跑 9 轴 EKF 姿态解算 + 姿态锚定光标控制（算法设计见 姊妹篇）绰绰有余。

3.4 异步纪律（官方指南红线）

星闪开发指南（docs/zh-CN/HiDiTingV100/samples/connect/星闪开发指南/README.md，455 行）反复强调：接口返回成功 ≠ 异步流程完成。必须等连接状态回调报告 SLE_CONNECT_CONNECTED 后才能交换 MTU/版本；"pair request submitted"后超时，先查对端是否还在广播、地址是否取自扫描日志。排障表同文件 :453。

4 · 零代码上板验证序列（AT 命令）

来自 sample README，业务串口波特率 750000。对端（EB21duino）保持出厂 dongle 固件的广播/服务端状态：

# Central 侧（3322）
AT+SLECLIENTENABLE
AT+SLECLIENTINIT
AT+SLECLIENTSCAN=0            # 开扫描，从日志取对端 6 字节地址
AT+SLECLIENTPAIR=<地址字节1>,...,<地址字节6>
AT+SLECLIENTSCAN=1            # 停扫描
AT+SLECLIENTFIND              # 服务发现：输出服务 UUID / 特征 UUID / 句柄
AT+SLECLIENTCB                # 为已发现 UUID 注册读写/通知回调
AT+SLECLIENTWRITE=<特征句柄>   # ★发数据（未来鼠标增量包的入口）

官方声明的业务扩展点（写代码时改哪里）：

  • Central 发送的数据内容 → sle_client.c 的 sle_ssapc_write()；
  • 收到的读/写/通知/指示处理 → g_sle_demo_ssap_cb 回调簇；
  • 服务/特征 UUID、权限 → sle_server.c 的 service_template（给对端自研 BS2X 固件时用）；
  • 量产前必须换掉示例 UUID，地址/句柄不可固化为静态配置（指南 §395、§438）。

5.1 本次会话的网页级误判（已纠正，勿重蹈）

本次调研中段，agent 仅凭利尔达官网《EB21 吞吐测试》文章正文中"Type-C 经 CP210x 串口 115200 连电脑"的描述，得出"EB21duino 的 USB 是串口，当不了 HID dongle"的错误结论，随后又断言"公开网页搜不到 EB21duino 资料"。

事实：这些信息当时就公开在利尔达自己的官方资料里，是 agent 没看。复盘（2026-10-12 晚补查）：
  • 官网吞吐文章页内就挂着利尔达飞书知识库链接：《Lierda EB21吞吐测试指南》（游客可读，正文和图片直接内嵌在页面 payload 里）；
  • 该飞书文档的开发板实拍照片（图2.1/图2.3）明确显示：板底边两个 Type-C，丝印分别为 "UART" 与 "USB"——UART 口经 CP210x 桥接（照片可见芯片丝印），USB 口为模组原生 USB。与 eb21duino-complete-guide.html 的原理图结论（C1=CP2105 双串口、C2=BS21 原生 USB，出厂固件枚举 SLE_MOUSE HID）完全一致；
  • 飞书文档正文原句："Lierda EB21 是基于华为 2821 芯片研发的星闪透传模组"——官方明示芯片为 Hi2821（板上 flashboot 横幅自报 bs21e 1.0.19，两者为同族事实并存，此处不强行归一）；
  • 同库还有 《Lierda EB21模组通信拉距测试报告_Rev1.0.pdf》 等兄弟文档。
教训（三条，按发生顺序）：① 只读了文章正文没点开文章里的外链（飞书文档才是真资料库）；② 只提取了文字没看文档里的图片——硬件接口形态照片里一清二楚；③ 把"搜索引擎搜不到"当成"网上没有"，没去厂商自有渠道（官网下载中心 API、飞书知识库、产品页 /iot-module/<id>）里翻。对硬件能力的断言，必须以原理图/实测/官方文档原文为准；确定性标注的标准必须统一：跑通>源码>文档>网文。

6 · 唯一悬案：SLE 2.0 ↔ SLE 1.0 空口互通（上板判据）

为什么悬：3322 是 SLE 2.0 / 16Mbps（SDK README 原文），BS21 是 SLE 1.0（EB21duino 笔记实证）。用户家中跑通的链路是 BS21E ↔ BS21（同为 SLE 1.0，同版本）。跨版本空口行为（版本协商、PHY 能力交集）无任何公开文档或实测记录。唯一利好：SSAP 应用层版本常量双方同为 1（sle_com.h:69，BS2X 侧 SSAP 也是标准 ssap 协议）。

测试步骤（半天内出结论）：3322 烧 diting-community → 业务串口 750000 → 按 §4 序列操作，EB21duino 保持出厂 dongle 固件上电：

  • 判据 A：AT+SLECLIENTFIND 能列出 EB21 的服务与特征句柄 → 协议层互通实锤；
  • 判据 B：AT+SLECLIENTWRITE=<句柄> 发数字节后电脑鼠标动了 → 端到端实锤，商单技术风险清零；
  • 失败排障：按星闪开发指南 :453 表——查广播是否在继续、地址是否取自扫描日志、是否等到了 CONNECTED 回调再 FIND；配对超时先重广播。

兜底预案（若跨版本不通）：dongle 端换用 fbb_bs2x SDK 自刷固件（USB Mouse + SLE Central 样例组合，§2 环节 5 已确认样例齐全），把版本协商的主动权拿到自己手里；3322 端逻辑不变。

附：Mac 本机当前挂着一个 CH340 串口（/dev/cu.usbserial-2110，静默无数据）——疑似 HH-M03 载板（其载板即 CH340），未确认；上板测试时可复用。
