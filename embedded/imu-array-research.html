IMU 阵列调研：32 颗 MEMS 叠加的 √N 降噪，与它真正的难点

will127534/IMU_Array 深度拆解 · 2026-10-02 · 深度评级：值得精读 —— 协议巧思 + 全链路时间设计 + 一个诚实的负结果

§1 项目速览

这是 Will Whang 的开源硬件项目（MIT，~350 star）：一块传感板载 32 颗 TDK ICM-42688-P，由一颗 iCE40UP5K FPGA 聚合读出，主机是 RP2040（Pico / 自制处理板）。作者的目标很实际：用它替代地震勘探里的动圈式 geophone 检波器——他此前做 geophone 地震仪时被模拟链路（负阻抗变换器抵消线圈内阻、运放、数字电位器、易自激的校准电路）折磨够了，想用"多颗便宜的数字传感器取平均"把模拟复杂度和贵价 ADI 芯片一起干掉。灵感来自 Sony 给 SPRESENSE 做的 16 颗 IMU 阵列板——那块板因为性能太好被列入出口管制，作者买不到，于是自己造了 32 颗的。

部件选型角色
传感器32 × ICM-42688-P（零售约二三十元/颗）消费级顶级 MEMS IMU，每颗独立 MISO
聚合iCE40UP5K（~5k LUT，一二十元）4096-bit 并转串移位寄存器 + 总线嗅探
主机RP2040 超频 250 MHz（Pico → 自制 Pico W 平替）配置、采数、标定、融合、传输
总线SPI：SCK/MOSI/CS 广播，32 根独立 MISO一次事务并行读 32 颗
同步共用 32.768 kHz CLKIN（RTC 模式）+ 片内时间戳全阵列同源采样时刻

仓库含三块板的 KiCad 工程（传感板 6 层 via-in-pad、bring-up 转接板、处理板）、Verilog、MicroPython 与 C SDK 固件，还有一篇内容比 README 丰富得多的博客长文。本文所有代码结论都直接读自仓库源码。

§2 基础：MEMS IMU 的噪声三件套

看懂这个项目先要分清 MEMS IMU 的三类误差，因为阵列平均只对其中一类有效：

  • 白噪声（宽带噪声）：采样间独立，表现为陀螺输出的角度随机游走（ARW）。ICM-42688-P 陀螺噪密度约 2.8 mdps/√Hz（数据手册 LN 模式），折合 ARW ≈ 0.17°/√h。N 颗独立取平均，这项按 1/√N 缩小——32 颗理论到 0.5 mdps/√Hz、ARW ≈ 0.03°/√h，摸到战术级门槛。
  • 偏置不稳定性（bias instability）：1/f 噪声，Allan 方差曲线的锅底。它是慢变过程，平均几乎压不掉，且各颗之间若有共同来源（温度、供电纹波、振动），平均更压不掉。
  • 确定性误差：刻度因子、轴间交叉耦合、安装失准角、常置偏置。这些不是噪声，是参数——靠标定消除，不靠平均（§8）。

Allan 方差是把一段静态数据在不同平均时间 τ 上重算方差，白噪声段斜率 −½、锅底即偏置不稳定性——它是评价"平均有没有用"的标准工具，作者的全部实测都用 ADEV 曲线呈现。

§3 核心思想：√N 平均与"虚拟 IMU"

把 N 颗装在刚性基板上的 IMU 输出对齐到同一坐标系后取平均，得到一颗"虚拟 IMU"：真实角速度/比力对所有颗是共模信号（刚性假设下完全相同），而各颗的白噪声互相独立，方差相加后除以 N² → 噪声标准差除以 √N。这是通信/测量领域最古老的空间分集思想：用面积和信息量换精度，而不是用钱换精度。

Sony 那块 16 颗 SPRESENSE 阵列被出口管制，就是 √N 的威力证明：消费级单颗 × √16 = 4 倍，直接把消费级 MEMS 推进战术级应用区，管制机构认为这改变了游戏的性质。JAXA 的论文（Kamata 2020）是这个方向的学术源头之一。

§4 真正的难点：不是算法，是同步和带宽

想清楚 §3 只需要十分钟，难的是工程：32 颗 IMU，200 Hz，每颗每帧 16 字节 FIFO 包——100 KB/s、819 kbps的持续流。传统做法是 MCU 挂 32 个 CS 轮询 SPI：先不说 RP2040 只有 2 个 SPI 口，轮询意味着 32 颗的采样时刻彼此错开几毫秒——对单颗而言只是延迟，对"取平均合成一颗虚拟 IMU"而言是致命的：不同时刻的样本平均，等于给系统多加了一阶滤波还混入相位误差。阵列的价值前提是"同一时刻"，所以问题变成：如何让 32 颗在同一个时钟沿采样、并且在下一帧到来前把 512 字节搬走。

作者的答案分三层，每层都很便宜：

  • 采样同源：ICM-42688-P 支持 CLKIN 外部时钟输入 + RTC 模式，片内采样逻辑和 32 kHz 时钟锁定。给 32 颗分同一根 32.768 kHz 时钟线，它们的采样与片内时间戳计数器全部同源——这是"同一时刻"的物理保证。
  • 读出并行：SCK/MOSI/CS 三根线对全体广播（所有芯片并联在同一总线上），但 MISO 每颗单独一根拉进 FPGA。于是"读一颗"的 SPI 事务天然变成"读全部"——32 颗在同一组时钟沿各自吐出自己的 FIFO 包。
  • 带宽汇聚：FPGA 用一个 4096-bit 移位寄存器（32 × 128 bit）把 32 路并行位流锁存，再串行吐给 MCU。README 里作者自嘲"懒得省这 4096 个 LUT，反正 iCE40 便宜"——一片 UP5K 也就一二十块钱，比任何"聪明"方案都便宜。

§5 解剖：总线拓扑与两次事务

主机每帧只做两次 SPI 事务。第一次"顺便"完成 32 颗同步采集：

最妙的一笔：0xB0 的双重身份

整个设计里最优雅的细节是这个巧合的利用：读 ICM-42688 FIFO 数据寄存器的 SPI 首字节是 0x30 | 0x80 = 0xB0（寄存器地址 + 读位）。FPGA 嗅探 MOSI 上的这个字节，把它同时当作自己的 LOAD 命令：

// spi_slave.v —— 命令字节 0xB0 正是 ICM42688 的 FIFO 读地址
CMD: if (cmd_get) begin
    if (cmd_byte == 8'hB0) next_state = LOAD;   // 与 32 颗 IMU 同步锁存
    else                   next_state = SEND;    // 其他（如 0x55）→ 回读快照
end

LOAD: begin  // 每个 SCK 上升沿，32 路并行移位进 4096-bit 寄存器
    miso_shift_register[127:0]   <= {miso_shift_register[126:0], IMU_MISO1};
    ...
    miso_shift_register[4095:3968] <= {miso_shift_register[4094:3968], IMU_MISO32};
end

于是不需要任何独立的命令协议、不需要先配置 FPGA 再配 IMU：主机按最普通的方式读 32 颗共享总线的 FIFO，采集就顺带完成了。FPGA 对 IMU 是"旁听者"，对主机是"快照缓冲"。

两个值得注意的实现细节：其一，读出阶段主机把 SPI 从 CPHA=0 切到 CPHA=1——因为 FPGA 在 SCK 上升沿移位输出，主机改在下降沿采样，半个周期的余量就出来了（代码注释原话："Because of the verilog code the data always shift at the postive edge"）。其二，FPGA 的 bitstream 没有外挂配置 Flash，每次上电由 RP2040 通过 SPI 直接灌进 iCE40（`initFPGA()`：复位 → 8 字节唤醒 → 灌 bitstream → 49 字节收尾），省一颗料还让固件和门逻辑版本永远绑定。

§6 全链路时间设计

这个项目对"时间"的处理贯穿到每一个环节，是它最像精密仪器的一部分：

  • 采样层：32.768 kHz CLKIN → 各片 RTC 模式锁定，采样与 DRDY 同源；每个 FIFO 包还带 16-bit 片内时间戳（32 kHz 计数，分辨率 30.5 µs）。
  • 主时钟层：处理板把 RP2040 的 12 MHz 晶振换成 VCTCXO，用 PIO 输入捕获测 GPS PPS 周期，P 控制器（Kp=0.1 + 滑动平均）输出 PWM 当 DAC 驯服压控端——一个自制 GPSDO。给 IMU 阵列的 32 kHz 就从这颗驯服后的晶振分出来，采样时钟可溯源到 GPS/UTC。
  • 数据层：每帧样本同时携带片内时间戳 + 主机 64-bit µs 时钟 + 校准到 UNIX 时间的偏移；对地震学这种靠相位相干叠加的领域，采样时刻的准确性是硬指标。
  • 分配层：双核分工——core1 跑 DRDY 中断驱动的采集 + 标定 + 融合，core0 跑 Wi-Fi/TCP 栈；作者甚至用"测 CS 引脚电平宽度"的办法在示波器上直接读出软件处理耗时。

§7 硬件细节里的深意

  • 四组旋转安装（0°/90°/180°/270°，每组 8 颗）：博客明确说这不是为了布线好看，而是照抄 Sony——抵消轴向灵敏度差异。MEMS 的 X/Y 轴是同一敏感结构的两个方向、Z 轴是另一种结构（作者的 ADEV 实测也看到 Z 轴曲线形状不同）；四向对称摆放让每颗的"个体轴差"在阵列层面互相抵消。代价是融合前要做旋转对齐：
组x′y′z′
组1（0°）xyz（不变）
组2（90°）−yx
组3（180°）−x−y
组4（270°）y−x
  • 机械应力设计：TDK 的 IMU 布局指南（远离螺钉、远离板边）在 32 颗的密度下根本无法全部满足，作者改用三条原则——方形板、对角线上不放 IMU（对角是应力最集中的地方）、三个螺钉孔三角安装（三点定义一个平面，装夹不产生弯矩）。LGA 封装的 MEMS 对基板应力极敏感，应力→偏置漂移是共模杀手。
  • 量程选择暴露用途：陀螺满量程设到最细的 ±15.625 dps、加速度 ±2 g——地震信号极小，要的是分辨率不是动态范围。16-bit 下陀螺 LSB ≈ 0.00048 dps。
  • 电源与热：FPGA 的 1.2 V 内核电和 3.3 V 都从连接板送来，传感板上不做 DC-DC——板上不发热，温度梯度是共模漂移的另一个来源。SPI 引脚间插地脚控制回流路径；FPC 选 22 pin 是为了直接复用树莓派摄像头排线。
  • 6 层板 + via-in-pad：32 颗 QFN 挤在一小块方形板上，退耦 0402 放背面手焊；顶层交给 JLC/PCBWay 贴。

§8 标定：二十面体与 32 套矩阵

确定性误差（刻度、失准、偏置）靠标定。作者按 Nilsson/OpenShoe 的经典方法，3D 打印一个二十面体夹具，20 个面各静置 90 s，对 32 颗各解出一个 3×3 刻度/失准矩阵和偏置向量，MATLAB 生成 imu_cal.h 编进固件。实测矩阵很有说服力：对角项普遍落在 0.997–1.005（±0.3% 的刻度误差），交叉项 ~0.001–0.004，其中第 11 颗的 Z 轴刻度 0.969——差了 3%，明显个体异常，正好演示了为什么"颗颗标定"而不是"一颗标全家"。

融合流水线（C 代码，RP2040 无硬件 FPU 全靠软浮点，500 Hz 仍绰绰有余）：旋转对齐 → 减偏置 → 乘刻度矩阵 → 32 颗平均 → 输出"虚拟 IMU"的 6 轴 + 平均温度。

§9 现实检验：作者自己的 ADEV 实验（本文最重要的一节）

负结果也是结果：博客里最诚实的部分是作者把实测 ADEV 与 Sony 论文（INERTIAL 2020, Fig.9）对比后的坦白——静态数据下，陀螺取平均的改善远小于理论 √N；他复现 Sony 的离群抑制/干扰抑制滤波，只在短 τ 段有点用，τ > 0.2 s 收益消失，τ ≈ 300 s 时离群抑制甚至比朴素平均更差；标定后的 ADEV 相比标定前也没有明显变化。他自评这次复现"失败"。

但这个"失败"恰好验证了图 1 的物理：静态 ADEV 的中长 τ 段由共模项主导——温度漂移、基板微应变、供电纹波，这些 32 颗一起漂，平均不掉；√N 只作用于白噪声段（短 τ）。他的另一个观察也指向同一处：静止时的陀螺数据反而比缓慢转动时更噪——典型的 1/f/慢漂移特征，不是白噪声。所以正确的期望是：

  • 短 τ（高频白噪声段）：阵列给满 √N ≈ 5.7 倍，ARW 0.17 → 0.03°/√h；
  • 中长 τ（锅底与漂移段）：收益取决于噪声里独立成分的占比，可能接近零；
  • 改善中长 τ 的正道不是加颗数，而是控温、控应力、控电源纹波——共模源头治理；
  • Sony 论文的收益场景包含动态激励与个体筛选，静态复现本来就是最苛刻的考卷。

对想做阵列的人，这是全文最值钱的一段：先测单颗的 Allan 曲线，把独立/共模成分分清楚，再决定颗数——如果共模占主导，加颗只是加钱。

§10 更深的视角：阵列是信号处理结构，不只是"多买几颗"

刚性基板上的 N 颗 IMU，把测量空间正交分成了两半：

  • 共模子空间（1 维）：刚体上所有点角速度相同——这就是真实信号（+共模噪声）。
  • 差分子空间（N−1 维）：任何"各颗不一致"的成分——按定义不可能是角速度，只能是单颗噪声、电气干扰或故障。

朴素平均只是对这个结构最粗的利用（把差模功率均匀压掉 1/N）。JAXA 的 Kamata 2020 把它做成显式的阵列信号处理：干扰抑制（电气串扰在颗间有特定空间指纹，可投影剔除）与离群抑制（某颗偏离共识即判为故障，降权或剔除）。再往前一步：加速度计阵列还天然感知角加速度——间距 r 的两颗加速度计之差包含 α×r 项，这就是"无陀螺惯导"的原理；而旋转-平动分离对地震学正好是刚需（旋转地震学：旋转分量能区分 P/S 波与瑞利波的水平分量）。作者替换 geophone 的项目，方向上正踩在这条线上。

§12 拍板：这个项目教给我们什么

值得直接抄的五个设计：
① SPI"广播写、并行读"拓扑——共享 SCK/MOSI/CS + 每颗独立 MISO，一颗的价格把 N 颗变成同刻采样，任何多传感器同读场景（ADC 阵列、麦克风阵列）都适用；
② 0xB0 双重身份——用协议里现成的字节当 FPGA 命令，零额外协议成本；
③ CLKIN 同源 + 片内时间戳——同步不靠软件对齐，靠物理时钟；
④ MCU 软加载 bitstream——iCE40 不挂配置 Flash，固件/门逻辑版本强绑定；
⑤ 诚实的方法论——先测单颗 Allan 曲线、分清独立/共模成分再定颗数。
什么时候考虑阵列：单颗 MEMS 已到顶、还差一个数量级的白噪声指标、且预算/共模环境允许时。反之若误差由偏置漂移或振动主导，先治源头，别买 32 颗。
