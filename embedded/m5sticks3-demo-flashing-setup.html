01 / 结论先行：最方便的开发方式

官网为 StickS3 列了四条路：Arduino IDE、UiFlow2（MicroPython 图形化）、ESP-IDF、PlatformIO。结合我们已有笔记的实际经验，本机定型为 arduino-cli + esp32:esp32 核心 + M5Unified/M5GFX 库，理由有三：

  • 8 月两篇 StickS3 笔记验证过 arduino-cli 全流程（环境搭建、库补丁、烧录），命令行天然适合交给 agent 执行；Arduino IDE 只是同一工具链的 GUI 壳。
  • 本机已装 esp32:esp32 3.3.10 核心，与 M5Stack 官方板包 m5stack:esp32 3.3.9 同代（均已跟进 Arduino 3.x）。不必为一个板型再装一套约 1 GB 的平行核心，FQBN 加上参数即可等价。
  • M5Unified 0.2.17 已内置 board_M5StickS3 板型识别（I²C 47/48、Port A 9/10、M5PM1 电源类），例程代码板卡无关，无需改一行。

02 / 硬件与连接确认

StickS3（SKU K150）：ESP32-S3-PICO-1-N8R8（8 MB Flash + 8 MB Octal PSRAM）、1.14″ ST7789P3（135×240）、BMI270 六轴、ES8311 音频 codec + MEMS 麦克风 + 喇叭、板载红外收发（TX=46 / RX=42）、M5PM1 电源管理。

  • USB 为 ESP32-S3 原生 USB Serial/JTAG：Mac 免驱、免按 BOOT，直接 esptool 自动复位进入下载模式。
  • 本次端口 /dev/cu.usbmodem31301；arduino-cli board list 识别为 ESP32 Family Device，ioreg 中对应 "USB JTAG/serial debug unit"。
  • 电源按键逻辑：单击开机 / 双击关机、长按进下载模式——双击关机会让板子从 USB 上消失，这是本次掉线插曲的根因（见第 05 节）。

04 / FQBN 与编译参数

例程取自 M5Unified 库自带 Advanced 例程 Mic_FFT（24 kHz 采样、1024 点 FFT、四窗格显示），复制为独立工程 /Volumes/ssd/main_link/work/Mic_FFT。编译 FQBN：

esp32:esp32:esp32s3:PSRAM=opi,FlashSize=8M,PartitionScheme=default_8MB,CDCOnBoot=cdc
参数取值原因
PSRAMopiN8R8 的 PSRAM 是 8 MB Octal，必须选 opi 否则运行时堆分配失败
FlashSize8M板载 8 MB Flash
PartitionSchemedefault_8MB8 MB 分区表（3 MB APP / 1.5 MB SPIFFS）
CDCOnBootcdc走原生 USB CDC，Serial 即 USB 口日志（默认值是 Disabled）

编译一次通过：572,903 字节（17% APP 区），全局变量 25,944 字节（7% RAM），无需改任何例程代码。

05 / 烧录与 USB 掉线插曲

工程内固化了一键脚本 flash.sh：自动探测 /dev/cu.usbmodem* → 编译 → 烧录 → 抓 10 秒串口日志。

#!/bin/zsh  # flash.sh 核心三步
FQBN="esp32:esp32:esp32s3:PSRAM=opi,FlashSize=8M,PartitionScheme=default_8MB,CDCOnBoot=cdc"
PORT="$(ls /dev/cu.usbmodem* | head -1)"
arduino-cli compile -b "$FQBN"
arduino-cli upload   -b "$FQBN" -p "$PORT"

插曲：编译完成后板子从 USB 上消失

首次烧录时报 Could not open /dev/cu.usbmodem31301 ... No such file or directory。排查：ls /dev/cu.* 只剩蓝牙口；ioreg -p IOUSB 与 system_profiler SPUSBDataType 里 "USB JTAG/serial debug unit" 均已消失；轮询 30 秒无果——物理层掉线而非软件问题（烧录尚未开始，不存在固件改坏 USB 的可能）。最可能原因是 StickS3 被误触双击关机。

排查方法论：串口消失先分层——ls /dev/cu.* 看 macOS 枚举，ioreg/system_profiler 看 USB 物理设备。枚举和物理都没了就是线/板子的事，重插（黑屏则单击电源键开机）即可，不要在软件侧空转。

重新开机后执行 flash.sh：esptool v5.3.0 自动复位进入下载模式，573,056 字节压缩为 324,171 后 3.5 秒写完（1302 kbit/s），Hash 校验通过，RTS 硬复位生效。

06 / 验证方式与串口说明

烧录校验由 esptool 的 Verifying written data — Hash of data verified 保证；复位后程序即随开机自启。串口静默是正常现象：Mic_FFT 例程正常运行时不输出任何日志，仅在 M5.Mic.isEnabled() 失败时才打印 "microphone is not available."。板卡识别是否正确同样不用猜——若 M5Unified 认不出板子，麦克风初始化会失败并打出该错误。

上电后屏幕应为四窗格：顶部峰值频率读数（Hz，带三角标记）→ 绿色频谱柱状图 → 黄蓝瀑布图 → 底部白色实时波形。对麦克风说话/吹气，各窗格应实时起伏。
