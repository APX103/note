0. 结论先行（TL;DR）

1开发环境基本已经就绪

8 月做红外遥控器项目时装过的一套环境还在本机：arduino-cli 1.5.1（brew）、M5Stack 板包 m5stack:esp32 3.3.8（当前最新）、板包源 URL 也已配置。缺的只是库（M5Unified / M5GFX 都没了）和 sketch 目录（~/work/m5stack 下旧的 sketch 与打了补丁的 ESP32IRPulseKit 已被删除，只剩配置文件指向一个不存在的 sketchbook 路径）。

2烧录完全不依赖 ESP-IDF

arduino-cli upload 用的是板包自带的 esptool 5.2.0，不需要进 IDF 环境。反过来，烧预编译 merged bin 时用哪个 esptool 都行——包括 AMOLED 仓库 .local-tools 里 IDF 5.5.5 自带的那个，一条 write_flash 0x0 搞定。

3AirMouse 有现成固件，可直接烧

社区项目 Teapot174/AirMouseS3（GitHub，20★）就是"听说的那个 AirMouse"：BMI270 陀螺仪驱动的 BLE 空气鼠标，v1.0 release 提供预编译全量镜像 AirMouseS3.bin（0x0 起烧），M5Burner 里也收录了。想自己写/魔改，参考 tomokusaba/m5stack-ble-mouse（Qiita 有完整设计文，StickS3 专属，完成度最高）。

本笔记只做调研，没有烧录任何东西。动手前的第一条纪律（沿用 AMOLED 项目的习惯）：先把 StickS3 的 8MB 原厂全量备份下来再烧第三方固件，命令见第 7 节。

1. 硬件速查表

2. 官方开发方式与路线对比

官方 Arduino 教程（docs.m5stack.com/en/arduino/m5sticks3/program）的路径：Arduino IDE/CLI + M5Stack 板包 + M5Unified/M5GFX 库，例程用 ScrollGraph 验证。版本要求：板包 ≥ 3.2.5、M5Unified ≥ 0.2.12、M5GFX ≥ 0.2.18（本机板包 3.3.8 满足）。

路线适合备注
Arduino（arduino-cli）主力路线，社区案例最多本机环境已就绪；BLE HID（空鼠）、USB HID（Ducky 类）都有现成库
UIFlow2（MicroPython）图形化/快速原型出厂固件即 UIFlow2，M5Burner 可随时刷回
ESP-IDF想用 AMOLED 仓库那套工具链有社区 sample：ciniml/m5sticks3_idf_sample；对 StickS3 来没必要，Arduino 生态更全
ESPHome接 Home Assistantslochewie/M5StickS3-ESPHome、TitoTB/M5StickS3-ESPHome
ZephyrRTOS 玩家thc1006/zephyr-m5stack-sticks3（首个公开移植）

4. 编译 / 烧录 / 监视标准命令

4.1 三条主命令

编译 / 烧录 / 监视sh
FQBN="m5stack:esp32:m5stack_sticks3:PartitionScheme=default_8MB"
arduino-cli board list                          # 找端口，/dev/cu.usbmodem*

arduino-cli compile --fqbn $FQBN ~/work/m5stack/某sketch目录
arduino-cli upload  --fqbn $FQBN -p /dev/cu.usbmodemXXXX ~/work/m5stack/某sketch目录
arduino-cli monitor -p /dev/cu.usbmodemXXXX --config baudrate=115200

4.2 下载模式（官方方法）

板子正常会自动进下载模式；连不上时手动进入：按住侧边 RESET 约 2 秒，看到板内绿色 LED 闪烁后松开，再接 USB 烧录。

4.3 板级编译选项（板包 3.3.8 实测）

  • USB Mode：默认 Hardware CDC and JTAG；要做 USB HID（USB 鼠标/键盘，免蓝牙）时选 USBMode=default（USB-OTG / TinyUSB）+ Adafruit_TinyUSB 库。
  • PartitionScheme：8MB flash，默认 default_8MB 即可（8 月项目同款）。
  • UploadSpeed 默认 921600。

4.4 8 月沉淀的坑（仍然有效）

  • "port busy" → 串口监视器没退干净，lsof /dev/cu.usbmodemXXXX 杀残留进程。
  • 端口名会变（usbmodem1101 ↔ usbmodem101），每次烧前 board list 确认。
  • 板载外设供电：M5.Power.setExtOutput(true, m5::ext_none)（IR 等外设需要）；用 IR 接收时 M5.Speaker.end() 防干扰。

5. 与已有 ESP-IDF（AMOLED 仓库）的关系

用户直觉是"arduino-cli 烧录 + 复用已下载的 IDF"。调研结论：两者解耦更好用。

场景用什么说明
编译/烧录自己写的 Arduino sketcharduino-cli 全包板包自带 esptool 5.2.0 + xtensa 工具链，IDF 完全不参与
烧预编译 merged bin（如 AirMouseS3.bin）任一 esptool板包的 ~/Library/Arduino15/packages/m5stack/tools/esptool_py/5.2.0-cn/esptool，或 AMOLED 仓库 ./scripts/idf.sh 环境里的 python -m esptool（IDF 5.5.5）——效果一样
ESP-IDF 原生开发 StickS3可选有 ciniml/m5sticks3_idf_sample 可起步，但 Arduino 生态对这块板友好得多，不推荐
烧 merged bin 的通用命令（两种 esptool 二选一）sh
# 方式 A：板包自带 esptool
~/Library/Arduino15/packages/m5stack/tools/esptool_py/5.2.0-cn/esptool \
  --chip esp32s3 -p /dev/cu.usbmodemXXXX -b 921600 write_flash 0x0 固件.bin

# 方式 B：借用 AMOLED 仓库的 IDF（.local-tools）python 环境
~/work/ESP32-S3-Touch-AMOLED-1.8/.local-tools/espressif/python_env/idf5.5_py3.11_env/bin/python \
  -m esptool --chip esp32s3 -p /dev/cu.usbmodemXXXX -b 921600 write_flash 0x0 固件.bin
merged bin 是"bootloader + 分区表 + 应用"的 0x0 起全量镜像，和 AMOLED 板恢复出厂镜像的烧法一模一样，肌肉记忆直接复用。

6. 社区可直烧固件盘点

6.1 AirMouse（空气鼠标）—— 两个层次的选择

项目方式特点

7. AirMouse 直烧方案（第一次操作的建议步骤）

1先备份原厂 8MB（纪律）
全量备份 + 校验sh
~/Library/Arduino15/packages/m5stack/tools/esptool_py/5.2.0-cn/esptool \
  --chip esp32s3 -p /dev/cu.usbmodemXXXX -b 921600 \
  read_flash 0 0x800000 sticks3-factory-backup.bin
shasum -a 256 sticks3-factory-backup.bin   # 记下哈希，和 AMOLED 板同款习惯
2下载并烧录 AirMouseS3 v1.0
直烧sh
curl -LO https://github.com/Teapot174/AirMouseS3/releases/download/v1.0/AirMouseS3.bin
~/Library/Arduino15/packages/m5stack/tools/esptool_py/5.2.0-cn/esptool \
  --chip esp32s3 -p /dev/cu.usbmodemXXXX -b 921600 write_flash 0x0 AirMouseS3.bin
3使用

电脑蓝牙搜索并连接 AirMouse 热点 → 手持 StickS3 移动 = 移动光标；A 键左键，B 键冻结光标（漂了就按 B 稳住再动）。烧录不顺时：按住侧边 RESET ~2 秒，绿 LED 闪时松开，手动进下载模式。

4不满意时的升级路径

手感/功能想改（如滚轮、中键、防抖策略）→ 直接读 tomokusaba 的源码 + Qiita 设计文，按需移植成 arduino-cli sketch（BLE 层用 T-vK/ESP32-BLE-Mouse 库），BMI270 数据从 M5.Imu.getImuData() 取。

风险很低：随时可以用第 1 步的备份 write_flash 0x0 恢复出厂（UIFlow2），或者用 M5Burner 重刷任意官方固件。
