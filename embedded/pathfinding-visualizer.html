这五个算法其实是同一个算法

把 BFS、Dijkstra、贪心最佳优先、A* 摆在一起会发现,它们共享同一副骨架:维护一个优先队列,反复「取出当前最好的点,松弛它的邻居」。全部区别只在一句问答——什么叫"最好",也就是优先级函数 f:

算法优先级最短路径?行为特征
BFS先进先出仅在无权图只数格子,完全无视边权,踩着沼泽也照走
Dijkstraf = g(已走代价)✔(非负权)不知道目标在哪,向四面八方均匀扩散成圆形波前
贪心最佳优先f = h(离目标估计)✘一头冲向目标,撞进沼泽或死胡同就绕大弯
A*f = g + h✔(h 不高估时)有方向感的 Dijkstra,波前是被目标拉长的椭圆
加权 A*f = g + ε·h(ε>1)✘(代价 ≤ 最优 ×ε)拿最优性换速度,工程里调 ε 的常规操作

其中 g 是从起点走到这里的真实代价,h 是到目标的估计(启发函数)。由此有一个关键推论:A* 是超集——把 h 恒置 0,A* 就退化成 Dijkstra;边权全为 1 时,它又和 BFS 等价。所以工程上只需要实现 A* 一个,后两者都是它的特例。这也是「为什么我只见过 A*」的第一层答案:Dijkstra 没有消失,它被合并进 A* 里了。

动画里盯住三件事:Dijkstra 的已探索区域是以起点为圆心的同心圆(每个方向都同样有希望,适合"一站算出到所有地方的距离");A* 的探索区域是朝目标拉长的椭圆(启发函数像指南针,把算力花在有用的方向上);贪心的探索区域是一根细长的线(快,但路径经常不是最短,铺开沼泽试一试就现形)。

为什么机器人寻路的世界里只剩 A*
  • 代价地图天然非负。占据栅格 / costmap 里,边的代价 = 距离 × 地形系数,永远是正数。Bellman-Ford 和 Floyd-Warshall 存在的理由(负权边、全源最短路)在物理世界里根本不出现,自然一辈子碰不到。
  • 任务是点到点。机器人导航几乎总是"从这里到那个目标",而不是"到所有地方"。Dijkstra 的全向扩散在这个任务里就是纯粹的浪费——同样的地图,A* 访问的格子常常少一个数量级。
  • 启发函数是白送的。栅格分辨率已知,欧氏 / 曼哈顿距离就是一个绝不高估(admissible)的 h,最优性自动保住;换算成物理距离即可,零成本。
  • 嵌入式算力是刚需约束。访问节点少一个数量级 = 重规划频率高一个数量级,对动态避障是硬指标。

而且你在机器人代码里实际遇到的大多是 A* 的变体家族,认出它们就够了:

  • Hybrid A*:状态带上连续坐标和朝向,考虑车辆运动学(车不能原地转),DARPA 城市挑战赛经典,泊车规划标配;
  • D* / D* Lite:环境变化时增量重规划而不是从头再搜——火星车路径规划用的就是它;
  • JPS(Jump Point Search):均匀网格上剪掉对称路径,同结果快一个数量级;
  • Theta*:路径点之间做视线检查,走出任意角直线而不是锯齿;
  • RRT / RRT* / PRM:机械臂那种几十维的位形空间,栅格会维度爆炸,改用随机采样建树/建图。注意 PRM 建好 roadmap 图之后,图上查询最短路用的仍然是 Dijkstra / A*——Dijkstra 没退场,它躲在这些算法的底层;
  • ROS 2 Nav2 的默认规划器 Smac Planner(A* 家族)就是上面这套工程化落地的例子。
负权边:一条机器人工程师可以不背的冷知识

Dijkstra「取出即敲定」的贪心前提依赖非负权:一旦出现负权边,绕远路可能更便宜,先敲定的距离就是错的(而且是悄悄错掉,不报错)。这时要换 Bellman-Ford(O(V·E),还能检测负环)或先做 Johnson 重标记。复杂度速查:

算法复杂度适用
BFSO(V+E)无权图单源
Dijkstra(二叉堆)O((V+E)·log V)非负权单源;稠密图用朴素 O(V²) 反而快
A*≤ Dijkstra,取决于 h 的质量非负权 + 单目标 + 可用的启发函数
Bellman-FordO(V·E)有负权边,可检测负环
Floyd-WarshallO(V³)全源最短路(所有点对)
