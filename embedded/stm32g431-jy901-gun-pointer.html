1. 目标与最终形态

做一个"电子教鞭/玩具枪空中鼠标":IMU 装在枪头,枪口指向映射为鼠标光标(或 FPS 游戏视角)移动。交互设计:

操作效果
转动枪头光标绝对跟随:枪转多少度,视角转多少度(默认增益 60 count/度)
回正枪头光标精确回到原位(闭环记账,无累积误差)
按住 KEY(PC13)离合:视角冻结,枪随便挪——等于"抬起鼠标换个位置"
松开 KEY无缝衔接,当前枪姿成为新参考点 → 无限旋转
快速点按 KEY(<0.3s)鼠标左键(开火)
按住 KEY ≥5s 后松开进入磁校准模式(LED 快闪),画 8 字 15 秒,再点按一下结束并保存到模块 Flash

USB 枚举为 "USB Optical Mouse"(VID 0x0483 / PID 0x5710,标准 HID 启动协议鼠标,4 字节报告 [buttons, dx, dy, wheel])。注意:是有意的通用鼠标身份,不是克隆任何具体厂商的 VID/PID。

2. 硬件清单与接线

2.1 物料

  • WeAct STM32G431 CoreBoard(STM32G431CBU6,QFN48,Cortex-M4 170MHz,128K Flash/32K SRAM)——板载 LED=PC6,用户按键 KEY=PC13,BOOT0 键=PB8,8MHz HSE 晶振
  • 维特智能 JY901L 九轴姿态模块(片内卡尔曼融合,直接输出角度)——最终方案
  • GY-ICM20948V2(ICM-20948 裸九轴)——方案一,已弃用(原因见第 5 节)
  • ST-Link V2(SWD 烧录/调试),USB-C 数据线(必须带数据芯)

2.2 接线(JY901L 与 ICM-20948 通用同一组引脚)

传感器模块WeAct G431 排针说明
VCC3V3两个模块都支持 3.3V
GNDGND
SCLPA15(丝印 A15,内排)I2C1_SCL, AF4
SDAPB7(丝印 B7,外排)I2C1_SDA, AF4
G431 的 I2C 引脚坑(查 DS12589 复用表确认):PB6 在 G431 上不是 I2C1_SCL(和 F1/F4 不一样),PB8/PB9 虽然可以是 I2C1 但 PB8 兼 BOOT0。最终选 PA15+PB7,干净无占用。JY901L 的 I2C 是开漏输出,官方要求 4.7kΩ 外部上拉;实测 STM32 内部 40k 弱上拉在 87kHz 短线下可用,升 400kHz 或长线时务必补外部上拉电阻。

3. macOS 工具链:Keil 工程转 GCC

官方仓库的例程全是 Keil MDK-ARM 工程,macOS 没法用。转换方法(每个例程通用):

  1. 工具链:用 xpack 发行版(arm-none-eabi-gcc 15.2.1)。brew 装的 arm-none-eabi-gcc 不带 newlib,编译任何 stdint.h 代码直接报 cannot find crt0.o——这是已知坑,别用 brew 版。
  2. GCC 启动文件:从 ST 官方 cmsis-device-g4 仓库取 Source/Templates/gcc/startup_stm32g431xx.s(Keil 自带的 .s 是 ARM 汇编语法,GCC 不认)。
  3. 链接脚本:手写 STM32G431CBTx_FLASH.ld(Flash 128K @ 0x08000000,SRAM 32K @ 0x20000000)。
  4. Makefile:源文件清单直接从 .uvprojx 里 grep 出来逐个对齐,保证与 Keil 工程一个不差。
# 烧录 + 校验 + 复位(OpenOCD)
openocd -s /opt/homebrew/share/openocd/scripts \
  -f interface/stlink.cfg -f target/stm32g4x.cfg \
  -c "adapter speed 4000" \
  -c "program build/xxx.elf verify reset exit"

# USB DFU 备用通道(按住 BOOT0 → 点 NRST → 松开 BOOT0)
dfu-util -a 0 -s 0x08000000:leave -D build/xxx.bin
DFU 的 :leave 在 G4 bootloader 上会报 "Error during download get_status",是良性提示,固件其实已烧好,按一下 NRST 即可运行。

4. I2C 远程诊断方法学(无示波器)

这次最有价值的方法论:传感器"扫不到"时,不用示波器,用 SWD 读 GPIO 输入寄存器做电气层诊断。

4.1 上拉/下拉试探法

把引脚临时切成输入模式,分别挂内部上拉(40kΩ)和下拉,读 IDR:

上拉读值下拉读值结论
高低悬空(线没接通/断芯)
低低外部硬拉低(短路到 GND,或对端模块没上电——ESD 二极管把信号钳到 0)
高高外部强上拉(模块已供电,板上拉电阻生效)

GPIOB IDR 地址 0x48000410,GPIOA 是 0x48000010。这次实战结果:SCL 线硬低 + SDA 线悬空 → 定位为杜邦线断芯,换线即解决。

4.2 I2C 总线挂死恢复

MCU 在 I2C 传输中途复位,从机可能攥住 SDA 不放(挂死)。恢复方法:固件里先把 SCL 切 GPIO 开漏输出,打 9~16 个时钟脉冲直到 SDA 释放,再补一个 STOP 条件,然后才初始化 I2C 外设。09 工程已实现(I2C1_BusRecovery())。

4.3 验证脚本

符号地址用 arm-none-eabi-nm 从 elf 提取,OpenOCD mdw 读内存,mww 写变量(可在线改运行参数,如灵敏度、轴模式)。注意:重新编译后符号地址会偏移,必须重新取地址;OpenOCD 的 mdw 输出在 stderr,管道处理要 2>&1。

5. 方案一:ICM-20948 自研融合(教训记录)

第一版用 GY-ICM20948V2(I2C 地址 0x68,WHO_AM_I=0xEA),自己跑姿态融合,USB CDC 输出四元数+欧拉角(200Hz,逗号分隔)。这一步走通了,但最终弃用,教训如下。

5.1 三算法同实现,按键轮切对比

算法本质特点
Madgwick梯度下降修正四元数单增益 β=0.1 好调,收敛快;无零偏估计
MahonyPI 反馈(比例+积分)Ki 积分项自动学出陀螺零偏;稳态下等价于零偏的 Kalman 估计
2 态 Kalman逐轴 [角度, 零偏] 状态估计roll/pitch 用加速度做观测;yaw 只能陀螺积分+磁力计互补

5.2 零偏校准两层防御

  • 开机校准:静止 3 秒采 600 样本求均值;带静止校验(偏离均值 >1dps 就重采)
  • ZRU 零偏在线学习:关键设计是看"信号恒定程度"而不是"绝对值"——对原始陀螺做慢均值(τ≈1.2s),偏差 <1.5dps 且 |加速度|≈1g 持续 2s 判静止,首次判静止时快照式锁定(bias=g_avg,光标立刻停),持续静止时慢速跟踪(α=0.01)。这样即使零偏漂到很大也能重新锁定。

5.3 弃用原因

GY 模块的 ICM-20948 是 B 级芯片:陀螺 Z 轴静止零偏高达 21.7 dps(良品应 <1 dps),且零偏随温度/时间游走(两次校准测得 21.7 → 25.3 dps)。再好的算法也救不了这个硬件底子。这也是"PS 手柄 6 轴不漂"的真相之一:消费级大厂用筛选过的良品 + 运行时持续零偏学习 + 游戏层回中兜底,三件套缺一不可。

另一个收获:ICM-20948 内部磁力计 AK09916 不直接挂总线,要开 bypass 模式(INT_PIN_CFG=0x02)后以 0x0C 地址直读,或配内部 I2C 主机搬到 EXT_SENS_DATA 寄存器。

6. 方案二:JY901L 片内融合(正解)

JY901L 片内跑动态卡尔曼,直接输出融合好的 roll/pitch/yaw/角速度/四元数,陀螺静止零漂 ±0.5~1 dps(比 GY 模块好 20 倍以上)。我们只剩"读寄存器+映射"两件事。

  • I2C 地址 0x50,上电启动时间约 1000ms(固件里要先 delay 再配置)
  • 默认回传速率只有 10Hz,必须写 RRATE 寄存器(0x03)= 0x0B 提到 200Hz
  • 陀螺输出有"静止自动归零"特性(低于阈值输出精确 0)——防漂移设计,别误以为是坏了
  • 航向角是 9 轴磁融合,磁场校准前 yaw 可能游走,校准后稳定

7. JY901L 数据格式与寄存器全表(实测验证)

I2C 寄存器读:标准 HAL_I2C_Mem_Read,8 位寄存器地址,返回小端 int16。实测 dump 0x30~0x5A 验证:

寄存器内容换算实测验证
0x00SAVE(写 0x0000 保存配置到 Flash)—
0x01CALSW 校准0x0001=加计校准; 0x0007=磁校准开始; 0x0000=结束
0x03RRATE 回传速率0x06=10Hz(默认), 0x0B=200Hz✅
0x34~0x36加速度 AX/AY/AZraw/32768×16 = g✅ 静止 AZ=1.0005g
0x37~0x39角速度 GX/GY/GZraw/32768×2000 = °/s✅(静止时输出精确 0 是特性)
0x3A~0x3C磁场 HX/HY/HZ原始值✅
0x3D~0x3F姿态角 Roll/Pitch/Yawraw/32768×180 = 度✅ 范围 X:±180 Y:±90 Z:±180
0x51~0x54四元数 q0~q3raw/32768(备用,指向向量法用)

UART 模式(备选,本项目未用):默认 9600 波特率,0x55 帧头连续输出,可接 USART2(PA2/PA3)。

8. 校准:加计/磁/静止验收数据

8.1 校准流程(全部可通过 I2C 命令在板完成,无需上位机)

  1. 加速度校准:模块水平静置 → 写 CALSW=0x0001 → 等 5 秒 → 写 CALSW=0x0000 结束 → 写 SAVE=0x0000 保存
  2. 磁校准:写 CALSW=0x0007 → 拿起模块画 8 字翻转 15 秒 → 写 CALSW=0x0000 结束 → SAVE 保存。09 固件里已做成"长按 KEY 5 秒进入,点按结束"
  3. 陀螺零偏:JY901L 上电自动校准(静止即可)

8.2 静止验收(60 秒,加计校准后)

轴起始60s 后漂移
yaw97.10°97.10°0.00°
pitch0.32°0.35°0.03°
roll-2.31°-2.32°0.01°

验收标准:完全静止 = 输出纹丝不动。达标。

9. USB HID 鼠标实现与坑

9.1 时钟

G431 的 USB 要 48MHz:HSE 8MHz → PLLM/2 → PLLN×72 → VCO 288MHz → PLLQ/6 = 48MHz 供 USB,PLLR/2 = 144MHz 主频。USB 引脚 PA11/PA12 直出 Type-C,无需 GPIO 配置。

9.2 踩过的坑

  • ST USB Device Library 版本匹配:CubeG4 v1.5 自带 core 是旧 API,CDC/HID 类层必须用 v2.9.0;v2.10+ 引入 pClassDataCmsit/classId 字段,直接编译不过。
  • nano.specs 的 printf 默认不带浮点:%f 输出空白,链接加 -Wl,-u,_printf_float,并补齐 newlib 桩(_sbrk/_write/_read/_close/_lseek/_isatty/_fstat/_kill/_getpid/_exit)。
  • HID 报告要攒着发:主机轮询 100Hz(bInterval=10ms)而固件产 200Hz,USBD_HID_SendReport 返回 BUSY 时位移要保留累加,否则丢一半位移。
  • 未连接主机时位移积压要封顶(±500 count),否则重连瞬间光标暴跳。
  • HID 报告格式(启动协议鼠标):[buttons, dx, dy, wheel] 4 字节,int8 相对位移 -127~127。ST 的 usbd_hid.c 自带标准鼠标报告描述符,不用自己写。

10. 绝对映射算法:闭环/离合/无限旋转

10.1 核心:用相对鼠标 API 实现绝对定位

鼠标只能发相对位移,所以固件自己记账维护"镜头位置估计",每帧只发"还差多少":

每帧 (200Hz):
  off_yaw = yaw_unwrapped - yaw_lock        // 当前枪姿相对锁定姿态的偏移(度)
  target  = -sens × off_yaw                  // 目标镜头位置(count), 符号实测校准
  dx      = round(target - cam_x_est)        // 差多少发多少
  cam_x_est += dx_sent                       // 发出去的记账

闭环的妙处:量化误差、丢帧、任何扰动自动校正,整条链路没有自由积分器 → 原理性免疫积分漂移。FOV 60° 的游戏里 sens≈60 时,枪转 30° ≈ 镜头扫满屏。

10.2 离合(抬鼠换位)与无限旋转

按住 KEY:  冻结, 不发位移, 累积器清零(防松手跳变)
松开 KEY:  yaw_lock = yaw_now - cam_x_est / sens
           → 镜头位置不变(无缝), 当前枪姿成为新参考

游戏里转身 180° 后手扭到极限 → 按住 KEY 把枪放回舒适位 → 松开继续,视角纹丝不动。这就是无限旋转。

10.3 按键状态机(单键三功能+磁校准)

动作判定功能
点按 <0.3s松开时 press_cnt<60 帧左键(发按下+松开两帧报告)
按住press_cnt>0离合冻结
按住 ≥5s 后松开press_cnt≥1000 帧进入磁校准(LED 快闪),再点按结束+保存

11. 三个边界问题:回卷/漂移/万向节锁

11.1 yaw ±180° 回卷跳变(已修)

症状:拖到某些位置光标突然从一边飞到另一边。根因:yaw 量程 ±180°,跨界瞬间偏移量跳 360°,闭环把它当巨大反向位移修正。修法:对 yaw/roll 做连续展开(unwrap)——每帧把增量 wrap 到 ±180 再累加,展开域里永不回卷:

yaw_u += wrap180(yaw - yaw_prev);  yaw_prev = yaw;

11.2 Z 轴(yaw)漂移的正确认知

roll/pitch 有重力做绝对锚,永不漂移,也不被 yaw 漂移传染;yaw 没有重力参考,只能靠磁力计。处理:磁校准(一次性)+ 离合随手重锁(使用习惯)+ axis_mode 可切换。

固件留了 axis_mode 全局变量(SWD 可在线改):0=yaw/pitch(磁融合),1=roll/pitch(纯重力锚定,物理零漂移,代价是左右改侧倾手势)。

11.3 万向节锁(极点保护,已修)

枪口接近正上/正下(pitch≈±90°)时欧拉角退化,yaw/roll 瞬间互换身份跳 180° → 光标方向翻转。修法:|pitch|>80° 时冻结水平轴输出,离开极点区域无缝恢复。终极方案是四元数指向向量映射(JY901L 的 0x51~0x54 直接出四元数),需要时再上。

13. 复现手册

# 仓库: WeActStudio.STM32G431CoreBoard, 分支 gunpointer-v1
# 工具链: xpack arm-none-eabi-gcc 15.2.1 (Makefile 里 TOOLCHAIN 变量指到 bin 目录)

cd Examples/09-GunPointer/GCC
make          # 编译
make flash    # ST-Link 烧录+校验+复位
make dfu      # 备用: USB DFU 烧录 (按住 BOOT0 点 NRST 进入)

# 使用
# 1. 插 Type-C 到电脑, 枚举为 "USB Optical Mouse"
# 2. 枪口指向屏幕, 松开状态下即绝对跟随
# 3. 按住 KEY = 冻结视角换位; 点按 = 左键; 长按 5s = 磁校准模式

# 工程谱系
# 01-Blink      GCC 工具链最小验证 (LED PC6 闪烁)
# 05-I2C_Scan   I2C 总线扫描器 (接新传感器先烧它)
# 06-Attitude   ICM-20948 三算法姿态融合 + USB CDC 输出 (弃用但可玩)
# 07-AirMouse   ICM-20948 角速度->HID 鼠标 (弃用)
# 08-JY901      JY901L 读取/格式验证/校准命令测试
# 09-GunPointer 最终版: JY901L 绝对映射 HID 鼠标

# 在线调参 (无需重编译)
openocd ... -c init -c halt \
  -c "mww <sens 地址> 0x42C80000" ...   # sens=float, 需先 nm 取地址

关键调参变量(arm-none-eabi-nm build/09-GunPointer.elf 取地址):sens(灵敏度 count/度,当前 60)、axis_mode(0=yaw 1=roll)、dbg_angle/dbg_lock/dbg_cam(观测)。
