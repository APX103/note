工具链搭建（macOS）

在 Mac 上给 STM32 编译烧录的全部装备，以及一个 Homebrew 的经典坑。

3.1 需要装什么

工具安装说明
OpenOCD（含 ST-Link 支持）brew install openocd烧录 + SWD 调试 + 内存读写，全程核心工具
arm-none-eabi-gcc（含 newlib）xpack 发行版（见 3.3）交叉编译器
Python 3 + PyMuPDF + Pillowpip3 install --user pymupdf pillow原理图提取、寄存器表生成、帧转 PNG

macOS 不需要装 ST-Link 驱动（usbhid 原生可用）。验证 ST-Link 已连上：

ioreg -p IOUSB -w 0 | grep -i stlink    # 应看到 STM32 STLink

3.2 坑：Homebrew 的 arm-gcc 没有 C 库

brew install arm-none-eabi-gcc 装的编译器不带 newlib，编译任何用到 stdint.h 的代码直接报 fatal error: stdint.h: No such file or directory。这是本教程踩过的第一个环境坑，且 brew 里没有对应的 newlib 包。

3.3 正解：xpack GNU Arm 工具链

xPack 的发行版自带 newlib，一个 tarball 解决：

# 查最新版（示例为 15.2.1，Apple Silicon 用 darwin-arm64）
curl -sL https://api.github.com/repos/xpack-dev-tools/arm-none-eabi-gcc-xpack/releases/latest \
  | grep browser_download_url | grep darwin-arm64

curl -sL -o xpack-gcc.tar.gz "<上面的 url>"
tar xzf xpack-gcc.tar.gz
# 解压出 xpack-arm-none-eabi-gcc-<ver>/，bin/ 下即完整工具链

Makefile 里直接写绝对路径引用（也可以 symlink 到 /usr/local/bin）。

3.4 烧录与验证三板斧

# 烧录 + 校验 + 复位运行（一行搞定）
openocd -s /opt/homebrew/share/openocd/scripts \
  -f interface/stlink.cfg -f target/stm32h7x.cfg \
  -c "adapter speed 4000" \
  -c "program build/camera_lcd.elf verify reset exit"

# 读内存（例：看状态结构）
openocd -s /opt/homebrew/share/openocd/scripts \
  -f interface/stlink.cfg -f target/stm32h7x.cfg \
  -c "adapter speed 4000" -c init -c halt \
  -c "mdw 0x2400039c 10" -c resume -c shutdown

# 转储一段内存到文件（例：帧缓冲）
... -c "dump_image /tmp/frame.bin 0x24040020 17280" -c resume -c shutdown
H7 的双 Bank flash、2048K 容量 OpenOCD 0.12 都能自动识别。adapter speed 4000 把 SWD 拉到 4 MHz，dump 一帧 17 KB 只要 ~0.1 秒。

3.5 Windows 用户

原厂三个 Demo 是 Keil MDK 工程，Windows + MDK-ARM 直接开箱即用（装 STM32H7 DFP 和 ST-Link 驱动即可）。本教程的 GCC 工程在 Windows 上可用 xpack Windows 版 + OpenOCD 或 STM32CubeProgrammer 等价替换，命令语义一致。
