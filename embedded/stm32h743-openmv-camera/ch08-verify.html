STM32H743 摄像头完全教程 / 第 8 章

远程验证方法学

没有示波器、不看串口，只靠 ST-Link 把嵌入式调试做成可重复的实验科学。

整个项目没有用示波器，串口也一行没接——所有调试通过 ST-Link 完成。核心思想：在固件里预埋「SWD 窗口」，把嵌入式调试变成可重复的远程实验。

8.1 窗口一：状态结构（只读）

typedef struct {
    uint32_t magic;        // 0xCA4CA4CA，确认结构有效
    cam_sensor_t sensor;   // 识别结果
    int32_t chip_id; uint32_t slv_addr7; uint32_t xclk_hz;
    uint32_t frames;       // 已采集帧数（看它在涨=流水线活着）
    uint32_t dcmi_errors;  // DCMI 超限/错误中断计数
    uint32_t last_frame_ms, fps;
    int32_t init_err;      // 0=OK；负数=失败步骤
    char name[16];
} cam_status_t;              // 地址：arm-none-eabi-nm 查 g_cam_status
# 读一次状态
openocd ... -c init -c halt -c "mdw 0x2400039c 10" -c resume -c shutdown

烧完固件先读它：传感器识别没识别、错误码是什么、fps 多少——不需要看屏幕就能知道固件活得怎么样。

8.2 窗口二：调试控制字（读写）

volatile uint32_t dbg_ctrl;   // OpenOCD mww 写入，cam_capture 检测变化并应用

bit 0/1  强制 DCMI VSPOL 高/低      bit 8 + bits9..15  手动曝光探测(AEC关)
bit 2    强制 HSPOL 高               bit 16            白光照明 LED
bit 3    PCLK 下降沿采样             bit 5/6           传感器色彩顺序实验

改极性/曝光不用重烧固件——mww 一下、等一秒、dump 一帧看结果，一分钟跑一轮实验。这个「热调参」回路是快速收敛的关键。

8.3 帧取证：dump → PNG → 肉眼看

./tools/dump_frame.sh /tmp/f.bin            # 可选第二参数=先写 dbg_ctrl
python3 tools/frame2png.py /tmp/f.bin f.png 108 80 1   # (宽 高 字节偏移)

这一步之后，「我看到的就是摄像头看到的」——黑屏、颜色、噪声全部可以量化分析：

  • 唯一值计数：全帧 3~5 个唯一值 ≈ 没有真实图像；几十~上千 = 正常
  • luma 量化：RGB565 加权亮度均值，改一版测一次（100→130 这样对比）
  • 行列方差：区分「均匀噪声」和「有结构的暗」

8.4 彩条地标：颜色问题的裁决者

人眼报「颜色不对」时，开启传感器彩条（已知真值：白黄青绿品红蓝黑），dump 按位置取色对比。任何字节序/极性/通道错位在标准色序面前无所遁形。这是本项目最值的单个实验（第 7 章坑 3）。

8.5 帧活性检验

./dump_frame.sh /tmp/a.bin ; sleep 3 ; ./dump_frame.sh /tmp/b.bin
diff <(xxd /tmp/a.bin) <(xxd /tmp/b.bin) | head
陷阱：想在一条 openocd 命令里 dump 两次 + sleep——CPU 在两次之间是 halt 的，diff 必为 0，会被误判为「画面冻结」。必须两次独立会话（中间 resume）。

8.6 手动探针：曝光/增益扫描

dbg_ctrl 的手动曝光模式把 AEC 关掉，从 64 行扫到 8128 行曝光、1×~60× 增益，每档 dump 一帧看 luma 响应——用来区分「场景真的黑」和「模拟链路坏了」（正常链路对曝光/增益必须有单调响应）。

8.7 方法论总结

  1. 固件常驻两个窗口（状态结构 + 控制字），调试能力是设计出来的，不是临时加的
  2. 每个「不对劲」先找一个客观地标（彩条、标准色序、luma、帧间差）再动手
  3. 一次只动一个变量，改完立即 dump 验证
  4. 所有实验脚本化存档（tools/），可重复 = 可交给别人验证
