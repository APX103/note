1. 板子与仓库摸底

WeAct MiniSTM32H723 核心板,主控 STM32H723VGT6(LQFP100,Cortex-M7,1MB Flash + 564KB RAM)。板载资源:

  • 0.96″ ST7735 TFT(160×80,SPI4) — 本次主角
  • 8MB SPI Flash(W25Q64 / 新版 PY25Q64,SPI1)+ 8MB OSPI Flash(OSPI1)
  • MicroSD 卡槽、8bit DCMI 摄像头口、USB-C
  • 用户按键 K1 = PC13,用户 LED = PE3,另有 NRST / BOOT0 键
  • SWD 调试口(PA13/PA14,4pin 排针)

仓库 WeActStudio.MiniSTM32H723 提供 9 个 STM32CubeMX 例程(GPIO/LCD/SD/SPIFlash/ADC/DCMI/PWR 等),每个例程自带完整 HAL 库源码,但只有 Keil MDK-ARM 工程文件 — 没有 Makefile、没有 CMake、CMSIS Device 里连 GCC 启动文件都被裁掉了(Source/Templates 整个缺失,只剩 Include 头文件)。Doc/ 有全套数据手册,Hardware/ 有原理图 PDF。

时钟树(从例程反推):25MHz HSE → PLLM=2 / PLLN=44 / PLLP=1 → SYSCLK=550MHz,HCLK=275MHz(AHB /2),APB 均 137.5MHz。

2. STM32H723 芯片特性(摘自 DS13313,仓库 Doc/ 内有)

H723 是 STM32H7 产品线里的「高配性价比款」:与旗舰 H743 同频 550MHz,但封装更小、价格更低(H733 是同款的加密版,多 AES/HASH)。仓库这块板用的是 H723VGT6(LQFP100,1MB Flash)。

类别规格
内核Cortex-M7 @ 550MHz,双精度 FPU,32KB I-Cache + 32KB D-Cache(嵌入式 Flash 零等待执行),MPU,1177 DMIPS(2.14 DMIPS/MHz),DSP 指令集
存储1MB Flash(带 ECC,单 bank,编程粒度 256bit/32 字节);564KB SRAM 全带 ECC = 128KB DTCM + 432KB 系统 RAM(其中最多 256KB 可重映射为 ITCM)+ 4KB 备份 SRAM
外部存储FMC(SRAM/PSRAM/SDRAM/NOR/NAND,16bit 总线);2× OctoSPI 支持 XiP;2× SDMMC
图形Chrom-ART(DMA2D)图形加速器 + LTDC 控制器(支持到 XGA) — 芯片能力很强,但本板板载的是 SPI 口的 ST7735,LTDC 要外接 RGB 屏
模拟2× 16bit ADC(3.6MSPS,双交错 7.2MSPS)+ 1× 12bit ADC(5MSPS);2× 比较器;2× 运放(GBW 8MHz);2× 12bit DAC;DFSDM(8 通道/4 滤波器,接数字麦克风)

数学加速CORDIC(三角/双曲/开方硬件加速)+ FMAC(FIR/IIR 硬件滤波器)— 电机控制、音频 DSP 的利器
其他TRNG、CRC、RTC(亚秒级+硬件日历)、96bit UID、ROP/PC-ROP/防篡改;供电 1.62~3.6V,内嵌 LDO(本板即 LDO 供电),VOS0 档位才能跑满 550MHz
注意 RAM 是分域的:DTCM(0x20000000)CPU 零等待但 DMA 访问不到;AXI SRAM(0x24000000,320KB)是 DMA 可用的主力;D2 域 SRAM1/2/3、D3 域 SRAM4 各有总线归属。原厂固件栈顶在 0x2401xxxx(AXI SRAM),我们自己的 Makefile 链接脚本把 RAM 定在 DTCM — 两种都合法,但涉及 DMA 时必须想清楚 buffer 放哪。

3. 工具链:brew 的 arm-none-eabi-gcc 是残的

机器上已有 arm-none-eabi-gcc(brew, 16.2.0)、openocd、cmake。但第一次编译直接炸:

arm-none-eabi-gcc/16.2.0/include/stdint.h:11:16: fatal error: stdint.h: No such file or directory
   11 | # include_next <stdint.h>

Homebrew 的 arm-none-eabi-gcc formula 不捆绑 newlib(GCC 自带的 stdint.h 是个 include_next 包装,需要 libc 的真身),而 brew 里也没有任何 newlib 包可补 — 这条路是死的。

正解是 Arm 官方 GNU Toolchain for Arm Embedded(brew cask gcc-arm-embedded,15.3.rel1)。但 brew 下载 gitlab.arm.com 的包时被连接重置(网络环境问题)。绕法:

  1. 手动 curl -fL --retry 3 -C - 断点续传 267MB 的 .pkg(走 gitlab.arm.com → S3 302 跳转,~500KB/s,约 9 分钟);
  2. 免 sudo 解包:pkgutil --expand-full arm-gnu-toolchain.pkg out/,payload 直接展开成可用目录(Payload/bin/arm-none-eabi-gcc),不污染系统、不需要管理员密码;
  3. Makefile 里 PREFIX = ../toolchain/arm-gnu/Payload/bin/arm-none-eabi- 指过去即可。验证 newlib 头文件在 Payload/arm-none-eabi/include/ 下存在。

顺手 brew install dfu-util(0.11),给以后 USB DFU 烧录留路(按住 BOOT0 上电,USB-C 直连即可,不需要 ST-Link)。

4. ST-Link 上线与原厂固件备份

ST-Link(V2 兼容,固件 V2J43M28)USB 直识别(VID:PID 0483:3752),macOS 下可用 ioreg -p IOUSB 确认(system_profiler SPUSBDataType 这次什么都没吐出来,ioreg 更可靠)。

烧新程序前先备份 — 一条 openocd 命令把 1MB 内部 Flash 全量转储:

openocd -f interface/stlink.cfg -f target/stm32h7x.cfg \
  -c "init; halt; dump_image internal_flash_0x08000000_1MB.bin 0x08000000 0x100000; shutdown"

转储校验:向量表 SP=0x240142C0(AXI SRAM,说明原厂固件用 D1 域 RAM)、复位向量落在 Flash、实际固件约 118KB(尾部全 0xFF 裁剪估算)、SHA-256 存档。halt 时 pc=0x08013c78,说明出厂片子里确实有程序在跑(README 说好的"不提供出厂测试程序"呢 — 其实焊在板子里的那份是有的,只是不给源码和二进制文件)。

备份文件:work/weactstudio_h723/backup/internal_flash_0x08000000_1MB.bin。需要还原时 program 回去即可。

5. 01-GPIO:Keil 工程转 Makefile

原则:不改官方仓库任何文件,工程建在 work/weactstudio_h723/01-gpio/,Makefile 用相对路径只读引用 Examples/01-GPIO 的 Core/Bsp/Drivers 源码。缺的三样东西从 ST 官方仓库补齐:

  • GCC 启动文件 startup_stm32h723xx.s — 在 CMSIS Device 子模块仓库 STMicroelectronics/cmsis_device_h7 的 Source/Templates/gcc/(注意:STM32CubeH7 主仓里该目录是 submodule,raw 路径要换成子模块仓,直接打主仓路径会 404);
  • 链接脚本 STM32H723ZGTX_FLASH.ld — 从 STM32CubeH7 的 NUCLEO-H723ZG 模板拿(VG/ZG 都是 1MB Flash,内存映射一致;RAM 段用 DTCM 128K @ 0x20000000);
  • 配套的新版 system_stm32h7xx.c — 例程自带的旧版缺 ExitRun0Mode(新启动文件一上电就 bl 过去配置电源域),必须和启动文件同版本配对使用,否则链接报 undefined reference。

编译参数:-mcpu=cortex-m7 -mthumb -mfpu=fpv5-d16 -mfloat-abi=hard,定义 USE_HAL_DRIVER STM32H723xx。HAL 驱动直接整目录 Src/*.c 全编译(没用到的模块被 hal_conf.h 里的宏裁掉,链接器再 gc-sections 收尸)。烧录+校验:

openocd -f interface/stlink.cfg -f target/stm32h7x.cfg \
  -c "program build/weactstudio_h723_gpio.elf verify reset exit"

现象:LED(PE3)按硬件 RNG 随机间隔(0~600ms)闪烁,按住 K1 变成 200ms 规律翻转 — 第一个程序跑通。

6. LCD Demo:逆向 BSP 的关键事实

03-LCD_Test 例程的 BSP(Bsp/ST7735/)是"驱动 + 总线胶水"两层结构:st7735.c 是通用驱动(命令序列/光标/FillRect/FillRGBRect),lcd.c 负责把驱动挂到 SPI4 上。把例程读懂后,几个不写进代码就亮不起来的事实:

7. 五个特效的实现要点

K1 单击循环切换(按下-释放边沿 + 200ms 锁定防抖),切换后 2.5 秒内顶部压一条 n/5 名称 标题条,LED 300ms 心跳。

7.1 STARFIELD — 3D 星空穿梭

256 颗星,每颗 (x,y,z) ∈ [-1,1]×[-1,1]×(0,1],每帧 z -= 0.012,透视投影 sx = x/z·36 + 80。z 越小越亮(亮度映射 RGB565 灰阶)、越近画 2px。z 触底就在远处重生。

7.2 DOOM FIRE — 经典火焰

半分辨率 80×40 热量图 + 37 色黑→红→黄→白调色板,2×2 上采样。每帧从底行随机点火,向上传播时取下方邻域(带 ±1 横向漂移)减随机衰减。全部整数运算,xorshift32 伪随机。

7.3 BOUNCE — 重力弹球

18 个球,重力 0.18、落地反弹衰减 0.86、速度过低时随机"续命"一脚。拖尾实现:不清屏,每帧把全 fb 各通道右移 1 位((p>>1) & 0x7BEF,一行位运算压暗,比 memset 还便宜)。

7.4 LIFE — 康威生命游戏

80×40 网格(2px 细胞)、环面边界、双缓冲。存活数 < 12 或超过 800 代自动重新撒种,避免死在静寂态。

7.5 PLASMA — 等离子体

每像素四个正弦叠加(两个行/列行波 + 一个对角行波 + 一个圆心漂移的径向波),值域归一后过彩虹调色。正弦用 256 项查表(启动时 sinf 预生成),12800 像素 × 4 查表在 550MHz M7 上毫无压力。

8. 踩坑清单

  1. brew arm-none-eabi-gcc 无 newlib — include_next <stdint.h> 找不到真身。别再试 brew 补包,直接上 Arm 官方工具链。
  2. gitlab.arm.com 下载被重置 — brew 装 cask 失败;手动 curl 带 -C - 断点续传可过。
  3. pkg 免安装 — pkgutil --expand-full 直接展开成目录用,不用 sudo、不写系统路径。
  4. STM32CubeH7 的 CMSIS Device 是 submodule — raw 文件要去 cmsis_device_h7 仓拿。
  5. 启动文件与 system 文件版本要配对 — 新版 startup 依赖 ExitRun0Mode,旧 system_stm32h7xx.c 没有。
  6. GCC 14+ 把 int-conversion 提升为错误 — 厂商 BSP 里 NULL 初始化整型字段在 Keil 下无事,GCC15 下报错;-Wno-int-conversion 放行(不改编译不动的厂商文件)。
  7. Makefile vpath 同名碰撞 — 自己的 src/main.c 和例程 Core/Src/main.c 经 notdir 后同名,sort 后例程目录排在前面,vpath 抢走了 main.c,链接时报一堆 MX_RTC_Init undefined 才暴露。自己的入口改名 app_main.c 解决。
  8. TFT96 宏的藏身之处 — 面板选型宏不在任何源码里,在 Keil uvprojx 的 Define 字段。移植工程时记得去 .uvprojx 里翻编译定义。

9. 上 RTOS 之后的注意细节

这颗芯片的 RTOS 生态相当全:FreeRTOS(STM32CubeH7 官方自带 NUCLEO-H723ZG 例程)、ThreadX/Azure RTOS(ST 官方 X-CUBE-AZRTOS-H7 支持)、Zephyr(官方 nucleo_h723zg 板级支持)、RT-Thread(主线 BSP stm32h723-st-nucleo,官方精简 BSP 清单里被评为「维护较好」)、MicroPython 1.20+(加了 STM32H723 与 NUCLEO_H723ZG 板)、rustBoot(安全启动/OTA 支持 stm32h723)。以 FreeRTOS 为例,H7 平台有几个和 F4 时代不一样的坑:

9.1 Cache × DMA 一致性(最大的坑)

开 D-Cache 后 CPU 看到的内存和 DMA 看到的会不一致。规则:DMA 缓冲区要么放进 MPU 配置的 non-cacheable 区域,要么显式维护 — 发送前 SCB_CleanDCache_by_Addr(),接收后 SCB_InvalidateDCache_by_Addr(),且地址和长度都要 32 字节对齐。RTOS 下驱动代码分散在多个任务里,漏一处就是偶发灵异 bug(SD 卡偶发 CRC 错、以太网偶发丢包大多是这个)。

9.2 内存域摆放

  • DTCM(0x20000000, 128KB):CPU 零等待,但 DMA 完全访问不到。FreeRTOS heap 别放这;任务栈放这里最快,但栈上局部 buffer 绝不能直接交给 DMA。
  • AXI SRAM(0x24000000, 320KB):DMA 可达,性能次之,放 heap 和 DMA buffer 的主力。
  • D2 域 SRAM1/2/3、D3 域 SRAM4:部分外设 DMA(如 BDMA 只能碰 D3)有域限制,分配时留心。
  • 链接脚本里把段拆开管理,配合 MPU 给 DMA 区开 non-cacheable,是最省心的结构。

9.3 HAL 时基与中断优先级

  • HAL 默认用 SysTick 当时基,FreeRTOS 也用 SysTick — 冲突。CubeMX 标准做法:SYS → Timebase Source 改成 TIM6 给 HAL,SysTick 留给 RTOS。
  • H7 中断优先级只有 4bit(16 级)。HAL 约定 NVIC_PRIORITYGROUP_4;FreeRTOS 的 configMAX_SYSCALL_INTERRUPT_PRIORITY(默认 5)以下的中断才能调 FromISR API,高于它的 ISR 连 RTOS 都不能碰(但也因此零延迟,适合放最硬的实时中断)。

9.4 其他

  • Cache 默认没开:厂商模板的 SystemInit 不自动开 I/D-Cache,550MHz 不开 cache 等于白买(我们上面的 demo 就没开,还有大把性能余量)。RTOS 工程启动早期 SCB_EnableICache()/SCB_EnableDCache(),并先把 MPU 区域规划好。
  • FPU 上下文:编译 -mfloat-abi=hard,FreeRTOS 用 GCC/ARM_CM7/r0p1 port(自动惰性保存 FPU 寄存器),别用 CM4F port 混。
  • Flash 编程粒度 256bit(32 字节) 且 H723VG 是单 bank:EEPROM 模拟、参数落盘、IAP/OTA 都不能像 F4 那样随手写字;OTA 没有双 bank 可换,但可以利用本板的 OSPI Flash XiP(代码跑在外部 Flash,内部 Flash 做升级缓冲,参考 01-GPIO_ExternalFlash_Run 例程),或者直接上 rustBoot。
  • 看门狗:多任务下建议单独低优先级任务喂 IWDG + 各任务心跳登记,谁卡死不喂谁。
  • CORDIC/FMAC 不是线程安全的共享资源:多任务用时加互斥锁,或者约定归一个 DSP 任务专用。

本板的边界也要清楚:屏幕是 SPI 小屏不是 LTDC 大屏;USB 片上只有 FS PHY(12Mbps),HS 要外接 ULPI PHY;没有无线(要 Wi-Fi 得外挂 ESP32 当网卡,或者用 SPI 网卡)。纯练手的话,从「相机取景 + 热成像 + 频谱仪」这类一块板就能玩的开始;要做正经项目,CAN 分析仪和 FOC 是这颗芯片相对同价位 MCU 最有差异化优势的两个方向。

# 恢复原厂固件
