0 · 结论速览

能拿到，拿到了，而且验证过了。这套上位机是 C#/.NET 写的、无混淆、类名清晰， 姿态解算算法完整地放在独立程序集 Bin/SinsEKF7.Core.dll（44 KB，26 个源文件）中。它的本质是一个 七状态全量卡尔曼滤波器（四元数 4 + 导航系速度 3），配 ZUPT 零速观测、磁航向观测、 三级静止检测和静止零偏估计——结构与 PX4/Pixhawk 早期七状态姿态 EKF 高度同源。 此外还完整挖出了三族伴随算法：振动特征算法族（时域链 + FFT 域 + 20 项统计指标）、 磁力计标定族（含一个 15 状态 EKF 的实时标定原生库）、以及一套简化 ZUPT 位移解算器。

一个容易混淆的点 这套 PC 端算法的用途是上位机的「位移解算 / 3D 轨迹回放」功能（代码里挂的测试数据集是"手术刀推轨"等 HWT605 录制集）。传感器模块本体固件里跑的那套融合算法并不在这套软件里——模块上电直接输出的 四元数是固件算的。固件考古（§2B）确认：软件内能找到的两类固件——OTA 镜像与评估板 hex—— 分别是 ESP8266 WiFi 桥与 STM32F1 UART 桥，均不含姿态算法； 模块主 MCU 固件不随软件分发（SWD dump 或行为指纹是仅剩的取证路径）。

2B · 固件考古与双层算法架构

把整套产品里的固件翻遍之后，整个系统的算法分工彻底清楚了——三层芯片、两套算法：

层芯片固件在软件里的位置职责算法
① 模块本体未知 MCU（上位机二进制全搜无记载；疑 STM32F1 级，拆壳可查） 不随软件分发（工厂烧录）姿态解算（产品主业） "动态卡尔曼"（官方口径）；0x24 AXIS6 寄存器可切六/九轴
② WiFi 版协处理器ESP8266Plugins/Python/OTA/upgrade/user*.bin WiFi 桥（Web 配置页 + TCP/UDP 转发）无
③ USB 评估板STM32F1 兼容（外设地址判定）Config/ConfigurationSpace/USB-Evaluation-Board/*.hex UART 桥 + AT 版本查询（"人格"固件）无

评估板固件"无算法"的证据链（都能复现）：

  1. "人格"固件：JY901-UART.hex 与 JY61P-UART.hex 整个二进制仅差 6 字节， 其中 3 字节即产品名（'9','0','1' vs '6','1','P'）——同一份代码换名字的 8 份拷贝；
  2. AT 命令桥：字符串区为 AT+VERSION=、<产品名> V1.0、OK!、ERROR!；
  3. 基因检测零命中：参考算法全部特征常量（g₀=9.7955、静止阈值、四元数标度 32768、 连 π/180 与 180/π）一个都搜不到——连一度角度换算都不做，纯数据管道；
  4. MCU 判定 STM32F1 兼容：GPIO 0x40010800 / AFIO / RCC / FLASH 0x40022000 / USART1+USART2 / DMA1 外设地址全套命中，无 USB 外设（USB 由板上独立转串口芯片承担）； 13KB 镜像、初始 SP 0x200006F0（小容量型）；
  5. 中断结构：向量表绝大多数 IRQ 指向默认死循环，仅 4 个真实 handler 且均为 ldr r0,[pc]; b.w 公共实现 蹦床——与双 UART DMA 转发桥一致；
  6. 上位机侧闭环：UsbCore.Procesor 从该目录加载 hex 并按模块名 CheckHexName 对比，不匹配提示"重刷评估板固件"——这是评估板换装机制，与传感器固件无关。
算力经济学，以及对自研产品的启示 这套双层架构是 2013 年代算力约束下的自然选择：模块 MCU 资源有限，跑轻量算法保 200Hz 实时输出； 位移解算又重又不需实时（录完回放），扔给 PC。今天情况反过来了——这套 7 态 EKF 的 C99 移植 在 Cortex-M4F 上只占约 1% 算力（§5.3），把"PC 级重算法"直接搬上 MCU、两层压一层 完全可行，这正是自研 HID 空鼠（姿态引擎 + 光标引擎单板直出）走的路线——比原厂的分层更激进， 因为算力允许了。

3 · 姿态解算：七状态全量 EKF（SinsEKF7.Core）

这是整套软件里最有价值的部分。SinsEKF7.Core.dll 是一个自包含算法库， 只依赖 MathNet.Numerics 做线性代数，26 个类职责分明（预测器 / 观测器 / 雅可比 / 检测器 / 参数各一个文件）。 它在软件里的角色：JY901 数据视图拿原始 acc/gyro/mag 喂给它，输出姿态四元数 + 速度 + 位移， 驱动 3D 轨迹回放。

3.1 坐标系与状态约定

导航系取 ENU（x 东、y 北、z 天），重力沿 −z。姿态用单位四元数 q = [q0, q1, q2, q3]（q0=w）表示， R(q) 为体→导航方向余弦阵（代码 Quaternion.ToDirectionCosine()， Alignment.BodyToNav()）。滤波器状态是七维全量状态（不是误差状态）：

x = [ q0, q1, q2, q3, vE, vN, vU ] T ∈ ℝ⁷

协方差 P 直接在这个 7 维状态上传播（7×7）。这是 2013 年前后嵌入式 EKF 的典型做法： 实现简单、无需误差状态注入，代价是大机动下的数值稳定性弱于现代 ES-EKF（后述）。

3.2 信号预处理与自动标定

进入滤波器之前有两级处理（调用方 DataAlgorithm 中）：

  • 标量一阶低通（他们叫 K 滤波）：yk = (1−k)yk−1 + k xk，acc/gyro 各 k=0.1；
  • 前 10 秒静止自标定（ImuAutoCalibrator）：窗口峰峰值低于阈值（陀螺 0.2°/s、加计 0.1 m/s²）持续 2 s 判静止， 再用 0.5×Fs 的三段轮转窗口累计均值，得到安装矩阵 Rinst（加计调平四元数的 DCM） 与陀螺零偏 bg；完成后把输入旋转到调平系、扣除零偏，并 filter.Reset() 重启初始化。 好处：模块不用严格水平安装，算法自己找水平。

3.3 三段式初始化（0–4 s 状态机）

两条对准公式（Alignment.cs）——调平用平均比力方向：

θtilt = atan2( √(ax² + ay²), az ),   axis = a × ẑ| a × ẑ |,   qtilt = [cos(θ/2), axis·sin(θ/2)]

航向用调平后的磁向量（水平分量指北）：

ψ = Dec + atan2( mE, mN )

3.4 机械编排预测（每拍执行）

姿态：陀螺角增量扣零偏 → 旋转向量转四元数（小角度用泰勒级数，避免除零）→ 右乘传播：

δq = quat( (ωb·Δt − δθbias) ),   qk+1 = normalize( qk ⊗ δq )

速度：比力旋转到导航系后积分，重力沿 −z 扣除；Ka 是粗对准算出的加计刻度因子（g₀/|ā|）：

vk+1 = vk + R(qk+1) · ( Ka ab Δt ) − g₀ Δt · [0,0,1]T

位置：仅在运动档位允许时做梯形积分，且任何静止标志（flag>0）都直接清零——位置只是短时演示量：

pk+1 = pk + ½Δt ( vk + vk+1 )  (仅 outRunPosFlag=1)

3.5 协方差传播与可观测性开关

每 5 ms 一次、按 4 拍轮转中的第 1/3 拍执行（CovariancePredictor + Jacobian.CalcF7/CalcQ7）：

P ← F₇ P F₇T + Q₇,  随后 P ← ½(P + PT)，对角负值截断

F₇ 是状态转移对 [q, v] 的解析雅可比（以累计角增量/速度增量为一阶项）， Q₇ 由过程噪声（角度增量噪声 0.01 rad、速度增量噪声 0.35 m/s）经四元数结构映射而成——两块 7×7 解析式在 Jacobian.cs 里全部显式展开（每块 ~90 行标量式），工程上很"莽"但透明可查。三个关键设计：

  • 可观测性开关：amode=6（六轴）时 Q 中 σθz²←0 且 P₀ 中 q₃ 方差置 0——偏航被显式声明为不可观，只靠陀螺积分，不发散；
  • 静止时角度增量清零（dax=day=daz=0 进 F）：静止期间不往姿态注入过程噪声，姿态确定性保持；
  • 噪声按累计增量注入：协方差用累计 Δθ、Δv（DelAngCov/DelVelCov）而不是瞬时值，对变步长更稳。

3.6 ZUPT 零速观测（第 0 拍）

这是整套算法的"锚"。IMU 没有绝对姿态/速度参考，加计只测比力——靠"静止时速度必为零"这个物理事实， 把速度误差拉回零，姿态误差随之通过 P 的交叉协方差被连带修正。观测模型：

H = [ 03×4 I₃ ],   z = 0（零速伪观测）,   新息 ν = 0 − v̂ = −v̂

逐轴卡方式门控：νi² / (γ² Sii) > 1 则整体拒绝本拍（防坏数据拉崩）。 精髓在量测方差 R 与门限 γ 随运动状态分四档，越静止拉得越狠：

motionlessFlag含义（检测条件）R（量测方差）门限 γ附加动作
0运动中10⁴（等于不信）γ₀×10⁻⁴—
1低角速率 ≥0.2 s（|ω|<1.5°/s）1γ₀（=10）|v|>0.5 则硬置零
2偏航静止 ≥1 s（ω_z 峰峰值<0.5°/s）10⁻²γ₀×10同上
4完全静止 ≥2 s（六路峰峰值全低于阈值）10⁻⁴γ₀×100|v|>0.1 则硬置零

增益与协方差按标准 KF 更新：K = P HTS⁻¹， x ← x − Kν（四元数归一化），P ← (I−KH)P 对称化。

3.7 磁航向观测（第 2 拍，仅 amode=9）

一维观测，量测函数是"把磁向量旋到导航系后取水平角"：

h(q) = atan2( ( R(q)m )E, ( R(q)m )N ),   新息 ν = h(q) − Dec

即"当前姿态下解算出的磁航向"应等于当地磁偏角——期望值本身就是参考。H = ∂h/∂q 是 解析雅可比（Jacobian.CalcH_Hdgc，atan2 比值求导展开成 ~40 行标量式）。测量噪声自适应：

  • 运动中：启动 2 s 内 Rmag=100（很松），之后 10·σhdg²；
  • 静止中：0.3·σhdg²（收紧），且静止累计超 10 s 时直接重新粗对准航向并重置 P（快速收敛不怕暂态）。

门控同样是卡方式（ν²/(γmag²S) ≤ 1，γmag=5），磁干扰大时整拍拒绝。

3.8 静止检测与陀螺零偏管理

MotionDetector 输出三级标志（见 3.6 表），检测器是"窗口峰峰值 + 阈值突破时锚点重置"式。 完全静止（flag=4）时有两件事发生：

  • 姿态冻结：角增量 δθ 直接替换为 δθbias（只扣零偏，不积分真实旋转）；
  • 分窗零偏估计：以 0.23·Fs 为窗长做三段轮转累计（清零→累计1→累计2→出均值）， 均值以 α=0.04 指数平滑进 bg——静止越久零偏越准，这是 MEMS 陀螺 "零偏不稳"的对冲手段。

4 · 「准确的姿态」是如何获得的

商用算法与教科书 Demo 的差距，不在"会写 EKF 公式"，而在把物理先验和工程防御做成闭环。 把这套实现拆开看，准确姿态来自七层机制的叠加：

一句话版本 加计管"水平不漂"（经 ZUPT 间接起作用）、磁力计管"航向不漂"、陀螺管"动态跟得上"、 静止检测管"什么时候该信谁"、零偏估计管"陀螺慢变"、门控管"坏数据进不来"。 姿态解算从来不是单个公式，而是这套信任调度系统。

值得注意的对照：模块固件里跑的算法（输出四元数的那套）通常是 Mahony/互补滤波或小型 EKF， 受限于 MCU 算力；而这套 PC 端算法跑在 x86 上，可以放手做 7×7 矩阵运算和多重防御。 也就是说：同一台 JY901，上位机里的"二次解算"在某些场景（尤其需要位移时）比模块固件输出更讲究。

黑盒测试还抓出并修复了一处移植偏差 MotionState / AutoCalState 的 min/max 字段在 C# 里默认是 0（double 字段默认值）， 移植版最初用了 ±∞ 初始化——首拍峰峰值行为不同。按 C# 默认值对齐后三场景全绿。 这正说明差分黑盒测试的价值：看代码逐行对照会漏的东西，逐拍比对抓得出来。

5.3 · C99 移植验证（可直接进固件）

为落地到 ESP32-S3 / STM32 固件，算法另有一份 C99 移植（开源库 quat-zupt-ekf/c/： 零依赖、无动态分配、与 Python 包逐模块对应），用同一套差分方法验证：

场景拍数最大绝对差（全列）静止判别序列
amode=910003.8 × 10⁻¹⁰完全一致
amode=930001.1 × 10⁻⁸完全一致
amode=630003.2 × 10⁻⁸完全一致

差异比 Python 版（10⁻¹⁵ 量级）略大，来源是 3×3 求逆改用伴随式与矩阵求和顺序不同—— 仍是同一算法的浮点噪声量级。C 移植同样被差分测试抓出一个教科书级 bug： filter_reset 的 memset 把嵌在结构体里的参数副本一并清零 （自标定完成触发 reset 时参数全变 0 → NaN），修复后全绿。嵌入式集成注意（float 替换需重验、 匀速误判怪癖的位置）见该库 c/README.md。

6 · 谱系：它从哪里来

多处结构证据指向 PX4/Pixhawk 早期的七状态姿态-位置 EKF（ekf_att_pos_estimator / ecl 前身一支）：

  • 同样的全量状态 [quat, velocity] 与 7×7 协方差直接传播；
  • DelAngCov / DelVelCov 式的 IMU 增量累计 + 周期性协方差注入调度；
  • ZUPT 的 H=[0 I] + 逐轴卡方门控 + 按运动状态切换 R；
  • 磁航向一维观测 atan2((R·m)_x,(R·m)_y) − dec 及其解析雅可比；
  • min/max 锚点重置式静止检测、静止分窗零偏估计；
  • 6/9 轴"amode"与 Q 中 z 轴角度噪声置零的可观测性处理。

本土化改造：G₀ 取广州纬度值 9.7955、参数 Wit 化命名、加入安装矩阵自标定、 WorkMode 位移档位、磁航向静止超时重对准（MagRunTime>10 s 触发 P 重置）。 结论：可视为 PX4 早期 EKF 的商用移植改良版（基于结构判断，未做逐行比对核实）。 对照现代实现：PX4 当前的 ECL2/EKF2 是 24 状态误差状态 EKF；误差状态式在大机动一致性、 数值稳定上都优于这种全量式——但全量式的可读性与实现成本优势，正是它在商用上位机里活到 2025 年的原因。

7 · 商用算法的七个弱点（研究价值所在）

⚠ 1 · 匀速旋转会被误判为"静止"（最严重的坑） 静止检测是"窗口峰峰值 + 阈值突破时锚点重置到当前值"式。开始匀速旋转后锚点即重置， 随后峰峰值只剩噪声 → 2 s 后 flag=4。后果链：姿态增量被 δθbias 替代（yaw 冻结） → 零偏窗口吸入转速 → 零偏被污染（合成数据实测 z 轴零偏被拉偏 ~5°/s 量级）→ 解冻后姿态跳变。 原厂测试集是"手术刀推轨"式往复运动，从不触发；车载匀速转弯、云台连续跟拍场景必踩。

其余六个按严重程度排列：

  1. 冻结与污染互相放大：冻结期间预测仍用被污染的 δθbias，错误在静止期持续累积；
  2. DataAlgorithm.calculate() 内硬编码 cfg.Fs=200，覆盖外层数据集采样率——500/1000 Hz 数据集实际按 200 Hz 阈值运行；
  3. 全量四元数协方差传播：大机动数值稳定性弱于 ES-EKF，只能靠 0.5(P+Pᵀ) 对称化和对角截断兜底；
  4. G0=9.7955 是广州本地 g：纬度差 ~0.1% g，经 ZUPT 拉扯表现为小俯仰偏差；
  5. 位置输出在 flag>0 时清零：只是短时相对位移演示量，不是 PDR 级输出；
  6. 初始化计数要求陀螺逐拍变化 <0.02 rad/s：振动环境下计数反复清零，粗对准延迟（有超时兜底）。

8 · 振动算法族（VibrationAlgorithm.dll + WTVibrationC.dll）

服务维特振动类产品（WTVB 系列），由 Plugins/algorithm/ServerApp.exe 独立进程承载， 另有原生 x64 的 WTVibrationC.dll（C 版，给 WTVibrationHelper64.exe 用）。 入口 VibrationCalculator.Calculate() 按三模式分发：

时域特征全集（AccMagnitudeReal 输出，三轴各一组）——标准振动监测指标全套：

类别指标
基础原始幅值、均值、绝对均值、方差、RMS、交流 RMS、峰值
无量纲特征峰值因子（Crest，AC/DC 两版）、峭度（Kurtosis）、偏度（Skewness）、脉冲因子、波形因子（Shape）
积分量速度 RMS、位移 RMS、速度峭度
频域（FFT 模式）加速度/速度/位移幅值谱，0.25x/0.5x/1x/2x/3x/4x/5x/6x 倍频 bin，0–0.5x/0.5–1x/1–2x/2–3x/3–4x/4–5x 分段能量，段总和

频率估计用带滞回的过零法（FsCal）：信号越过 ±阈值判定半周期， f = Fs / 半周期样本数；静止标志直接冻结计数。倍频 bin 的存在说明这族算法瞄准的是 旋转机械状态监测（转频的各次谐波是轴承/齿轮/不平衡的经典特征）。

9 · 磁力计标定族（Wit.MagCal.dll + Lib/RealMagCal*.dll）

四套并存，对应不同产品形态：

实现形态算法要点
CMagCali（椭圆拟合 UI 内）托管 C# 最小二乘意义下的 offset/range 迭代拟合：以 hOffset/hRange 参数化椭球， GetErrorSum 作为目标函数逐步收敛；初值 hRange=500
八面标定（EightFaceCalibration）托管 C# UI 引导用户六面+对角共 8 个朝向采点，取各面均值定 offset/scale
片上最大最小（OnChipMaxAndMin）UI + 下发命令 旋转采点记录 max/min，标定在模块固件内完成，上位机只引导
RealMagCal.dll（实时标定）原生 32 位，MATLAB Coder 生成 接口暴露 states[15] + covariance[225] —— 15 状态 EKF（PDB 路径 D:\RealMagCal20230920\…），运动中在线估计磁偏移/椭球参数； 批量版 RealMagCalOutN 吞 10 万点 gyro+mag 序列输出 8 路状态与距离序列
为什么这族值得单看 15 状态 EKF 接口（姿态 3 + 速度 3 + 陀螺零偏 3 + 加计零偏 3 + 磁相关 3 的经典划分） 说明"实时磁标定"实际上是导航级误差状态滤波器 + 磁椭球参数在线估计的组合—— 与第 3 节的 7 状态全量 EKF 是两代技术混用在同一软件里。原生 MATLAB 生成代码可另开课题用 Ghidra 慢啃。

10 · 简化位移解算器（ImuOptDisplacementSolver）

JY901 视图里的第二套、轻量位移方案——姿态由外部给定（模块输出的四元数），只做位移积分：

// 输入：raw acc + gyro + 外部四元数 q
acc_LP = α·acc + (1−α)·acc_LP_prev          // α = 0.12
a_nav  = R(q)·acc_LP − [0,0,g]              // 转导航系并去重力
static ‖a_nav‖<0.1 m/s² 且 ‖ω‖<0.012 rad/s 连续 5 帧？
  ├─ 是：v←0（ZUPT），且 accBias += a_nav×0.0008   // 零偏慢速回修
  └─ 否：v += ½(a_prev+a_now)·dt；p += v·dt       // 梯形积分
p ← clamp(p, ±2 m)                          // 硬限幅防漂

对比第 3 节的 EKF：这套是"无协方差、纯阈值"的工程捷径，胜在便宜；两套并存说明 厂商自己也在"精确但重"与"简单但糙"之间做了双轨。
