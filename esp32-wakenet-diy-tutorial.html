§1背景：唤醒词检测的原理与 WakeNet 配方

1.1 唤醒词检测 = 流式小词汇量分类

“Hey Siri”"小爱同学"这类唤醒，学术上叫 Keyword Spotting (KWS)：音频流上持续跑一个小神经网络，判断"最近 1 秒里有没有出现唤醒词"。它不是把语音转成文字，而是直接把声音片段分类成「目标词 / 其他话 / 噪声」——所以模型可以非常小。

一个完整的端侧唤醒系统只有四段，WakeNet 也不例外：

  1. 音频前端：16kHz 单声道 PCM 进来（可加 AEC/降噪/VAD，玩具可全省）。
  2. 特征提取：每 30ms 窗、10ms 步进算一帧 MFCC 或 log-mel 谱（40 维）。语音信息几乎都在谱包络里，这一步把 16000 个采样点压成 40 个数。
  3. 小 CNN：在 1 秒的特征序列（约 97 帧 × 40 维）上做分类，输出各类概率。
  4. 平滑触发：连续若干帧概率均值超过阈值才触发——这是防误唤醒的关键工程，比模型本身更重要。

1.2 WakeNet 公开了什么、藏着什么

先澄清一个常见误解：乐鑫没有发表过 WakeNet 的学术论文。它的公开资料就是 ESP-SR 文档和 GitHub 仓库，文档里明说了架构出处：

版本架构出处
WakeNet2/3（早期，已退役）受 DFSMN（前馈序列记忆网络）影响阿里达摩院 DFSMN 论文家族（2018）
WakeNet9 / 9l（ESP32/S3/P4 现役）膨胀卷积（Dilated Convolution）堆叠WaveNet（arXiv:1609.03499）
WakeNet9s（C3/C5/C6 小芯片）深度可分离卷积MobileNet（arXiv:1704.04861）

资源量级（官方 benchmark）：量化后 几十 KB 参数、15–50KB RAM、每帧 5–18ms。触发方式就是上面说的"多帧平均过阈值"。

那乐鑫的定制服务（收费、要 2 万条语料、周期 2–3 周）卖的是什么？语料工程和远场/噪声下的鲁棒性调优，不是模型结构——结构文档全写着。这留下一个空档：安静房间里的玩具场景，恰恰不需要那两样。这就是本教程的立足点。

§3路线 A：直接用官方 WakeNet（半天）

3.1 ESP-IDF 方式（推荐）

# 添加组件（会连 AFE/WakeNet/MultiNet 一起进来）
idf.py add-dependency "espressif/esp-sr"

核心用法是 AFE（音频前端）的 feed/fetch 循环，唤醒命中从 fetch 结果里拿（示意，以官方 esp-skainet 示例为准）：

esp_afe_sr_iface_t *afe_handle = esp_afe_handle_from_config(&afe_config);
afe_data = afe_handle->create_from_config(afe_config);
// 两个任务：task_feed 喂音频，task_fetch 取结果
while (1) {
    afe_fetch_result_t *res = afe_handle->fetch(afe_data);
    if (res->wakeup_state == WAKENET_DETECTED) {
        /* 唤醒命中！这里点亮你的灯 */
    }
}

3.2 换唤醒词

  • 免费可商用：官方文档列了 "Hi, 乐鑫" / "Hi,ESP" / "nihaoxiaoxin" 等若干内置词，通过 model 选择宏切换，一个模型最多同时挂 5 个词。
  • 自定义：走乐鑫定制流程——自备 ≥2 万条合格语料、2–3 周训练优化、收费（金额看词数和量产规模）。这是催生本教程路线 B 的直接原因。
Arduino 用户注意：ESP_SR 库对板型有支持列表，M5StickS3 这类板若不在列表里，通常切到 "ESP32S3 Dev Module + OPI PSRAM + 8MB Flash" 板型配置即可（与官方 DevKitC 参考设计同构）。

§4路线 B：自研复刻七步实战

以下全部是 2026-09-19 在 Mac (Apple Silicon) 上真跑通的流程，代码在 magic-wand/wakenet/scripts/，每一步都有可复现的命令。

图 1 · 自研复刻全流水线。所有中间产物可随时删掉重跑再生。
  1. 数据合成：用 macOS 自带 TTS 当"免费录音棚"

    训练唤醒词最贵的是数据。Mac 的 say 命令有 9 个英文语音 × 任意语速，两条命令就能合成一条训练样本：

    say -v Samantha -r 170 -o lumos.aiff "lumos"
afconvert -f WAVE -d LEI16@16000 lumos.aiff lumos.wav   # 转 16kHz int16 wav

    正样本设计成 3 语气 × 9 语音 × 5 语速 = 135 条（"lumos" / "Lumos!" / "lumos?"）。重点其实是负样本——误唤醒全发生在"听起来像"的词上，所以负样本词表要刻意收集易混词：

    NEG_TEXTS = ["luminous", "music", "locus", "focus", "mucus", "menus",
             "hocus pocus", "lupus", "lunch", "locust", "mouse", ...,
             "turn on the light", "hey siri", "okay google", ...]  # 90+ 条

    再程序化生成第三类「噪声」（白噪/粉噪/工频嗡嗡/静音底噪）。合计 1719 条。把自己的真实录音放 data/raw/mylumos/*.wav（30–50 条）会被自动吸收进训练——这一步强烈建议做，见 §8。

  2. 数据集：1 秒定长 + 说话人无关切分

    所有样本裁/补成 1.0s @16kHz。正样本能量裁边后随机放置在 1s 画布内（避免模型只认固定位置）；负样本随机裁 1s。最关键的工程决定：验证集留出 2 个完整语音（Daniel/Tessa），训练时一次都不出现——否则同一个人的样本泄漏到验证集，指标会虚高到没有意义。

  3. 特征前端：40 维 log-mel，纯 numpy 手写

    和 WakeNet 同款参数：30ms 窗（480 点）、10ms 步进（160 点）、40 个 mel 滤波器、512 点 FFT，1 秒得 97 帧。不要引 librosa，40 行 numpy 写完，将来 C 端照着翻译一遍就行：

    def logmel(x):                                  # x: (16000,) → (97, 40)
    frames = np.lib.stride_tricks.sliding_window_view(x, 480)[::160][:97]
    spec = np.abs(np.fft.rfft(frames * HANN, n=512, axis=1)) ** 2
    mel = np.log10(spec.astype(np.float64) @ FB.T + 1e-8)   # double 对齐 C 端
    return mel.astype(np.float32)

    归一化用全训练集的均值/方差（存下来，C 端要用），再 clamp 到 ±4——这个范围就是 int8 输入量化的标尺。

  4. 模型：深度可分离卷积 ×3，33K 参数

    照 WakeNet9s 的积木（MobileNet 深度可分离卷积）搭一个流式小网络。膨胀率 1→2→4→8 让感受野覆盖约 600ms，刚好罩住一个两音节词：

    class DSConv(nn.Module):                        # depthwise + pointwise
    def __init__(self, cin, cout, k, dilation):
        super().__init__()
        pad = dilation * (k - 1) // 2
        self.dw = nn.Conv1d(cin, cin, k, padding=pad, dilation=dilation, groups=cin)
        self.pw = nn.Conv1d(cin, cout, 1)
    def forward(self, x): return self.pw(self.dw(x))

# 输入 (40, 97) → stem Conv1d(40→48,k5) → DSConv(48→64,d2)
#   → DSConv(64→96,d4) → DSConv(96→128,d8) → 时间GAP → FC(128→3类)

    三类输出：[目标词, 其他话, 噪声]。"其他话"这一类必须有——它决定了听到无关词时模型会不会乱点头。全模型 33,075 参数，int8 后 33KB。

  5. 训练：类平衡采样 + 最优 checkpoint 回滚

    第一个大坑在这：正负样本 105:1512，直接训会塌成"全判其他话"（loss 正常下降、准确率=类先验、召回 0）。两个修法缺一不可：

    # ① 按类倒数权重过采样正样本，每个 batch 三类均衡
cls_n = np.bincount(y_train)
sampler = WeightedRandomSampler(1.0 / cls_n[y_train], num_samples=len(y_train))
# ② 每个 epoch 在留出语音上打分，分数 = 召回 − 2×误报，回滚最优权重
score = recall_on_val - 2 * false_alarm_on_val

    增广（在线做，每次采样现生成）：随机增益 0.25–1.0、加噪 SNR 12–40dB、±150ms 时间平移、SpecAugment。注意增广是随机流，不同 run 方差很大——最优 checkpoint 回滚同时解决了这个问题。40 epoch 后留出语音召回 100%、易混词误判 1.2%。

  6. 量化：逐通道 int8 + QAT，救回 15 个百分点

    第二个大坑：float 模型直接 int8 量化，准确率从 99.1% 崩到 81.5%。逐层检查激活都很健康——根因是判定边距太薄：每层 requant 取整噪声 ±0.5/127 累积 7 层，临界样本全被推过边界。解法是量化感知训练（QAT），前向时做伪量化、梯度直通（STE）：

    def wfq(w):   # 权重伪量化：逐输出通道对称 int8
    s = w.detach().abs().amax(dim=tuple(range(1, w.ndim)), keepdim=True) / 127
    q = torch.round(w / s).clamp(-127, 127) * s
    return w + (q - w).detach()          # 前向用量化值，反向梯度直通

def fq_act(x, scale, relu=True):  # 激活伪量化，scale 来自标定
    s = scale / 127
    q = torch.round(x / s).clamp(0 if relu else -127, 127) * s
    return x + (q - x).detach()

    量化公式与部署侧严格同构：权重逐输出通道 q_w = round(w/max|w|·127)，激活 scale 用 40 个 batch 的最大绝对值标定（训练和导出必须读同一份，存 stats.json）。QAT 微调 20 epoch 后，int8 准确率回到 96.2%。

  7. 导出与对拍：让 C 和 numpy 逐位一致

    导出脚本把权重/scale/mel 滤波器组写成 wakenet_model.h，C 端前向只有一种运算——整数累加 + float requant 取整：

    int32_t acc = b[o];
for (i, k ...) acc += (int32_t)x[i*T+ti] * (int32_t)w[(o*ci+i)*K + k];
y[o*T+t] = clamp(lrintf((float)acc * requant[o]), 0, 127);

    整数加法与求和顺序无关，两边天然逐位一致（实测 softmax 偏差 1.2e-07）。对拍有两个文件级检查：net（量化特征 → 概率，对 numpy 期望）和 mel（PCM → 特征）。

    对拍最大的坑：mel 对拍曾稳定差 0.07，换了 FFT 精度、双精度累加都没用——最后发现期望值是用 float 波形算的，而 C 端吃的是 int16 PCM。设备端输入本来就是 int16，期望值必须按 int16 量化往返后算。修正后偏差 3.4e-05。

§5部署到 ESP32

三个文件进工程即可：wakenet.c/h（int8 前向 + 触发器）、mel_fbank.c/h（特征前端）、wakenet_model.h（生成的权重）。零第三方依赖，Arduino 和 ESP-IDF 都能编。音频任务每 300ms 取最近 1 秒判一次：

#include "wakenet.h"
#include "mel_fbank.h"

static float feats[WN_NFRAMES][40];
static wn_trigger_t tg;

void audio_task(void *arg) {
    wn_trigger_init(&tg, /*avg_n=*/4, /*thr=*/0.7f);  // 连续4窗均值>0.7才触发
    while (1) {
        fill_last_1s_pcm(pcm);                        // 你的 I2S/PDM 采样
        mel_frames(pcm, 16000, feats);
        float probs[3];
        wn_forward(&feats[0][0], probs);              // [目标词, 其他话, 噪声]
        if (wn_trigger_update(&tg, probs[0])) {
            /* 唤醒命中：点亮魔杖 / 发事件 */
        }
        vTaskDelay(pdMS_TO_TICKS(300));
    }
}

触发器自带滞回（回落到 60% 阈值以下才允许下次触发），实测能压掉单窗概率尖峰——160 秒负样本流里有 3 个孤立尖峰，平滑后 0 次误触发。

§7踩坑速查表

#症状根因与解法
1训练 loss 正常下降，召回却是 0类不均衡塌缩（全判"其他话"）→ 按类倒数权重采样 + 按 召回−2×误报 挑 checkpoint
2同代码两次训练结果天差地别在线增广是随机流 → 不追随机种子，用验证集最优 checkpoint 回滚
3float 99% 量化后只剩 81%判定边距薄，requant 噪声累积翻转临界样本 → 逐通道权重量化 + QAT 微调
4训练 QAT 和导出 int8 行为不一致两边激活标定 scale 不同 → 标定结果存档（stats.json），导出只读不重算
5C 端 mel 和 python 永远差 ~0.07期望值用 float 波形、C 端吃 int16 PCM 的往返差 → 期望值按 int16 往返算
6验证准确率虚高（99%+）但上板不灵同一"说话人"的样本泄漏进验证集 → 按语音（说话人）切分，不是按样本随机切

§8局限与改进方向

如实交代当前边界（都是玩具场景可以接受、产品场景必须解决的）：

  • 正样本全是 TTS：9 个 macOS 语音训练，真人（尤其距离远/带口音）未系统验证。改进：自己录 30–50 条丢进 mylumos/ 混训，一行命令重跑。
  • 无音频前端：没有 AEC/降噪/AGC，嘈杂环境和回声场景会退化。玩具安静房间够用；要硬刚就上 ESP-SR 的 AFE，或把本模型喂给 AFE 后面。
  • 负样本域窄：只有 TTS 念词 + 程序噪声。真电视声/音乐/多人交谈没见过。改进：录几段环境音混进负样本。
  • 单一唤醒词：三类输出只支持一个词。要多词就把 FC 类别扩到 3+N，数据按词增加。
什么时候放弃自研回官方：要过认证/量产/远场 3 米唤醒率指标时。自研路线的价值是自由、白盒、零授权成本，不是替代工业方案。
