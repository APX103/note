01 / 需求与最终形态

两台设备组成一对一无线对讲：按住说话（Push-to-Talk），松开收听；不按时随时能收到对方语音并从喇叭放出。StickS3 用实体按键触发，AMOLED 板用触摸屏上的大按钮触发。无路由器、无手机、无云端，开机即用。

  • StickS3：按住 BtnA 说话；喇叭随时播放来话；小屏显示状态（空闲/发送中/接收中/对方占用）。
  • AMOLED 板：按住屏幕 PTT 区域说话；喇叭随时播放来话；大屏可显示电平表、链路质量、通话状态。
  • 交互上是"对讲机"而不是"电话"：同一时刻一方说、一方听，抢占有仲裁、状态有提示。

02 / 硬件盘点：两板音频全通

先回答最前提的问题：两块板都有麦克风和扬声器，且用的是同一颗音频 codec——这消掉了整个方案最大的不确定项。

StickS3 侧则由 M5Unified 全权托管 ES8311（M5.Mic / M5.Speaker），Mic_FFT 例程已验证录音链路可用。

03 / 为什么是 ESP-NOW：链路预算

ESP-NOW 是乐鑫在 Wi-Fi MAC 层之上做的无连接点对点协议：不建联、不要 AP、不等 IP，发就是发，单向空口延迟约 2–5 ms，非常适合语音包这种"小包、高频、容忍少量丢"的流量。

约束数值对本方案的影响
单包 payload（经典模式）250 字节音频按 ~200 B/包分片（约 20–25 ms 语音）
实际可持续吞吐约 100–500 kbps（视信道与发包节拍）64 kbps 语音码率留有余量；发包要限速避免冲爆
peers / 加密点对点 MAC 寻址，支持 CCMP（PMK/LMK）定向发给对方 MAC，他人不解析；可选加密
覆盖距离室内全屋、视距实测 100–200 m家用场景绰绰有余
信道固定单信道（1–13）两板锁同一信道；可选扫一遍挑最干净的

备选链路对照：Wi-Fi UDP（要 AP、要 IP，延迟抖动更大）、蓝牙 HFP/A2DP（配对复杂、语音走 HFP 音质差）、AuriRink/I2S 无线（不通用）。结论维持 ESP-NOW。

04 / 先例扫描

  • Adafruit《ESP-NOW Walkie Talkies》教程（2026-04）：Feather ESP32-S3 + I2S 麦克风，ESP-NOW 收发 I2S 音频包，架构与本方案同型。
  • atomic14/esp32-walkie-talkie：最流行的开源对讲机，支持 UDP 广播 / ESP-NOW 两种传输，ADPCM 压缩，包协议（序号+时间戳+丢包容忍）值得直接借鉴。
  • PCMFlow722（G.722 over ESP-NOW）：证明了 64 kbps 实时双向语音在 ESP-NOW 上可持续，且明确按半双工设计——与本方案码率和双工选择互相印证。
  • 社区共识的编码阶梯：裸 PCM（256 kbps，太重）→ IMA ADPCM（32–64 kbps，CPU 几乎免费，最常用）→ G.722（64 kbps 宽带音质）→ Opus（16–24 kbps 最省带宽但 S3 上 CPU 开销显著）。

05 / 音频管线设计

采集I2S DMA 16 kHz 16 bit 单声道，帧长 20 ms（320 样本）
编码IMA ADPCM 4:1 压缩 → 每帧 160 B + 头部
发包限速发送，单包 ≤250 B，附序号/时间戳
重排jitter buffer 60–100 ms 按序重排、补缺
解码ADPCM 还原（丢包则重置预测器，小爆音可忍）
播放I2S 连续 DMA 输出到 ES8311

参数建议

  • 起步：16 kHz / IMA ADPCM ≈ 64 kbps。两板例程原生就是 16 kHz，音质与带宽的平衡点，PCMFlow722 证明 64 kbps 可持续。
  • 若实测丢包率高：降到 8 kHz（≈32 kbps）换可靠性；若还想升级音质：换 G.722（同为 64 kbps 但 7 kHz 音频带宽）。
  • 播放侧恒速走时（数码时钟晶振）与发送侧采样钟有偏差，需要时钟弹性缓冲：水位低于阈值丢帧、高于阈值插帧，否则长时间通话会累积漂移。

06 / 双工模型与回声治理（三问三答）

Q1：会不会"串台"？

不会像模拟对讲机那样串。ESP-NOW 是按目标 MAC 定向发送的数字包（可再加 CCMP 加密），只有配对的那台板子会解析内容。同信道的其他 Wi-Fi 设备只会造成空口竞争（表现为丢包/卡顿），不会把声音串进别人的设备。

Q2：是不是全双工？

射频物理层是半双工的（Wi-Fi 同频段分时收发），但包交换层面双向可以交替并发——技术上能做出"边说边听"的伪全双工。本方案明确不做：全双工会引入声学回声消除（AEC）需求，S3 上做 AEC 性价比极低，且空口双向满流量会互相挤占。经典对讲机式半双工 + 抢占提示，体验反而清晰。

Q3：逻辑上会不会串扰（回声循环）？

会，这正是 PTT 要治理的核心。危险场景：A 按住说话时，A 的喇叭同时在放 B 之前的声音 → A 的麦克风把它录进去再发回 B → 回声循环甚至啸叫。治理规则：

规则行为
发送静音（核心规则）本地按住 PTT 期间，喇叭静音；期间收到的音频包丢弃（或缓存、松开后不补放，避免过期语音轰炸）
抢占仲裁收到对方 PTT_DOWN 后本端进入"对方占用"态：触摸/按键说话仍允许排队，但对端不播放；或直接禁止并震动/闪红提示"对方讲话中"
结束信令松开 PTT 即发 PTT_UP，超时未收到视为对方断线，自动回空闲态（防"卡死在占用"）
心跳低频心跳包携带 RSSI/电量，驱动在线状态显示
一句话总结交互语义：谁按住谁占有信道；占有期间自己不听；双方都按住时，先按者先说，后按者看到"占用"提示。这是最简单、永不啸叫、实现量最小的模型。

07 / 协议帧设计

统一帧头 + 两种载荷（信令 / 音频），纯 C++ 结构体打包，两边工程共享同一份头文件。

// 所有帧共用头（小端， packed）
struct frame_hdr_t {
  uint16_t magic;      // 0xE731 固定标识 + 版本
  uint8_t  type;       // SIG_PTT_DOWN / SIG_PTT_UP / SIG_HEART / AUDIO
  uint8_t  flags;      // 预留：加密、重传请求等
  uint16_t seq;        // 音频包序号（信令包恒 0）
  uint32_t ts_ms;      // 发端单调时间戳
};

// AUDIO 载荷： 160 B IMA ADPCM（20 ms @16 kHz）+ 4 B 状态字
// SIG 载荷：   心跳含 RSSI/电量/音量；PTT_UP 含累计发包数供对端统计
  • 丢包不重传（语音重传到得晚不如丢）；连续丢 3 包以上重置 ADPCM 预测器并静音一帧。
  • 配对信息（对端 MAC、信道、PMK/LMK）烧录时写死进 NVS，首次开机对码流程留作后续增强。

08 / 工程形态与代码复用

两个独立 Arduino CLI 工程（工具链与 Mic_FTF 完全一致，零新增环境），一个共享协议层：

work/espnow-intercom/
├── common/               # 纯 C++ 共享层，两工程软链接或复制
│   ├── protocol.h        # 帧结构、序号、时间戳
│   ├── adpcm.h/.cpp      # IMA ADPCM 编解码（无依赖）
│   ├── jitter_buffer.h   # 重排 + 时钟弹性缓冲
│   └── link.h/.cpp       # ESP-NOW 封装：配对、限速发包、RSSI
├── sticks3/              # M5Unified: M5.Mic / M5.Speaker / M5.BtnA
│   └── sticks3.ino
└── amoled/               # Waveshare: 15_ES8311 例程改造 + 触摸库
    └── amoled.ino
关注点StickS3AMOLED
编译均为 arduino-cli compile -b esp32:esp32:esp32s3:PSRAM=opi,FlashSize=8M,PartitionScheme=default_8MB,CDCOnBoot=cdc（AMOLED 板 Flash 16 MB，FlashSize 可改 16M）

优先分工先做发送端（Mic_FFT 已验麦）先做接收端（15_ES8311 已验喇叭）

09 / UI：按键与屏幕

  • StickS3（135×240 竖条小屏）：顶部状态色带——灰=空闲、绿=我方发送中、蓝=接收播放中、红=对方占用；底部大字显示对端 RSSI 与电量；按键长按 BtnB 弹出音量档位。
  • AMOLED（368×448 触摸大屏）：屏幕下半部整块是 PTT 按钮（按住即说话，视觉按压反馈），上半部显示实时电平条 + 频谱残影（复用 Mic_FFT 的 FFT 代码即可）+ 通话时长与链路质量。
  • 两端收到 PTT_UP 后状态带延迟 ~300 ms 回空闲，避免视觉闪跳。

10 / 风险与未决问题

风险评估预案
ESP-NOW 实际吞吐不足 64 kbps中低（有 64 kbps 成功先例，但受信道质量影响）M2 里程碑先实测单向吞吐；不足则降 8 kHz/32 kbps
收发时钟漂移累积中（长时间通话必然漂移）jitter buffer 水位控制丢帧/插帧
AMOLED 触摸"按住"语义低（CST820/FT3168 均可读持续按压）若只有按下/抬起事件，用状态机保持
StickS3 电池仅 250 mAh低（持续 Wi-Fi TX 耗电较快）空闲心跳降频 + 屏幕超时熄灭
两板同时上电抢信道低抢占仲裁（06 节）天然覆盖

11 / 里程碑

M1 双端自检各自跑通 mic→codec→speaker 本地回声，验证两板音频链路
M2 单向语音StickS3 说 → AMOLED 放，实测吞吐/丢包/延迟
M3 双向 PTT信令 + 抢占仲裁 + 发送静音，完整对讲体验
M4 加固时钟弹性缓冲、心跳掉线检测、UI 打磨、可选 CCMP 加密

每个里程碑独立可验证、可单独烧录演示，与既有"下载到 work → 烧录 → 记 HTML → push"流水线完全一致。
