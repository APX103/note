固件方案：基于小智（xiaozhi-esp32）分级改造

固件策略一句话：不从零写一行音频代码，全部站在小智开源固件肩膀上；而且 Demo 阶段可以做到"零固件改动"——录音留存这件事，在服务器侧收流落盘即可完成。本文给出 L0/L1/L2 三级改造路线，按验证进度逐级投入。

开源合规提示：xiaozhi-esp32 采用宽松开源协议（以仓库 LICENSE 为准，当前为 MIT），允许商用与闭源修改，但需保留版权声明。量产前在固件 About/官网放置合规声明即可。改造建议以 fork + 私有仓库维护，定期同步上游（上游修 bug、适配新板型，白捡）。

2L0–L2 分级改造路线（核心策略）

L0 · 零固件改动 对应 06 篇 Demo 第 1 周

淘宝成品机刷小智官方固件（或出厂自带），仅把 服务器地址指向我们自建的 xiaozhi-esp32-server。对话、童声、故事全部由服务器侧配置实现；录音全量留存由服务器收流时落盘实现（设备根本不知道自己在被存档）。

✔ 两周 Demo 达成 ✔ 零 C 开发 ✘ 按键交互是成品的（按住说话松开发送） ✘ 断网本地故事暂无
L1 · 配置级改造 对应 06 篇 Demo 第 2 周（可选）

在小智固件已有能力里做配置组合：预置离线故事包（flash 存 MP3，改 Makefile 分区表 + 资源打包）、调整按键映射（板型配置文件）、音量上限限幅。不写复杂新逻辑，改配置、加资源、重新编译烧录。

✔ 断网也有故事（红线兜底） ✔ 需 1–2 天 ESP-IDF 编译经验
L2 · 深度改造（种子家庭版起） 对应 09 篇路线图 Phase 2

实现完整 PRD 交互：多段录音状态机、本地缓存回放、断网录音暂存补传、3 键+长按组合、状态灯效协议、电量上报。工作量见第 8 节；建议此阶段引入固件工程师或外包。

3按键与录音状态机（L2 规格）

stateDiagram-v2 [*] --> 待机 待机 --> 录音中 : 按下录音键 录音中 --> 录音暂停 : 松开（3s内可再按续录） 录音暂停 --> 录音中 : 再按录音键（续段拼接） 录音暂停 --> 已封口 : 静默超时5s 自动封口 录音中 --> 已封口 : 静默超时5s 自动封口 已封口 --> 上传中 : 按发送键 已封口 --> 本地回放 : 按回放键 本地回放 --> 已封口 : 播放结束 上传中 --> AI思考 : 上传完成 AI思考 --> 播报中 : 首包音频到达 播报中 --> 待机 : 播报完成 上传中 --> 待机 : 失败→本地暂存提示重试

关键实现细节

  • 多段拼接：设备只做"分段缓存 + 顺序上传"，拼接与静默裁剪在服务器侧完成（对齐 ASR 时间戳），固件复杂度大幅下降。每段独立 Opus 帧，段间插入 200ms 静音标记。
  • 自动封口：录音中 VAD 检测连续静默 5s → "叮"提示音 → 进入已封口态。孩子无需理解"说完了要干嘛"。
  • 本地回放：已封口的缓存直接送解码器播放，不经网络——即时、可反复（复读机快乐，S2）。
  • 长按组合（L2 后期）：长按发送 2s = 故事模式；长按回放 2s = 时光机（向服务器要一条历史录音+AI 点评）。
  • 播放中抢话：L2 初期半双工（播放时新录音排队）；后续启用 AEC 全双工打断。
  • 童锁防误触：播报中按键只做"暂停/继续"，不误触发上传。

4录音上传通道（安全设计）

原则：设备不直连 OSS。云存储密钥永不下发到设备（儿童玩具被拆解提取密钥是真实风险）。所有音频经已鉴权的 WebSocket/TLS 通道发给 Agent 服务器，由服务器写 OSS。

上行消息（WebSocket JSON 控制帧 + 二进制音频帧）: { "type": "session.start", "device_id": "ECHO-XXXX", "segments": 3, "codec": "opus/16000/16k", "local_id": "20260918-1530-001" } <binary: opus frames...> { "type": "session.end", "duration_ms": 12400 } 服务器确认: { "type": "session.ack", "local_id": "20260918-1530-001", "archive_id": "rec_9f3a2c", "transcript_ready": true }
  • · 幂等去重：local_id 保证断网重传不产生重复存档。
  • · 断网暂存（L2）：音频段写 LittleFS（flash 预留 4MB 分区，≥ 500 段），联网后按序补传，家长端时间线无洞。
  • · 通道复用：L0 阶段对话流与存档是同一条流——服务器收到即落盘，天然全量留存。

5离线故事包（"永不中断"红线的兜底）

资源规格flash 预留 4–8MB 分区；Opus 24kbps 单文件；预置 20 个经典故事 ≈ 1 小时 ≈ 10MB（N16R8 模组 flash 16MB 充裕）
触发条件① 断网 ② 服务端额度/故障降级指令 ③ 音量键+回放键组合（彩蛋直通）
更新机制WiFi 空闲时 OTA 增量更新故事包（服务器可配置内容与顺序）

降级体验设计：断网时童声提示（本地预录 TTS 片段）"网络在睡觉，我先给你讲个故事吧"→ 直接开讲。孩子永远听不到"错误""失败""充值"这类词——这是把竞品"讲到一半要充值"的崩塌体验反过来做成口碑的细节。

6配网、绑定与 OTA

环节方案体验目标
首次配网复用小智配网（SoftAP/蓝牙 + 微信小程序或浏览器页面输 WiFi）祖辈也能完成：开机 → 手机扫码 → 选 WiFi → 30s 内连上
设备绑定设备屏幕/贴纸印二维码（设备指纹签名），家长扫码 → 绑定家庭 → 监护人同意流程（合规必需）绑定即完成《儿童个人信息保护》告知同意，全程 < 1 分钟
断网恢复记忆重连 + 指数退避；重连期间自动进入本地故事降级路由器重启不打断睡前故事
OTA小智 OTA 通道 + 灰度发布（1% → 10% → 全量）+ 版本回滚出问题远程救砖，不产生退货
日志回捞家长授权后触发设备上传运行日志（脱敏）客服排障不靠猜

7资源预算与音频规格

音频规格（全链路统一）

  • · 采样率 16kHz 单声道（ASR 与存档够用，省带宽）
  • · Opus 16–24kbps：上行对话 16k，故事/回放 24k
  • · 存档双份：Opus（播放用）+ 转写文本（检索用）
  • · AGC 目标电平 -18dBFS；VAD 阈值按童声调校

ESP32-S3 资源预算（N16R8）

  • · RAM：音频缓冲 + Opus + TLS ≈ 预算内（小智已验证）
  • · PSRAM 8MB：断网暂存缓冲、故事包缓存充裕
  • · Flash 16MB：固件 3MB + 故事包 8MB + 暂存 4MB 分区
  • · 功耗：活跃 ≈ 300mA，待机呼吸灯 < 50mA——2000mAh 足够
