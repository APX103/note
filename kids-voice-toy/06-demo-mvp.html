Demo 最简实现路径：14 天，<¥800，零焊接，几乎零固件改动

这一篇回答你上一版方案最大的两个问题：成本没降到最低、Demo 没做到最简。本次的解法是——硬件买现成品、固件不改一行、录音留存放到服务器侧做、家长端只做一个页面。全部自研工作量收敛到：部署一个开源服务器 + 一次配置 + 两个小脚本 + 一个单页 H5。

1Demo 要验证的三个假设（不多不少）

假设一 · 孩子侧

孩子对"按键说话 + 可爱童声回应 + 能听自己录音"的玩具，第 7 天仍主动去按——而不是像以前的 AI 玩具一样吃灰。

假设二 · 家长侧

妈妈看到"手机上按时间线回听孩子说的话"时情绪反应强烈（笑出声/转发给爸爸/反复回放）——这是买单意愿的直接前兆。

假设三 · 技术侧

小智生态（固件+服务器）改造成本的判断成立：一个下午能部署、一周能定制，对话质量（ASR 童声识别 + 人设）达到"孩子愿意继续聊"的水平。

Demo 明确不验证：续航、外壳颜值、量产成本、3C、按键 A/B 方案、支付——这些全部后置。Demo 只验证"孩子玩不玩、妈妈动不动心"。

2五条最简原则（本方案与上一版的本质区别）

1

能买不焊：设备直接淘宝买小智兼容成品机（¥79–168）。不上开发板、不焊 INMP441、不画 PCB——那些是内测阶段的事。

2

能不改就不改：固件零改动（L0 路线）。设备交互先用成品的"按住说话"，我们自定义的多段录音交互等验证完核心价值再说。

3

能用别人的服务就不自建：ASR/LLM/TTS 全部 API；录音存储先落服务器本地磁盘，OSS 都可以后接。

4

能服务器侧做就不动设备："全量录音留存"在服务器收流时落盘实现——设备完全无感知，这就是最简。

5

能一页就不做三页：家长端 Demo = 单页 H5（时间线+播放器），三天写完，样式从简。

314 天 Day-by-Day 计划

第一周：让设备开口说话，让录音留下来
Day 1–2
采购与开户
  • · 淘宝下单小智兼容整机 ×2（关键词与买前确认清单见 02 篇档位 A；买 2 台，1 台试错 1 台备用）
  • · 注册：DeepSeek（LLM）、火山引擎（ASR 免费额度）、腾讯/阿里轻量云 4C8G（月付 ~¥100，选国内节点延迟低）
  • · 域名一个（或先用云厂商免费二级域名 + 自动 HTTPS）
Day 3–4
部署自建小智服务器
  • · GitHub 拉取 xiaozhi-esp32-server，docker-compose 一键起（含 Web 管理台）
  • · 配 Provider：ASR=火山流式（或 FunASR 容器）、LLM=DeepSeek、TTS=Edge-TTS（音色 zh-CN-xiaoyi）
  • · 设备切到自建服务器（成品机 OTA 换 server 地址 / 刷官方固件填自己域名；06 篇避坑①）
  • · 验收：孩子按住说话 → 软萌童声回复。到这一步已有一台"能聊天的玩具"
Day 5–6
录音全量落盘（自研第一块，约 60 行代码）
  • · 在服务器收流回调处挂旁路：会话音频 → 拼 OPUS 文件 → 本地磁盘；ASR 转写结果入库（SQLite）
  • · 批处理脚本：LLM 给每条打 3 个标签（话题/情绪/可爱分）——晚上跑批，白天陪玩
  • · 验收：说 10 句话后，磁盘上有 10 个音频文件 + 10 条带标签的转写记录
Day 7
周末实战 #1：交给第一个家庭（宝妈 + 女儿）开始 7 天真实使用。给妈妈的唯一任务：什么都不用做，第 7 天一起听听回放。
第二周：让妈妈看到价值，让人设定型
Day 8–9
家长端单页 H5（自研第二块，2 天）
  • · 一个 HTML 页面 + 3 个接口（04 篇 API 表）：按日列表 / 签名播放 URL / 收藏
  • · 手机浏览器打开即用；播放按钮做成大圆钮（05 篇线框图直接照抄）
  • · 验收：妈妈手机上点开，3 秒内听到女儿的声音——观察她的表情，这是 Demo 最重要的时刻
Day 10–11
Agent 人设与安全调优
  • · 挂上 04 篇系统 Prompt，按女儿的真实反应迭代语气（每晚饭后听当天录音找问题）
  • · 输入输出接关键词过滤（自建儿童词表第一版）；敏感话题兜底话术灌入
  • · 故事模式：预置 20 个公版故事文本 → Edge-TTS 批量生成缓存，点播秒回
Day 12–13
时光机首秀（差异化时刻）
  • · 最简实现：H5 加"随机回放一条 7 天前的录音"按钮 + LLM 生成一句点评拼在播放后
  • · 给孩子演示："还记得你上周说的话吗？"→ 玩具放出她自己的原声——拍下这一刻（就是抖音第一条素材，见 08 篇）
Day 14
复盘与 Go/No-Go：拉数据（使用次数/天数）、访谈妈妈（愿不愿意推荐/买）、逐条过判据（第 4 节）→ 决定进入小批量（09 篇 Phase 2）或调整方向。
排期假设：执行人 = 你 1 人 + AI 编程工具全开（这一版的代码量就两个脚本 + 一个页面，完全在个人可完成范围）；宝妈家庭配合成本低（她本来就想做这个产品）。如果 Day 4 结束设备还不能对话，立即检查 02 篇避坑清单，必要时换第二台机型——不要在一台机器上耗超过 1 天。

4Go / No-Go 判据（提前写死，防止自我感动）

指标Go（继续）调整后重来No-Go（停）

6避坑清单（每一条都是别人真金白银踩过的）

① 成品机锁服务器：部分淘宝"小智 AI"成品机固件锁死官方服务器、无 OTA 改址入口。下单前让客服确认"能否连接自建服务器/能否刷机"，收货第一时间验证；被锁就直接走"USB 刷官方小智固件"路线（需看板型是否有适配，02 篇买前确认三问）。
② 板型不适配：冷门板子可能没有小智固件适配包。优先选社区支持列表里的热门板型（面包板/虾哥机等大众款），别贪便宜买"同价位配置更高"的杂牌。
③ Edge-TTS 限流：免费通道有并发/频率限制，故事批量生成会 429。批处理加退避重试、错峰夜间跑；正式售卖前必须切商用 TTS（04 篇组合 B）。
④ ASR 对童声的挫败：幼儿发音不清会导致识别稀碎、AI 答非所问，孩子立刻失去兴趣。若火山识别童声效果差：切换/混用 FunASR 中文模型，或 Prompt 里告诉 LLM"你听到的是转写可能不准的小孩子话，听不懂就温柔地请她再说一遍"——把识别缺陷转化成"玩具没听清"的自然交互。
⑤ 家庭 WiFi 的 2.4G：ESP32 只支持 2.4GHz。给种子家庭的第一条语音提示："请连 2.4G 的 WiFi"——这是未来量产退货的头号来源，Demo 就要开始记录这类摩擦。
⑥ 录音同意：哪怕 Demo 阶段，也向家庭明确"所有录音存在你自己服务器上、仅项目组可见"——既是尊重，也是给自己习惯合规流程。
