VISUAL SPEECH RECOGNITION / LIP READING · 2026-10

视频没有音频，
机器能「看」出人说了什么吗？

想从一个没有音轨的视频里识别出说话内容——不能走 ASR，只能靠画面。这个方向存在且活跃了十年，学名叫唇读 / 视觉语音识别（Visual Speech Recognition, VSR）。结论先行：能做到，但精度分场景差出一个数量级——英文开放句子最好 ~20% 词错率、中文句子级 ~30% 字错率、而把词表缩到几十条命令词则能做到 95%+ 准确率且可跑在端侧。本文核对了两套主流开源框架的官方数字、中文数据集现状，并给出四条落地路线的拍板。

整理：2026-10-23基线：Auto-AVSR / AV-HuBERT 官方仓库 + 论文实勘结论：结题不立项 — 需求为零错误率「指哪打哪」，VSR 物理不可达；笔记留档备查

00 / TL;DR结论速览与拍板

能做到。「看视频猜说了什么」是正经的研究领域（lip reading / VSR），从 2016 年 LipNet 端到端建模算起，深度学习路线已推进十年，开源世界有两套事实标准框架（Auto-AVSR、AV-HuBERT），模型已能在英文基准上超过专业人类唇读员。但它不是魔法——唇形只是语音的有损投影（很多音素口型相同、中文声调完全不可见），所以精度天花板由场景的「词表大小 + 语言先验强弱」决定。按场景拍板：

你想要什么可行性推荐路线
英文短句转写（demo / 糊转写喂 LLM）可行，糊但能用Auto-AVSR 视觉 checkpoint（WER 20~25%）+ LLM 后处理纠错
中文开放句子逐字转写demo 可，产品勉强无现成中文预训练模型——需在 CMLR/LRW-1000 上自炼；预期 CER ~30% 起，实况更差
中文命令词交互（机器人 / 无障碍 / 安静场景）可行，且能上端侧自研：MediaPipe 唇部 468 关键点 → 轻量序列模型（GRU/TCN）→ N 类命令，预期 95%+
其实有音频、只是环境嘈杂强烈推荐换赛道音视频融合（AVSR）：同一框架下 WER 直降一个数量级到 0.8~2%

诚实的边界：「无差错逐字转写」不存在，这不是工程问题而是信息论问题——嘴唇可见信息量就那么多，剩下的全靠语言模型先验脑补。正确的产品姿势是把 VSR 输出当「模糊查询/意图候选」交给下游 LLM 消歧，而不是当精确字幕用。

结题记录（2026-10-23）：需求判定为「鼠标级指哪打哪、错误率≈0」的精确输入，与 VSR 的物理上限不匹配，不立项，本笔记留档备查。若未来仍需要「无声的精确输入」，正确方向是手势/指向（IMU 空鼠路线已验证指哪打哪）或按键类通道，而非读唇。

01 / DEFINITION这是什么：术语澄清与物理上限

术语：不是「面部识别」

需求口语里说的「通过面部识别看懂说的话」，对应的学术术语是唇读（lip reading），也叫视觉语音识别（VSR）或 visual-only ASR。相邻概念先分清楚，调研时不至于串台：

术语输入与本题关系
VSR / lip reading（唇读）只有视频（唇部）就是本题
AVSR（音视频融合）视频 + 音频不是本题，但常被论文数字混淆——媒体常把 AV 成绩当「读唇突破」宣传
Silent Speech Interface（无声语音接口）表面肌电 EMG / 舌超声 / 脑电等另一条技术路线，贴传感器读肌肉/舌头信号，精度更高但需要穿戴设备
人脸识别 / 表情识别图像认人、认情绪，不认「说了什么」——与本题无关

为什么难：viseme 多对一 + 声调不可见

语音→口型的映射是多对一的：发声位置看不见，只看得见唇/颌的动作。经典的 viseme 研究结论是英语约 40+ 个音素只对应十几个可区分口型（viseme）——/p/ /b/ /m/ 都是双唇闭合，/t/ /d/ /n/ 唇形几乎一样。也就是说从口型反推音素本身就是一个欠定问题，模型必须靠语言统计先验（这个词后面更可能接什么）来消歧。这对中文是双重打击：

  • 声调完全不可见——「十 / 时 / 是 / 事」口型一致，四声全靠猜；
  • 同音字海量——音素级已经欠定，字级更是雪上加霜。

人类对照：专业唇读员对连贯语料的理解率通常也就三到五成（还要靠上下文和重放）。机器在受控基准上已经超过这个水平——但基准是新闻播报域的正面清晰视频，落到实况（侧脸、逆光、胡子）会显著退化。

两个读数陷阱要避开：① 搜「lip reading SOTA」常看到 0.8% WER——那是 Burchi & Vielzeuf 2024（arXiv:2405.12983）的音视频融合成绩，不是纯视觉，本文已核对原文；② Auto-AVSR 仓库里有个 vsr_trlrs3_23h checkpoint 是 93% WER——那是「只用 23h 标签」的消融实验款，别下错，要用 vsr_trlrs2lrs3vox2avsp。

中文（比英文难一档，数据也少一档）

基准规模当前水平（参考点）
CMLR（浙大，句子级）10.2 万句，央视新闻域CER ~30% 量级（如知识蒸馏方法 31.27%）；「视频→拼音→汉字」两阶段（LipCH-Net）是主流解法之一
LRW-1000 / CAS-VSR-W1k（中科院计算所，词级）1000 词类、2000+ 说话人、~70 万段中文词级最大公开基准，自然环境
CCTVDS（软件学报工作）1.5 万样本、20.95GB为绕开数据缺失自建的半自动语料

中文的现状一句话：基准存在、公开预训练模型基本缺失。英文能直接下载 20% WER 的 checkpoint，中文得自己在 CMLR/LRW-1000 上炼——而声调不可见 + 同音字意味着同样数据量下 CER 天然比英文 WER 高。

把词表缩小，世界立刻美好

VSR 的难度几乎全部来自开放词表。一旦任务收窄为「从 10~50 条命令里选一条」（口令、数字、确认/否认），欠定问题变成封闭分类问题，语言先验不再需要脑补开放文本：LipNet 2016 年就在 51 词的 GRID 上做到 4.8% WER；近十年的关键点 + 轻量序列模型方案在几十词命令集上普遍能到个位数错误率。这是嵌入式/机器人场景真正的甜点区。

03 / PIPELINE技术原理：一条标准流水线

所有主流 VSR 系统都可以拆成同一条链，差异只在每一环的选型：

视频帧流（25fps 是事实标准）
   │  ① 人脸检测与跟踪（每帧）
   ▼
② 唇部表征：裁剪嘴部 ROI（96×96 灰度图，端到端派）
              或 唇部关键点序列（MediaPipe FaceMesh 468 点中取嘴部 ~40 点，轻量派）
   ▼
③ 视觉前端：3D/2D 时序卷积（ResNet-18 变体）或直接吃关键点坐标
   ▼
④ 序列编码：Conformer / Transformer（自监督预训练是主流）
   ▼
⑤ 解码：CTC / RNN-T / 自回归注意力
   ▼
⑥ （可选）外部语言模型 / LLM 后处理：对口型歧义做消歧纠错

三个流派值得知道：

  • 自监督表征派（AV-HuBERT）：掩码建模预训练音视频表征，唇读/AVSR/语音翻译一套表征通吃，Meta 2022，比之前最好成绩提升约 20%；
  • 数据规模化派（Auto-AVSR）：用现成 ASR 自动标注海量网络视频（VoxCeleb2、AVSpeech），把训练数据从 438h 堆到 3291h，WER 从 36% 压到 20.3%——这行本质是数据生意；
  • LLM 化派（2024~）：VSP-LLM 把视觉语音编码器接进 Mistral 7B 做连续唇读和视觉语音翻译；VALLR（2025）把 Whisper 架构改造成视觉 ASR 语言模型；另有工作证明「把 Whisper 这类强 ASR 改造成唇读器」比从头训更强。趋势明确：唇读的下一步是把解码器换成语言模型——恰好对症 viseme 欠定这个老病根。

中文侧只有数据集、没有能直接下载的句子级预训练模型（这是本次调研明确的最大缺口）：CMLR（浙大，10.2 万句新闻）、LRW-1000/CAS-VSR-W1k（计算所，1000 词类 × 2000 人 × 70 万段，中文词级最大）、CCTVDS（软件学报自建）。商用侧（公安场景的中文唇语识别公司、国外 Liopa 等）全部闭源、不可验证，按不存在处理。

算力参考：推理一个 250M 的视觉模型，单张消费级 GPU（或 Apple Silicon MPS）绰绰有余；真正贵的是预训练（Auto-AVSR 默认 4 节点 × 8 GPU）。自采小数据微调 / 小词表自研模型，一张卡甚至 CPU 就能闭环。

05 / ROUTES四条落地路线

路线 A：直接用 Auto-AVSR（英文转写）

拿 vsr_trlrs2lrs3vox2avsp_base.pth（20.3% WER）对视频推理，输出英文句子。适合英文 demo、或「糊转写 + LLM 纠错」的流水线——20% WER 的句子再交给 LLM 按上下文修，对「看懂大意」够用，对逐字精确不够。成本：一张 GPU + 官方 notebook 改造半天。

路线 B：VLM API 零样本读唇（10 分钟可证伪）

GPT-4o / Gemini 都收无声视频。拿 10 段自己录的清晰正面短句试一下：短词、数字、问候语大概率能蒙对不少，长句基本靠编。MLLM 语音能力评估的文献结论一致——通用多模态模型零样本唇读显著弱于专用 VSR 模型（VSP-LLM 的动机正在于此：给 MLLM 外挂视觉语音编码器）。这条路线的价值是「零成本验证需求」，不是生产。

路线 C：自研小词表命令识别（机器人/端侧场景，推荐）

需求收窄为「从 ≤20 条命令里分类」后，自研完全可行，且符合端侧约束：

摄像头 25fps → MediaPipe FaceMesh（手机/树莓派 ~30fps 无压力）
   → 取唇部 ~40 个关键点，做平移/尺度/旋转归一化
   → 滑窗 0.5~1.0s 片段 → 2 层 GRU 或小 TCN（参数量 <1M）
   → N 类命令 + 1 类「非命令」
数据：每条命令自录 50 遍 × 2~3 个使用者 ≈ 半天采集
预期：封闭词表错误率个位数；做说话人校准后 95%+ 常见

关键点路线不吃像素，对光照和背景天然鲁棒，量化后甚至能塞进 ESP32-S3 级别 MCU 的伴生算力（关键点检测跑在主机/协处理器上）。

路线 D：音频其实可得 → 音视频融合

如果「没音频」只是暂时约束（嘈杂、静音场景），AVSR 是收益最大的一步：同一框架下 WER 从 20.3% 直落到 0.8~2%，对噪声的鲁棒性也远好于纯音频。Auto-AVSR 提供 AV 模型可直接用。产品决策前先问一句：音频真的拿不到吗？

06 / RISKS风险与坑清单

  • 拍摄条件敏感：正面 ±30° 以内、光照均匀、距离适中是基准前提；侧脸、逆光、大角度直接崩。胡子、口罩、麦克风遮挡嘴唇=直接出局；
  • 说话人差异：每个人嘴唇形状和说话习惯不同，跨说话人泛化是主要掉分点；小词表方案强烈建议做「每人 5 分钟校准数据」；
  • 静音段幻觉：CTC/自回归模型对着不动嘴也可能脑补出词，工程上需要 VAD 式的「说话活动检测」门控（唇部关键点幅度就能做）；
  • 流式实时是研究前沿：主流模型按切段离线跑；真正的流式 VSR（边说边出）仍是论文区，产品上用滑窗切段绕过；
  • 中文特别坑：声调不可见 + 同音字，直出汉字错误率难看；「视频→拼音→汉字两阶段 + LLM 消歧」是文献验证过的缓解路线；
  • 数字引用坑：见到惊人好成绩先查是不是 AV 融合（0.8% 那种）或受限词表（GRID 4.8% 那种），再和自己的场景对号；
  • 隐私与伦理：唇读等于「隔着距离偷听话」，面纹是生物特征——自研系统数据留在本地，别把用户口型视频传第三方 API（这也是路线 B 只适合验证、不适合生产的原因之一）。

07 / VERDICT拍板与 MVP 建议

总判定：技术上成立，产品上必须按场景收窄。建议的决策顺序：

  1. 先证伪需求（10 分钟）：录 10 段目标短语的无声视频，丢给 GPT-4o/Gemini 看蒙对率。蒙对率连大意都覆盖不了 → 说明目标场景对 VSR 太难，及时止损；
  2. 若目标是英文转写（1 天）：Auto-AVSR checkpoint + 官方 inference notebook 跑通，输出接 LLM 纠错；
  3. 若目标是中文命令词交互（1 周，推荐）：路线 C 自研。命令表 ≤20 条，MediaPipe 关键点 + GRU，自采数据半天、训练半天、端侧部署一天——错误率预期个位数，配合「非命令」类和确认机制可产品化。家庭机器人这类「看口型确认唤醒/静音下发指令」的场景，这条路线的性价比最高；
  4. 任何时候拿得到音频：立刻切 AV 融合，别硬啃纯视觉。

再强调一次定位：VSR 输出是「候选意图」不是「精确转写」。系统设计上永远给一条兜底通道（按钮/语音/重试），唇读作为增强而非唯一输入，用户的体验预期就立得住。
