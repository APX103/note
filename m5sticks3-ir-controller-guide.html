0. 整体流程总览

整个项目只有六步，每一步都可以独立验证，不要跳步：

  1. 确认目标：你的空调是什么品牌/协议（决定选方案 A 还是 B）。
  2. 了解硬件：板载红外的引脚、器件特性、使用限制（发射距离、载波）。
  3. 搭环境：安装 Arduino CLI、M5Stack 板包、红外库。
  4. 写最小程序：先发一帧已知信号，把"发射→接收"链路打通（这是最关键的一步）。
  5. 实现功能：按选定的方案（生成帧 / 学习回放）写出完整控制器。
  6. 实测固化：近距离对准空调验证，然后固化使用姿势（距离、按键习惯）。
最重要的原则：先打通链路，再堆功能。第一步不要写任何业务逻辑，只验证"设备能不能发出一段空调认识的信号"。

1. 认识硬件：StickS3 的红外能力

1.1 引脚与器件

功能引脚板载器件特性
IR 发射 TXGPIO46Everlight IR928-6C（940nm 红外管）单管 + 22Ω 限流，功率较小，高电平点亮
IR 接收 RXGPIO42Vishay VSOP38338（38kHz 解调接收头）内置 AGC + 带通滤波，active-low 输出，10K 上拉

1.2 必须先知道的四条使用特性

① 发射距离短，必须近距离正对

板载红外管功率小，有效发射距离 ≤ 30-50cm，且要正对设备的红外接收窗（空调面板右下角的暗红色小窗）。这是设备固有特性，不是软件能解决的。

② 接收目标距离 30-100cm

接收头带 AGC，信号太近（<20cm）会饱和导致波形失真，太远信号弱。学习时把遥控器/手机放在 30-100cm 处最稳。

③ 载波 38kHz

接收头对 38kHz 载波最灵敏（带宽约 ±2-3kHz）。你的信号源（遥控器/手机 App）应使用 38kHz 载波。

④ 供电与干扰

代码里必须先 M5.Power.setExtOutput(true, m5::ext_none); 给板载红外供电，并调用 M5.Speaker.end(); 关闭扬声器功放（功放会干扰 IR 接收）。

3. 方案选型：生成帧 vs 学习回放

做 AC 控制器有两条完全不同的路，先选路再动手：

方案 A：库生成标准帧直发方案 B：学习 + 回放
原理库内置该品牌协议，用代码生成一帧标准波形发送捕获遥控器的原始波形，原样重放
前提你的空调品牌在库的协议表里（Panasonic/Gree/Haier/Midea…）任意品牌、任意按键，只要捕获质量好
稳定性最稳 波形教科书级，空调一定认识依赖学习时捕获质量（容易受距离/AGC 影响）
灵活性可程序化生成任意温度/模式/风速组合只能重放录过的按键
推荐首选协议不在库里的备选
判定方法：先把库支持列表看一遍（ESP32IRPulseKit 的 ac/ 目录），找到你空调品牌就用方案 A；找不到再用方案 B。绝大多数主流空调都能在 A 里找到。

4. 方案 A：库生成标准帧直发（推荐）

以 Haier 空调为例，完整可编译的 sketch（K1 短按 = 开关，K2 长按 = 关机）：

示例代码text
#include <M5Unified.h>
#include <ESP32IRPulseKit.h>

constexpr uint16_t IR_TX_PIN = 46;
constexpr uint16_t IR_RX_PIN = 42;

esp32irpk::IRSender tx(IR_TX_PIN);
esp32irpk::IRReceiver rx(IR_RX_PIN, false);

void setup() {
  M5.begin();
  Serial.begin(115200);
  delay(200);

  M5.Power.setExtOutput(true, m5::ext_none);  // 给板载红外供电
  delay(100);
  M5.Speaker.end();                           // 关功放，避免干扰 IR

  // 发送端：长帧建议关闭相位对齐载波、加大 RMT 内存
  tx.setTxMemBlocks(2);
  tx.setPhaseAlignedCarrier(false);
  tx.begin();

  Serial.println("K1: 开关   K2长按: 关机");
}

void loop() {
  M5.update();

  if (M5.BtnB.pressedFor(1000)) {
    Serial.println("power off");
    M5.Power.powerOff();
  }

  if (M5.BtnA.wasPressed()) {
    sendToggle();
  }
  delay(10);
}

static bool powerOn = false;  // 交替开/关
void sendToggle() {
  powerOn = !powerOn;

  // 库生成一帧教科书级 Haier 帧（完整头部 + 正确校验和）
  esp32irpk::ac::Haier::Frame f;   // 默认 制冷24°C / 风速自动
  f.setPower(powerOn);

  uint16_t ticks[esp32irpk::ac::Haier::Frame::kMaxTicks];
  esp32irpk::IRRawTickBuffer buf{ticks, esp32irpk::ac::Haier::Frame::kMaxTicks, 0};
  if (!f.toRaw(buf)) {
    Serial.println("encode failed");
    return;
  }
  esp32irpk::IRRawTickView view{buf.ticks, buf.len};

  // 连发 3 次（模拟真实遥控器重复行为），提高空调命中率
  for (int i = 0; i < 3; i++) {
    tx.send(view);
    delay(80);
  }
  Serial.printf("sent Haier %s\n", powerOn ? "ON" : "OFF");
}

4.2 关键概念：一次"开机"发出去的是整包状态

空调红外和电视遥控器完全不同：电视发的是"命令码"（比如"音量+"），而空调每一帧发的是完整的设备状态快照——模式、温度、风速、风向、开/关，全部打包在一个帧里，一次发射出去。

以 Haier 为例，一帧固定 9 字节（72 位），字段分布如下：

字节内容示例值
0固定前缀 0xA5（协议识别）0xA5
1开/关命令（低 4 位）+ 温度（高 4 位，16-30°C）0x81 = 开 + 24°C
2固定标志位 + 上下摆风0x20 = 摆风关
3-5固定位 / 风速 / 其他标志…
6模式（高 3 位）+ 其他0x20 = 制冷
7保留0x00
8校验和（前 8 字节求和，取低 8 位）0x72

所以"按一下开关"并不是发一个单独的"开"命令，而是把这 9 字节整体打包成一帧波形发送：其中只有字节 1 的 command 字段从"关"改成"开"，温度 / 模式 / 风速 / 风向这些字段原样跟着这一帧一起上传。由此推出三条实操结论：

  • 每次发出去的都是完整快照——不存在"只改开关、其他不变"的单独命令，所以开机前必须先想好整套参数。
  • 想换温度 / 模式 = 重新生成一帧（改 setter 再 toRaw，或加按键循环不同参数）；旧帧里的温度是固定的。
  • 不同品牌帧长 / 字段位置不同（Haier 9 字节、Gree 8 字节、Panasonic 27 字节…），但"整包状态"这个模型完全一致。

对应到代码里一目了然：f.setTemperatureC(26) 只是改帧里温度字段，f.toRaw() 把整帧编成 mark/space 波形，tx.send() 一次性全部发出。

4.3 修改成你的空调设置

库每个品牌都提供 setter，直接改默认帧即可生成你想要的模式/温度：

示例代码text
esp32irpk::ac::Haier::Frame f;
f.setPower(true);
f.setMode(esp32irpk::ac::Haier::Mode::COOL);   // COOL / HEAT / DRY / FAN / AUTO
f.setTemperatureC(26);                          // 16-30°C
f.setFan(esp32irpk::ac::Haier::Fan::AUTO);      // AUTO / LOW / MED / HIGH
f.setSwingV(esp32irpk::ac::Haier::SwingV::OFF); // OFF / UP / DOWN / CYCLE

不同品牌命名略有差异（如 Gree 用 ac::Gree::Mode::COOL），但结构完全一致。

4.4 完整源码（可直接编译运行）

以下是一个完整可编译的版本，包含方案 A（K1 短按生成标准 Haier 帧开关）与备用的学习路径（K1 长按进入学习）。复制后按 sketch.ino 保存为同名文件夹即可用 arduino-cli 编译：

m5stick_s3_ir_toggle_remote.inoArduino C++完整可编译 · 方案 A 全功能（生成帧直发 + 学习备选）
// M5StickS3 Single-Button IR Toggle Remote
// ==========================================
// One-key infrared remote for M5StickS3.
//
// Button mapping (M5StickS3 front face):
//   K1 (GPIO11) -> M5.BtnA
//   K2 (GPIO12) -> M5.BtnB
//
// Behavior:
//   K1 short press : send the stored toggle IR frame (on/off)
//   K1 long press  : learn a new toggle IR frame from the on-board IR receiver
//   K2 long press  : power off the device via M5.Power.powerOff()
//
// The learned frame is saved to LittleFS as /toggle.bin.
//
// Hardware: M5StickS3 (ESP32-S3)
// IR TX: GPIO46 (on-board)
// IR RX: GPIO42 (on-board)
// K1   : GPIO11
// K2   : GPIO12
//
// Arduino IDE settings:
//   Board: M5Stack -> M5StickS3
//   Partition Scheme: 8M with spiffs (3MB APP/1.5MB SPIFFS)
//   Libraries: M5Unified, M5GFX, ESP32IRPulseKit

#include <M5Unified.h>
#include <ESP32IRPulseKit.h>
#include <LittleFS.h>

constexpr uint16_t IR_TX_PIN = 46;
constexpr uint16_t IR_RX_PIN = 42;

// On-board IR LED / receiver.
// M5StickS3 on-board receiver is active-high (idle low, mark high),
// so inverted=false. If you wire an external VS1838B module, use true.
esp32irpk::IRSender  tx(IR_TX_PIN);
esp32irpk::IRReceiver rx(IR_RX_PIN, false);

// Minimum ticks for a valid AC frame. A repeat frame is usually < 10 ticks;
// a real AC state frame is usually 100~400 ticks.
constexpr size_t MIN_TOGGLE_TICKS = 50;

const char *TOGGLE_FILE = "/toggle.bin";

constexpr size_t MAX_TICKS = 1024;
uint16_t tickBuffer[MAX_TICKS];

enum class State {
  IDLE,
  LEARNING,
};

State state = State::IDLE;
uint32_t learnStartMs = 0;
bool k1LongTriggered = false;

// Best-capture accumulator for learning: the phone remote can only be tapped
// repeatedly (each tap sends one frame), and the receiver's AGC settles
// differently per tap. Instead of saving the first plausible capture, we keep
// the cleanest one seen and auto-save it once we have a couple of taps.
uint16_t bestTicks[MAX_TICKS];
size_t bestLen = 0;
int bestScore = -1;
uint32_t firstGoodMs = 0;

// Cleaned tick buffer used for decode attempts: real captures often contain
// sub-150us glitch pulses from the receiver; merging them into their neighbor
// recovers the underlying mark/space stream so the Haier decoder can walk it.
uint16_t cleanTicks[MAX_TICKS];
size_t cleanLen = 0;

void applyGlitchFilter(const esp32irpk::IRRawTickView &raw) {
  cleanLen = 0;
  for (size_t i = 0; i < raw.len; i++) {
    uint32_t us = (uint32_t)raw.ticks[i] * 10u;
    if (us < 150 && cleanLen > 0) {
      // Merge the glitch into the previous tick (same polarity is fine for a
      // mark/space duration sum; the next tick keeps alternating).
      cleanTicks[cleanLen - 1] = (uint16_t)(cleanTicks[cleanLen - 1] + raw.ticks[i]);
    } else if (cleanLen < MAX_TICKS) {
      cleanTicks[cleanLen++] = raw.ticks[i];
    }
  }
}

// Quality score for a structurally plausible (but undecodable) AC capture:
// data marks ~520us and data spaces ~600-1800us add points, glitch ticks
// (<150us) subtract. A capture that contains the Haier double header
// (3000/3000/3000/4300) anywhere gets a huge bonus: a headerless capture is a
// mid-frame slice that will not be recognized by the AC, so it must never win.
int captureScore(const esp32irpk::IRRawTickView &raw) {
  int score = 0;
  bool hasHeader = false;
  for (size_t i = 0; i + 3 < raw.len; i++) {
    uint32_t a = (uint32_t)raw.ticks[i] * 10u;
    uint32_t b = (uint32_t)raw.ticks[i + 1] * 10u;
    uint32_t c = (uint32_t)raw.ticks[i + 2] * 10u;
    uint32_t d = (uint32_t)raw.ticks[i + 3] * 10u;
    const uint32_t tol = 3000 * 55 / 100; // 55% tolerance, matches library
    if (a + tol >= 3000 && a <= 3000 + tol &&
        b + tol >= 3000 && b <= 3000 + tol &&
        c + tol >= 3000 && c <= 3000 + tol &&
        d + tol >= 4300 && d <= 4300 + tol) {
      hasHeader = true;
      break;
    }
  }
  if (hasHeader) score += 500; // complete frame beats any headerless one
  for (size_t i = 0; i < raw.len; i++) {
    uint32_t us = (uint32_t)raw.ticks[i] * 10u;
    if (us >= 450 && us <= 650) score += 2;        // data mark (~520us)
    else if (us >= 600 && us <= 1800) score += 1;  // data space (0 or 1 bit)
    else if (us < 150) score -= 2;                 // glitch
  }
  return score;
}

void setup() {
  M5.begin();
  Serial.begin(115200);
  delay(200);
  Serial.println("\nM5StickS3 IR Toggle Remote");

  // Power on the on-board IR transceiver.
  M5.Power.setExtOutput(true, m5::ext_none);
  delay(100);

  // Speaker amp disturbs IR RX.
  M5.Speaker.end();

  if (!LittleFS.begin(true)) {
    Serial.println("LittleFS mount failed");
    M5.Display.println("FS mount failed");
    while (true) delay(1000);
  }
  Serial.println("LittleFS OK");

  rx.setMaxRxSymbols(512);
  // M5StickS3 on-board IR receiver merges multiple AC frames with the default
  // 30 ms idle threshold. Drop it to 15 ms so repeated Haier frames are split
  // into separate captures and the first full frame can be decoded.
  rx.setIdleThresholdUs(15000);
  rx.begin();

  // More RMT TX memory blocks reduce the chance of underruns when sending
  // long AC frames under Wi-Fi/BLE interrupt load.
  tx.setTxMemBlocks(2);
  // Phase-aligned carrier has very high symbol throughput; long AC frames are
  // safer with the free-running hardware 38 kHz carrier.
  tx.setPhaseAlignedCarrier(false);
  tx.begin();

  M5.Display.setRotation(3);
  M5.Display.setTextFont(&fonts::FreeMonoBold9pt7b);
  M5.Display.clear();

  drawUI();

  Serial.println("K1 short: send toggle");
  Serial.println("K1 long : learn toggle (tap power 3-4x, 30-100cm)");
  Serial.println("K2 long : power off");
}

void loop() {
  static uint32_t aliveTimer = 0;
  if (millis() - aliveTimer > 5000) {
    aliveTimer = millis();
    Serial.println("alive");
  }

  M5.update();

  // K2 long press -> power off the device.
  if (M5.BtnB.pressedFor(1000)) {
    Serial.println("K2 long press -> powerOff");
    M5.Display.fillRect(0, 120, 240, 60, TFT_BLACK);
    M5.Display.setCursor(0, 120);
    M5.Display.setTextColor(TFT_RED);
    M5.Display.println("Power off...");
    delay(500);
    M5.Power.powerOff();
  }

  // K1 gesture handling.
  if (M5.BtnA.isPressed()) {
    if (!k1LongTriggered && M5.BtnA.pressedFor(1200)) {
      k1LongTriggered = true;
      startLearning();
    }
  } else {
    if (M5.BtnA.wasReleased()) {
      if (!k1LongTriggered) {
        sendToggle();
      }
      k1LongTriggered = false;
    }
  }

  // Learning mode: capture a valid IR frame.
  if (state == State::LEARNING) {
    esp32irpk::IRReceiveResult<4> result;
    if (rx.read(result)) {
      Serial.printf("Captured IR: len=%u flags=%u\n",
                    (unsigned)result.raw.len,
                    (unsigned)static_cast<uint8_t>(result.flags));

      // Clean the waveform before decoding: merge sub-150us glitch pulses so
      // the Haier bit-walk can proceed. Raw-replay still uses the raw ticks.
      applyGlitchFilter(result.raw);
      esp32irpk::IRRawTickView cleanView{cleanTicks, cleanLen};
      Serial.printf("Cleaned: len=%u\n", (unsigned)cleanLen);

      // Try to identify the AC vendor. The return value matters: if any
      // vendor matched, the raw frame is real and safe to save as-is; if none
      // matched we need extra structural checks before trusting the capture.
      esp32irpk::ac::AcVendor vendor = esp32irpk::ac::decodeAny(cleanView, &Serial);

      // If this is a Haier AC frame, re-encode a clean single-frame raw
      // instead of saving whatever the receiver happened to merge together.
      // Decode from the glitch-filtered view so stray short pulses cannot
      // break the bit walk.
      esp32irpk::ac::Haier::Frame haier;
      if (esp32irpk::ac::Haier::Frame::fromRaw(cleanView, haier)) {
        Serial.println("Haier frame decoded");
        haier.printTo(Serial);

        uint16_t haierTicks[esp32irpk::ac::Haier::Frame::kMaxTicks];
        esp32irpk::IRRawTickBuffer haierBuf{haierTicks,
                                            esp32irpk::ac::Haier::Frame::kMaxTicks,
                                            0};
        if (haier.toRaw(haierBuf)) {
          esp32irpk::IRRawTickView haierView{haierBuf.ticks, haierBuf.len};
          Serial.printf("Re-encoded clean Haier frame: len=%u\n",
                        (unsigned)haierView.len);
          if (saveToggle(haierView)) {
            state = State::IDLE;
            drawUI();
          }
        } else {
          Serial.println("Haier re-encode failed");
        }
      } else if (result.raw.len >= MIN_TOGGLE_TICKS) {
        // Not a Haier frame. If decodeAny recognized another vendor, save the
        // raw immediately (raw replay works for any protocol).
        if (vendor != esp32irpk::ac::AcVendor::UNKNOWN) {
          if (saveToggle(result.raw)) {
            state = State::IDLE;
            drawUI();
          }
          return;
        }
        // No vendor matched: keep the capture only if it is structurally
        // plausible (a pulse-distance AC frame always has 1-bit spaces of
        // roughly 1.0-2.6 ms). Keep the BEST one across repeated taps and
        // auto-save a couple of seconds after the first good capture.
        bool hasOneBitSpace = false;
        for (size_t i = 0; i < result.raw.len; i++) {
          uint32_t us = (uint32_t)result.raw.ticks[i] * 10u;
          if (us >= 1000 && us <= 2600) {
            hasOneBitSpace = true;
            break;
          }
        }
        if (hasOneBitSpace) {
          int sc = captureScore(cleanView);
          // A headerless mid-frame slice (score < 500) is never usable; only
          // keep captures that contain the complete Haier double header.
          if (sc >= 500 && sc > bestScore) {
            bestScore = sc;
            bestLen = cleanLen;
            for (size_t i = 0; i < bestLen; i++) bestTicks[i] = cleanTicks[i];
            if (firstGoodMs == 0) firstGoodMs = millis();
            M5.Display.fillRect(0, 120, 240, 60, TFT_BLACK);
            M5.Display.setCursor(0, 120);
            M5.Display.setTextColor(TFT_GREEN);
            M5.Display.printf("GOT IR\nlen=%u\nKeep tapping",
                              (unsigned)bestLen);
            Serial.printf("Good capture len=%u score=%d (keep tapping...)\n",
                          (unsigned)bestLen, sc);
          } else if (sc < 500) {
            // Complete-frame capture (no header) is not saved; show a hint.
            M5.Display.fillRect(0, 120, 240, 60, TFT_BLACK);
            M5.Display.setCursor(0, 120);
            M5.Display.setTextColor(TFT_YELLOW);
            M5.Display.printf("HEAD MISSING\nlen=%u\nTap again",
                              (unsigned)result.raw.len);
            Serial.printf("Capture missing Haier header (len=%u) - tap again\n",
                          (unsigned)result.raw.len);
          }
        } else {
          // Garbage: no data-bit structure. Ignore silently and keep
          // listening - a bad tap must not erase a previous good one.
          Serial.println("Ignored noisy capture");
        }
      } else {
        // Likely a repeat frame or noise; keep listening.
        M5.Display.fillRect(0, 120, 240, 60, TFT_BLACK);
        M5.Display.setCursor(0, 120);
        M5.Display.setTextColor(TFT_YELLOW);
        M5.Display.printf("TOO SHORT\nlen=%u\nTap again",
                          (unsigned)result.raw.len);
        Serial.println("Ignored: signal too short");
      }
    }

    // Auto-save the best capture ~3s after the first good one. This matches
    // "tap repeatedly": a couple of taps give the receiver enough chances for
    // a clean frame, then we store the best one and leave learning.
    if (state == State::LEARNING && bestScore >= 0 && firstGoodMs != 0 &&
        (millis() - firstGoodMs > 3000)) {
      esp32irpk::IRRawTickView bestView{bestTicks, bestLen};
      Serial.printf("Saving best of %d taps: len=%u score=%d\n",
                    bestScore >= 0 ? 2 : 1, (unsigned)bestLen, bestScore);
      if (saveToggle(bestView)) {
        state = State::IDLE;
        drawUI();
      }
    }

    // 15-second learn timeout: gives you time to keep tapping. Save the best
    // capture seen so far instead of discarding everything.
    if (millis() - learnStartMs > 15000) {
      if (bestScore >= 0 && bestLen > 0) {
        esp32irpk::IRRawTickView bestView{bestTicks, bestLen};
        Serial.printf("Timeout - saving best capture len=%u score=%d\n",
                      (unsigned)bestLen, bestScore);
        if (saveToggle(bestView)) {
          state = State::IDLE;
          drawUI();
        }
      } else {
        state = State::IDLE;
        M5.Display.fillRect(0, 120, 240, 60, TFT_BLACK);
        M5.Display.setCursor(0, 120);
        M5.Display.setTextColor(TFT_YELLOW);
        M5.Display.println("Learn timeout\nNo signal");
        Serial.println("Learn timeout - no usable capture");
        delay(1000);
        drawUI();
      }
    }
  }

  delay(10);
}

bool loadToggle(size_t &outLen) {
  outLen = 0;
  if (!LittleFS.exists(TOGGLE_FILE)) return false;

  File f = LittleFS.open(TOGGLE_FILE, FILE_READ);
  if (!f || f.size() < 2) return false;

  uint16_t len = 0;
  f.read((uint8_t *)&len, sizeof(len));
  if (len == 0 || len > MAX_TICKS) {
    f.close();
    return false;
  }

  size_t bytesToRead = len * sizeof(uint16_t);
  // New format is exactly 2-byte length + ticks. Older firmware stored the
  // length as 4 bytes (size_t), so its files are 2 bytes longer; reject them so
  // a stale corrupt file is not replayed after a firmware update.
  if ((size_t)f.size() != sizeof(len) + bytesToRead) {
    f.close();
    return false;
  }

  size_t readBytes = f.read((uint8_t *)tickBuffer, bytesToRead);
  f.close();
  if (readBytes != bytesToRead) return false;

  outLen = len;
  return true;
}

void sendToggle() {
  static bool powerOn = false; // first press sends ON
  powerOn = !powerOn;

  // Generate a textbook Haier frame with the library encoder: full
  // 3000/3000/3000/4300 double header, 520us marks, correct sum checksum.
  // This bypasses the unreliable learn-from-phone path entirely - the AC
  // always understands this waveform.
  esp32irpk::ac::Haier::Frame f; // default: cool / 24C / fan auto / swing off
  f.setPower(powerOn);

  uint16_t ticks[esp32irpk::ac::Haier::Frame::kMaxTicks];
  esp32irpk::IRRawTickBuffer buf{ticks, esp32irpk::ac::Haier::Frame::kMaxTicks, 0};
  bool okEncode = f.toRaw(buf);

  M5.Display.fillRect(0, 120, 240, 60, TFT_BLACK);
  M5.Display.setCursor(0, 120);

  if (!okEncode) {
    M5.Display.setTextColor(TFT_RED);
    M5.Display.println("ENCODE FAIL");
    Serial.println("Haier encode failed");
    return;
  }

  esp32irpk::IRRawTickView view{buf.ticks, buf.len};

  // Send it 3 times with a short gap, like a real remote's repeat behaviour -
  // improves the chance the AC catches it through its own AGC window.
  bool sent = true;
  for (int i = 0; i < 3; i++) {
    if (!tx.send(view)) sent = false;
    delay(80);
  }

  M5.Display.setTextColor(sent ? TFT_GREEN : TFT_RED);
  M5.Display.printf("%s %s\nlen=%u", powerOn ? "PWR ON" : "PWR OFF",
                    sent ? "OK" : "FAIL", (unsigned)view.len);
  Serial.printf("Sent Haier %s len=%u %s\n", powerOn ? "ON" : "OFF",
                (unsigned)view.len, sent ? "OK" : "FAIL");

  delay(300);
  drawUI();
}

bool saveToggle(const esp32irpk::IRRawTickView &raw) {
  M5.Display.fillRect(0, 120, 240, 60, TFT_BLACK);
  M5.Display.setCursor(0, 120);

  if (!raw.ticks || raw.len == 0) {
    M5.Display.setTextColor(TFT_RED);
    M5.Display.println("Empty IR");
    Serial.println("Empty IR capture");
    delay(1000);
    drawUI();
    return false;
  }

  File f = LittleFS.open(TOGGLE_FILE, FILE_WRITE);
  if (!f) {
    M5.Display.setTextColor(TFT_RED);
    M5.Display.println("Save failed");
    Serial.println("Failed to open toggle file");
    delay(1000);
    drawUI();
    return false;
  }

  // Store the length as an explicit uint16_t (2 bytes). Writing sizeof(raw.len)
  // (4 bytes, since IRRawTickView::len is size_t) desynchronises the file
  // layout from loadToggle(), which reads a 2-byte length and then starts
  // reading ticks at the wrong offset.
  uint16_t len = static_cast<uint16_t>(raw.len);
  f.write((const uint8_t *)&len, sizeof(len));
  for (size_t i = 0; i < raw.len; i++) {
    uint16_t t = raw.ticks[i];
    f.write((const uint8_t *)&t, sizeof(t));
  }
  f.close();

  // Dump to Serial for backup.
  Serial.println();
  Serial.printf("// IR_TOGGLE LEN=%u TICK_US=10\n", (unsigned)raw.len);
  Serial.printf("const uint16_t IR_TOGGLE_LEN = %u;\n", (unsigned)raw.len);
  Serial.printf("const uint16_t IR_TOGGLE[] PROGMEM = {\n  ");
  for (size_t i = 0; i < raw.len; i++) {
    Serial.printf("%u", raw.ticks[i]);
    if (i + 1 < raw.len) Serial.print(", ");
    if ((i + 1) % 16 == 0) Serial.print("\n  ");
  }
  Serial.println("\n};");
  Serial.println();

  M5.Display.setTextColor(TFT_GREEN);
  M5.Display.printf("SAVED\nlen=%u", (unsigned)raw.len);
  Serial.printf("Saved toggle len=%u\n", (unsigned)raw.len);
  delay(1000);
  return true;
}

5. 首次实测：打通收发链路

这一步是整件事的成败关键。上传后立刻做链路验证：

  1. 把设备举到空调正前方 30-50cm，对准空调接收窗（面板右下角暗红色小窗）。
  2. 按 K1，观察空调有没有反应。
  3. 若没反应，按顺序检查：距离/角度 → 载波 38kHz → 板子供电（setExtOutput）→ 端口是否烧对。
不要一开始就隔 1 米测试。 板载红外管功率小，先近距离确认链路通，再考虑距离。90% 的"发不出去"都是距离/角度问题，而不是代码问题。
链路验证通过后再加功能（学习、多按键、屏幕显示）。先小步跑通，再扩展，永远比一次写完再查快。

6. 方案 B：学习 + 回放（任意遥控器）

当你的空调品牌不在库的协议表里时，用学习回放：捕获遥控器原始波形 → 保存 → 原样重发。

6.1 捕获（学习）

示例代码text
// 初始化接收
rx.setMaxRxSymbols(512);      // 空调帧长，务必调大
rx.setIdleThresholdUs(15000); // 15ms 空闲阈值，把连发帧切成独立捕获
rx.begin();

// 循环里读一帧
esp32irpk::IRReceiveResult<4> result;
if (rx.read(result)) {
  // result.raw.ticks[] = mark/space 时长数组（1 tick = 10us）
  // 在这里保存 result.raw
}

6.2 保存到 LittleFS（文件格式约定）

示例代码text
// 格式：2 字节 uint16_t 长度 + len 个 uint16_t tick（小端）
File f = LittleFS.open("/power.bin", FILE_WRITE);
uint16_t len = (uint16_t)raw.len;              // 注意！长度必须是 2 字节
f.write((const uint8_t *)&len, sizeof(len));
for (size_t i = 0; i < raw.len; i++) {
  uint16_t t = raw.ticks[i];
  f.write((const uint8_t *)&t, sizeof(t));
}
f.close();
文件格式是学习回放最容易翻车的地方：长度字段必须固定写 2 字节（uint16_t）。如果用 sizeof(raw.len)（size_t 在 ESP32 上是 4 字节），读写就会错位，回放出来的波形整体损坏。

6.3 回放

示例代码text
// 读文件 → 还原 ticks → 发送
uint16_t len = 0;
f.read((uint8_t *)&len, sizeof(len));
for (size_t i = 0; i < len; i++) f.read((uint8_t *)&tickBuffer[i], sizeof(uint16_t));

esp32irpk::IRRawTickView view{tickBuffer, len};
tx.send(view);

6.4 学习时的捕获质量判断

  • 一帧空调波形通常 100-250 个 tick（Haier 约 150）。
  • 波形的数据位应包含 1-bit 空间（约 1000-2600µs）；如果完全没有，说明捕获的是噪声，重学。
  • 理想的帧从 同步头开始（如 Haier 是 3000/3000/3000/4300µs）；缺头的半帧空调不认。
  • 手机万能遥控 App 通常只能"点按"发一帧，且信号偏强——放在 30-100cm、连按 3-5 次，取最干净的一帧。

6.5 完整示例：录制 + 回放两件套

下面两个 sketch 配合使用：先用 recorder 录制遥控器按键保存到 LittleFS，再刷 player 读取文件回放（支持两个槽位：power_on / power_off）。文件格式为 2 字节 uint16_t 长度 + len × 2 字节 tick，1 tick = 10µs。

m5stick_s3_ir_recorder.inoArduino C++完整可编译 · 录制 power_on / power_off 两个槽位
// M5StickS3 IR Recorder
// ======================
// Records raw IR waveforms from the on-board IR receiver (GPIO42) and saves
// them to LittleFS as "/power_on.bin" / "/power_off.bin". It also prints the
// captured waveform as a copy-paste C array over Serial, so a PC-side script
// can turn it into a header file for the player sketch.
//
// Hardware: M5StickS3 (ESP32-S3)
// IR RX: GPIO42 (on-board)
// IR TX: GPIO46 (not used here)
//
// Arduino IDE settings:
//   Board: M5Stack -> M5StickS3
//   Partition Scheme: pick an 8MB option with SPIFFS/LittleFS (e.g. 8MB)
//   Libraries: M5Unified, M5GFX, ESP32IRPulseKit

#include <M5Unified.h>
#include <ESP32IRPulseKit.h>
#include <LittleFS.h>

constexpr uint16_t IR_RX_PIN = 42;

// Most IR receiver modules output an active-low signal; set inverted=true.
// If you get no captures, try inverted=false.
esp32irpk::IRReceiver rx(IR_RX_PIN, true);

struct Slot {
  const char *name;
  const char *filename;
  uint16_t color;
};

Slot slots[] = {
  {"power_on",  "/power_on.bin",  TFT_GREEN},
  {"power_off", "/power_off.bin", TFT_RED},
};

const int SLOT_COUNT = sizeof(slots) / sizeof(slots[0]);
int currentSlot = 0;
bool armed = false;          // waiting for an IR frame
uint32_t armedAt = 0;

void setup() {
  M5.begin();
  Serial.begin(115200);
  delay(200);
  Serial.println("\nM5StickS3 IR Recorder starting...");

  // Power on the on-board IR receiver (EXT_5V output).
  M5.Power.setExtOutput(true, m5::ext_none);
  delay(100);
  Serial.println("EXT_5V ON");

  // Disable speaker amp while receiving, otherwise IR RX is noisy.
  M5.Speaker.end();
  Serial.println("Speaker off");

  // Mount LittleFS. formatOnFail=true will create the FS if it does not exist.
  Serial.println("Mounting LittleFS...");
  if (!LittleFS.begin(true)) {
    Serial.println("LittleFS mount failed");
    M5.Display.println("FS mount failed");
    while (true) delay(1000);
  }
  Serial.println("LittleFS OK");

  // Make sure long AC frames (hundreds of ticks) are not truncated.
  rx.setMaxRxSymbols(512);
  rx.begin();
  Serial.println("RX begin OK");

  M5.Display.setRotation(3);
  M5.Display.setTextFont(&fonts::FreeMonoBold9pt7b);
  M5.Display.clear();

  drawUI();
  printHelp();
}

void loop() {
  static uint32_t aliveTimer = 0;
  if (millis() - aliveTimer > 5000) {
    aliveTimer = millis();
    Serial.println("alive");
  }

  M5.update();

  // BtnA: cycle through slots
  if (M5.BtnA.wasPressed()) {
    if (armed) cancelArm();
    currentSlot = (currentSlot + 1) % SLOT_COUNT;
    drawUI();
  }

  // BtnB: arm/disarm recording for the selected slot
  if (M5.BtnB.wasPressed()) {
    if (armed) {
      cancelArm();
    } else {
      armSlot();
    }
  }

  // If armed and no signal within 10s, timeout.
  if (armed && (millis() - armedAt > 10000)) {
    cancelArm();
    M5.Display.fillRect(0, 140, 240, 40, TFT_BLACK);
    M5.Display.setCursor(0, 140);
    M5.Display.setTextColor(TFT_YELLOW);
    M5.Display.println("Timeout");
  }

  // Read IR.
  esp32irpk::IRReceiveResult<4> result;
  if (rx.read(result)) {
    if (armed) {
      saveCapture(result.raw, slots[currentSlot]);
      armed = false;
    } else {
      // Not armed: just dump to serial for inspection.
      dumpRaw(result.raw, "preview");
      M5.Display.fillRect(0, 60, 240, 120, TFT_BLACK);
      M5.Display.setCursor(0, 60);
      M5.Display.setTextColor(TFT_CYAN);
      M5.Display.printf("Preview len=%u\n", (unsigned)result.raw.len);
    }
  }

  delay(5);
}

void drawUI() {
  M5.Display.clear();
  M5.Display.setCursor(0, 0);
  M5.Display.setTextColor(TFT_WHITE);
  M5.Display.println("IR RECORDER");
  M5.Display.println("A:slot  B:record");

  for (int i = 0; i < SLOT_COUNT; i++) {
    int y = 60 + i * 30;
    if (i == currentSlot) {
      M5.Display.fillRect(0, y, 240, 24, slots[i].color);
      M5.Display.setTextColor(TFT_BLACK);
    } else {
      M5.Display.fillRect(0, y, 240, 24, TFT_BLACK);
      M5.Display.setTextColor(slots[i].color);
    }
    M5.Display.setCursor(4, y + 4);
    M5.Display.print(slots[i].name);
    if (LittleFS.exists(slots[i].filename)) {
      M5.Display.print(" [OK]");
    } else {
      M5.Display.print(" [---]");
    }
  }
}

void armSlot() {
  armed = true;
  armedAt = millis();
  M5.Display.fillRect(0, 140, 240, 40, TFT_BLACK);
  M5.Display.setCursor(0, 140);
  M5.Display.setTextColor(TFT_YELLOW);
  M5.Display.printf("Aim remote at\nStickS3 for %s", slots[currentSlot].name);
}

void cancelArm() {
  armed = false;
  drawUI();
}

void saveCapture(const esp32irpk::IRRawTickView &raw, const Slot &slot) {
  if (!raw.ticks || raw.len == 0) {
    M5.Display.println("Empty capture");
    return;
  }

  // LittleFS binary format: uint16_t length, then each tick as uint16_t (LE).
  // Store the length as an explicit uint16_t: writing sizeof(raw.len) (4 bytes,
  // since IRRawTickView::len is size_t) would desynchronise the file from the
  // player's loadSlot(), which reads a 2-byte length.
  File f = LittleFS.open(slot.filename, FILE_WRITE);
  if (!f) {
    Serial.printf("Failed to open %s for write\n", slot.filename);
    M5.Display.println("Write failed");
    return;
  }

  uint16_t len = static_cast<uint16_t>(raw.len);
  f.write((const uint8_t *)&len, sizeof(len));
  for (size_t i = 0; i < raw.len; i++) {
    uint16_t t = raw.ticks[i];
    f.write((const uint8_t *)&t, sizeof(t));
  }
  f.close();

  // Also print to Serial as a copy-paste C array.
  dumpRaw(raw, slot.name);

  // Move to next slot for convenience.
  currentSlot = (currentSlot + 1) % SLOT_COUNT;
  drawUI();

  M5.Display.fillRect(0, 140, 240, 40, TFT_BLACK);
  M5.Display.setCursor(0, 140);
  M5.Display.setTextColor(TFT_GREEN);
  M5.Display.printf("Saved %s\nlen=%u", slot.name, (unsigned)raw.len);
}

void dumpRaw(const esp32irpk::IRRawTickView &raw, const char *label) {
  if (!raw.ticks || raw.len == 0) return;

  Serial.println();
  Serial.printf("// IR_SLOT: %s  LEN: %u  TICK_US: 10\n", label, (unsigned)raw.len);
  Serial.printf("const uint16_t IR_%s_LEN = %u;\n", label, (unsigned)raw.len);
  Serial.printf("const uint16_t IR_%s[] PROGMEM = {\n  ", label);
  for (size_t i = 0; i < raw.len; i++) {
    Serial.printf("%u", raw.ticks[i]);
    if (i + 1 < raw.len) Serial.print(", ");
    if ((i + 1) % 16 == 0) Serial.print("\n  ");
  }
  Serial.println("\n};");
  Serial.println();
}

void printHelp() {
  Serial.println("M5StickS3 IR Recorder");
  Serial.println("BtnA: switch slot");
  Serial.println("BtnB: start/cancel recording");
  Serial.println("Captured arrays are printed here for PC-side conversion.");
  Serial.println();
}
m5stick_s3_ir_player.inoArduino C++完整可编译 · 读取 LittleFS 文件并回放
// M5StickS3 IR Player
// ====================
// Reads raw IR waveforms saved by the recorder (LittleFS files) and replays
// them through the on-board IR transmitter (GPIO46).
//
// Files expected on LittleFS:
//   /power_on.bin
//   /power_off.bin
//
// Each file format: uint16_t tick_count, followed by tick_count uint16_t ticks.
// 1 tick = 10us. This matches ESP32IRPulseKit's IRRawTickView.
//
// Hardware: M5StickS3 (ESP32-S3)
// IR TX: GPIO46 (on-board)
// IR RX: GPIO42 (not used here)
//
// Arduino IDE settings:
//   Board: M5Stack -> M5StickS3
//   Partition Scheme: pick an 8MB option with SPIFFS/LittleFS
//   Libraries: M5Unified, M5GFX, ESP32IRPulseKit

#include <M5Unified.h>
#include <ESP32IRPulseKit.h>
#include <LittleFS.h>

constexpr uint16_t IR_TX_PIN = 46;

// On-board IR LED. Most modules are active-high on this board.
esp32irpk::IRSender tx(IR_TX_PIN);

struct Slot {
  const char *name;
  const char *filename;
  uint16_t color;
};

Slot slots[] = {
  {"power_on",  "/power_on.bin",  TFT_GREEN},
  {"power_off", "/power_off.bin", TFT_RED},
};

const int SLOT_COUNT = sizeof(slots) / sizeof(slots[0]);

// Max ticks we are willing to load from a file. Air-conditioner frames rarely
// exceed a few hundred ticks; this gives plenty of headroom.
constexpr size_t MAX_TICKS = 1024;
uint16_t tickBuffer[MAX_TICKS];

void setup() {
  M5.begin();
  Serial.begin(115200);
  delay(200);

  // Power on the on-board IR transmitter (EXT_5V output).
  M5.Power.setExtOutput(true, m5::ext_none);
  delay(100);

  if (!LittleFS.begin(true)) {
    Serial.println("LittleFS mount failed");
    M5.Display.println("FS mount failed");
    while (true) delay(1000);
  }

  tx.begin();

  M5.Display.setRotation(3);
  M5.Display.setFont(&fonts::FreeMonoBold9pt7b);
  M5.Display.clear();

  drawUI();

  Serial.println("M5StickS3 IR Player");
  Serial.println("BtnA: send power_on");
  Serial.println("BtnB: send power_off");
}

void loop() {
  M5.update();

  if (M5.BtnA.wasPressed()) {
    sendSlot(0);
  }
  if (M5.BtnB.wasPressed()) {
    sendSlot(1);
  }

  delay(50);
}

void drawUI() {
  M5.Display.clear();
  M5.Display.setCursor(0, 0);
  M5.Display.setTextColor(TFT_WHITE);
  M5.Display.println("IR PLAYER");

  for (int i = 0; i < SLOT_COUNT; i++) {
    int y = 50 + i * 40;
    bool exists = LittleFS.exists(slots[i].filename);
    M5.Display.setTextColor(exists ? slots[i].color : TFT_DARKGREY);
    M5.Display.setCursor(4, y);
    M5.Display.printf("%s: %s", (i == 0 ? "A" : "B"), slots[i].name);
    M5.Display.setCursor(4, y + 18);
    M5.Display.printf("  [%s]", exists ? "OK" : "missing");
  }

  M5.Display.setTextColor(TFT_LIGHTGREY);
  M5.Display.setCursor(0, 160);
  M5.Display.println("Press A/B to send");
}

bool loadSlot(const Slot &slot, size_t &outLen) {
  outLen = 0;
  if (!LittleFS.exists(slot.filename)) {
    Serial.printf("File not found: %s\n", slot.filename);
    return false;
  }

  File f = LittleFS.open(slot.filename, FILE_READ);
  if (!f || f.size() < 2) {
    Serial.printf("Failed to open %s\n", slot.filename);
    return false;
  }

  uint16_t len = 0;
  f.read((uint8_t *)&len, sizeof(len));
  if (len == 0 || len > MAX_TICKS) {
    Serial.printf("Bad tick count %u in %s\n", (unsigned)len, slot.filename);
    f.close();
    return false;
  }

  size_t bytesToRead = len * sizeof(uint16_t);
  // New format is exactly 2-byte length + ticks. Older firmware stored the
  // length as 4 bytes (size_t), so its files are 2 bytes longer; reject them.
  if ((size_t)f.size() != sizeof(len) + bytesToRead) {
    Serial.printf("Bad file size %u for %s (re-record it)\n", (unsigned)f.size(), slot.filename);
    f.close();
    return false;
  }


  size_t readBytes = f.read((uint8_t *)tickBuffer, bytesToRead);
  f.close();
  if (readBytes != bytesToRead) {
    Serial.printf("Short read %s\n", slot.filename);
    return false;
  }

  outLen = len;
  return true;
}

void sendSlot(int index) {
  const Slot &slot = slots[index];
  size_t len = 0;
  bool ok = loadSlot(slot, len);

  M5.Display.fillRect(0, 120, 240, 60, TFT_BLACK);
  M5.Display.setCursor(0, 120);

  if (!ok) {
    M5.Display.setTextColor(TFT_RED);
    M5.Display.printf("No data for\n%s", slot.name);
    Serial.printf("No data for %s\n", slot.name);
    delay(1000);
    drawUI();
    return;
  }

  esp32irpk::IRRawTickView view{tickBuffer, len};
  bool sent = tx.send(view);

  M5.Display.setTextColor(sent ? TFT_GREEN : TFT_RED);
  M5.Display.printf("Send %s\n%s", slot.name, sent ? "OK" : "FAIL");
  Serial.printf("Send %s len=%u %s\n", slot.name, (unsigned)len, sent ? "OK" : "FAIL");

  delay(500);
  drawUI();
}

7. 使用最佳实践与避坑清单

7.1 发射（控制空调）

做法原因
≤30-50cm、正对空调接收窗板载 IR 功率小，远了信号到不了
连发 2-3 次（间隔 50-100ms）模拟遥控器重复行为，提高命中率
确保 38kHz 载波接收头只对 38kHz 灵敏

7.2 接收（学习）

做法原因
信号源放 30-100cm太近 AGC 饱和失真，太远信号弱
连按 3-5 次，取最佳帧单次捕获可能撞上 AGC 恢复期/半帧
关闭扬声器功放（M5.Speaker.end()）功放噪声会干扰 IR 接收
接收通道用 128 符号 + DMA空调长帧（75-125+ 符号）不被截断

7.3 通用避坑清单

1 先确认"谁在发信号"

手机 App 能控空调 ≠ 它的码能被轻松学习。先用库的生成帧做链路验证（方案 A），确认设备自身收发正常，再谈学习。

2 一个按键一个动作，别让 repeat 帧捣乱

长按遥控器会连发多帧，学习时捕获到的可能是合并帧。点按 + 多次捕获取最佳。

3 协议"单帧"就别连发

有些品牌一帧就是完整指令（如 Haier、Toshiba、Samsung），连发两帧会被当成两次按键（开关互相抵消）。查库文档确认你的品牌是否单帧，连发只用于提高命中率时也要控制次数与间隔。

4 上传报 "port busy"

先退出串口监视器再上传；若仍占用，用 lsof /dev/cu.usbmodemXXXX 找到残留的 serial-monitor 进程并结束。

5 端口名会变

设备重插/重枚举后端口名可能从 usbmodem1101 变成 usbmodem101。上传前用 arduino-cli board list 确认。

6 改第三方库要留记录

把库放在项目内（如 .arduino_sketchbook/libraries），改动记进 README，防止库更新被覆盖。
