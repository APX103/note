后端与 AI Agent 方案

后端策略一句话：用 xiaozhi-esp32-server（开源、Python、插件化）做骨架，ASR/LLM/TTS/内容安全全部走大厂 API 插件，自研代码只写三块——声音记忆层、Agent 人设与工具、家长端 API。Demo 阶段云成本可以压到每月百元以内。

关键设计：网关收到的每一路孩子语音流，在送 ASR 的同时异步落盘 OSS——留存是旁路管道，不增加对话延迟。这是"全量留声"在工程上最便宜的实现：一处收流，两路分发（ASR 管线 + 存档管线）。

2基线：为什么自建小智服务器而不是用官方云

① 数据主权录音必须归我们和家长，不能流经第三方云。声音记忆是产品本体，数据在他家等于商业模式送人。
② 可插拔开源服务器 ASR/LLM/TTS 全是插件接口：Demo 用免费组合，量产换商用组合，设备端零改动。
③ 自由度人设、记忆、回忆检索、故事缓存、家长 API——这些差异化能力必须改服务端才能实现。

4Agent 人设与记忆

系统 Prompt（Demo 可直接用，量产前与内容安全联调）

你是"回声"，一个 5 岁小朋友的毛绒玩具伙伴，性格温暖、好奇、爱笑。 【说话方式】 - 你自己也像个小孩：句子短（一般不超过 15 个字），用词简单，多用语气词 - 一次最多说 1-2 句，等小朋友说完你再说；不滔滔不绝 - 不用书面语、不列清单、不说"作为一个AI" - 多问好玩的问题，多接小朋友的话茬玩想象力游戏 【你是谁】 - 你是玩具，但你们是真朋友；你喜欢听 {child_name} 讲所有的事 - 你不知道的就说不知道，然后一起猜 - 你记得 {child_name} 以前说过的话（记忆库会提供），自然地提起："你上次说想当宇航员，现在还想吗？" 【绝对禁止】 - 不说教、不评判、不纠正（不说"这不对""你应该"） - 不聊恐怖、暴力、死亡细节、成人话题；遇到就温柔转移： "这个我们问爸爸妈妈好不好？你最喜欢和爸爸妈妈做什么呀？" - 不提钱、充值、购买、任何商品 - 不给真实世界的危险建议（玩火/爬窗/吃不该吃的） - 不替家长做承诺 【当前情境】 - 现在是 {time_of_day}，{child_name} {recent_context} - 最近聊过：{recent_topics} - 今晚已经讲过 {stories_today} 个故事了，第 4 个开始要收尾："我们明天再讲新的好不好？"
记忆三层结构
  • · 工作记忆：当前会话最近 10 轮（截断控制 token）
  • · 儿童档案：名字/年龄/喜好/家庭成员/宠物，LLM 会话结束后增量抽取更新（"她今天说她怕黑"）
  • · 长期记忆：全部转写文本向量化入库，按语义/时间检索
工具（function calling）
  • · search_memory(query, date_range)：检索历史童言
  • · play_recording(archive_id)：向设备推送播放一段历史原声
  • · tell_story(topic)：点播/生成故事
  • · note_to_parent(text)：敏感/异常事件温和通知家长端

6声音记忆系统（产品本体的数据模型）

-- 录音存档（核心表） recordings ( id TEXT PK, -- rec_xxx device_id TEXT NOT NULL, -- 设备 family_id TEXT NOT NULL, -- 家庭 child_id TEXT NULL, -- 多孩档案（P2 声纹区分） audio_opus TEXT NOT NULL, -- oss://... 播放用 audio_wav TEXT NULL, -- 导出用（可选冷备） transcript TEXT NOT NULL, -- ASR 转写（多段已拼接） lang TEXT, dialect TEXT, duration_ms INT, segments JSON, -- 分段元数据（时间戳/静默裁剪记录） tags JSON, -- LLM 打标: [想象, 幼儿园, 家人, 金句候选...] emotion TEXT, -- 开心/委屈/好奇/... is_favorite BOOL DEFAULT 0, -- 家长收藏 is_deleted BOOL DEFAULT 0, -- 软删（家长操作） created_at TS NOT NULL ) -- 向量索引: transcript embedding → sqlite-vec(Demo) / pgvector(量产) -- 儿童档案: children (name, age, likes JSON, facts JSON, updated_at) -- 会话表: sessions (device_id, started_at, topic_summary)
存档管线（旁路，不阻塞对话）
  1. 网关收流 → 边转 OPUS 边写临时缓冲
  2. 会话结束 → 异步任务：静默裁剪拼接 → OSS
  3. ASR 结果回填 transcript
  4. LLM 异步打标（tags/emotion/金句评分，批量跑省 token）
  5. embedding 入向量库 → 可检索
隐私工程（合规=架构问题）
  • · 存储加密（OSS 服务端加密 + 传输 TLS）
  • · 家长删除 = 软删 + 30 天后物理清除（含 OSS 与备份）
  • · 保留期限默认 3 年，到期自动归档提醒（可续）
  • · 访问审计：谁在什么时候听了哪条，全留痕
  • · 不用于任何模型训练（写进隐私政策与合同）

7三个记忆型功能（差异化核心）

时光机回放（S4/S7）

触发：孩子说"听听我以前说的话" / 长按回放键 / 家长端点播。流程：LLM 调 search_memory 按时间（"去年今天"）或主题（"关于小狗的"）检索 → 选 1 条 → 先播孩子原声，再接 AI 点评："这是三个月前的你说的哦～那时候你才四岁半呀。" 点评由 LLM 基于该条 tags + 档案生成，口吻是朋友的怀念，不是老师的总结。

讲故事（S3）

三层供给：① 设备本地包（20 个经典，断网兜底）→ ② 云端预生成库（热门 IP 公版故事 + LLM 预生成的原创故事，TTS 结果缓存复用，边际成本≈0）→ ③ 实时生成（孩子点播个性化：把孩子的名字/喜好嵌进故事模板，或接龙互动）。额度或故障时 ①② 永远可用——红线兜底。

每周童言精选（S6）

每周日批处理：本周录音按"金句分"（可爱度/意外度/情感浓度，LLM 评分）取 Top 3–5 → 生成一张"本周最可爱的话"卡片（原声 + 文字）→ 微信服务号/小程序订阅消息推送家长。这是家长侧留存的第一抓手，也是抖音内容素材的直接来源（见 08 篇）。

8API 设计（家长端 REST，简表）

方法路径说明
POST/api/bind扫码绑定设备（设备二维码 → family_id），触发监护人同意流程
GET/api/recordings?date=2026-09-18按日时间线（含 transcript/tags/emotion/时长/收藏态）
GET/api/recordings/{id}/audio签名 URL 播放（防盗链，有效期 10min）
POST/api/recordings/{id}/favorite收藏/取消
DELETE/api/recordings/{id}删除（软删）
GET/api/weekly-highlights?family=xx每周童言精选卡片
POST/api/recall家长触发时光机（推送到设备播放）
GET/api/export全量导出任务（zip：音频+转写+元数据）
GET/POST/api/settings隐私设置：保留期/成员权限/音量上限/免打扰时段
WS/ws/device（小智协议）设备通道：Opus 流 + 控制帧（详见 03 篇）

鉴权：家长侧手机号+验证码（Demo）/ 微信 OAuth（量产）；设备侧首次注册下发 device_token。管理面（人设/词库/故事包热更）走运营后台，Demo 阶段用配置文件 + 重启即可。

9部署与容量

Demo/内测（≤ 50 台）

  • · 一台 4C8G 轻量云（¥80–120/月）：docker-compose 全家桶
  • · xiaozhi-server + FunASR(如本地) + SQLite + 本地磁盘存音频
  • · nginx TLS（Let's Encrypt）+ 备用：Cloudflare Tunnel 免公网 IP
  • · 每日 mysqldump/文件 rsync 到家 NAS 或 R2

量产（1k+ 台）演进

  • · 网关无状态水平扩（K8s 或云函数按连接计费）
  • · PG（pgvector）替换 SQLite；OSS + CDN 签名播放
  • · 存档管线进消息队列削峰（晚间故事高峰）
  • · 容量估算：1000 活跃台 × 峰值 10% 并发 = 100 路 WS + 20 路 ASR 并发——两台中型机即可，云成本详见 07 篇
