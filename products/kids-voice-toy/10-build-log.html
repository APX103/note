构建过程（按时间线）

阶段一
骨架与服务端主链路（约 1 小时）
读 9 篇设计 → 提炼 docs/protocol.md（JSON 控制帧 + PCM 二进制帧，文本/二进制靠 WS opcode 区分）→ FastAPI 落地 ws_device 网关、agent 管线（ASR→输入安全→LLM 人设→输出安全→TTS）、SQLite 七张表、家长端 REST。关键工程决策：存档做旁路管道不阻塞对话；AI 供应商三插口全部允许"没配也能跑"（LLM 降级为本地童趣话术、ASR 留空、TTS 降级合成提示音）——零密钥也能全流程验证。
阶段二
家长端 H5 + 固件（约 1.5 小时）
H5 单页四屏（绑定/时间线/精选/我的），"原声优先"：大圆播放键是页面最大元素。固件以同仓库 intercom/tuner 实测代码为模板，6 个模块：板级 bring-up（PMU 供电恢复/SH8601/FT3168 复位释放——这三个不带上就是黑屏+触摸失灵的祖传坑）、手绘 UI（三个大圆按钮 + 状态色条 + 5x7 字库）、音频层（ES8311 双向常开 + HPF/门限 DSP + PSRAM 双缓冲）、多段录音状态机（L2 规格：按住录/松开暂停/3s 续录/静默 5s 自动封口/长按组合/童锁）、WiFi+WS、主循环。一次编译通过后修三处（环形缓冲 2 的幂、头文件名、WS 组件 API 改名）。
阶段三
Docker 化 + 测试客户端体系
server/Dockerfile（含 ffmpeg 供 TTS 转码）+ compose（数据卷/密钥文件/健康检查）。工具三件套：echo_client.py 交互式设备模拟器（WAV 上传/Mac 麦克风/童声 afplay 试听）、run_tests.py 契约测试（自带临时服务端，不碰真实数据）、record.py 录音脚本。方针：硬件之外全部可测。
阶段四
v0.2：多设备多用户（设计→实现→测试）
按"卖硬件、对接百万设备"设计：devices/members/invites/story_plays 四张新表；设备首连注册并签发 device_token（量产强制校验）；6 位绑定码（10 分钟/单次/防爆破锁定）对标小智配对；一家庭多设备（按 device_id 路由推送）+ 一家庭多成员（admin/listener/lite 三级角色）；解绑留数据（二手转卖场景）；影子家庭机制保证"设备先说话后绑定，时间线无洞"。实现中抓出并修掉一个设计漏洞：hello 时不该建影子家庭，否则第二台设备加入会被 409 拦截。契约测试 21 → 41 项。
阶段五
故事库万级化 + 推荐引擎
故事从代码内置迁到 SQLite（20 篇是种子，库容量无上限）；推荐引擎只扫元数据列（5,406 篇实测：全库扫描 3.7ms、推荐+取正文 35ms）；硬不重复（集合差集，非概率）+ 每日主题轮换（家庭×日期确定性哈希）+ 喜好加权 + 安可机制（全库讲完挑最久未讲）；"今晚已讲 N 个"真实计数注入人设。扩库双管线：import_stories.py（清洗/安全拒收/去重/主题归类）+ generate_stories.py（LLM 批量原创，万篇一夜）。实测灌入清华 STORAL 中文寓言语料：8,379 篇去重 → 5,386 篇入库（过短 656/过长 2,132/安全拒收 193/重复 12）。注意：STORAL 无商用许可，正式售卖前换授权语料或全量原创生成。
阶段六
录音攻坚（本篇最有含金量的部分，见下节）
从"按回车结束不了"到真实 7.9 秒语音过全链路，连踩九坑全记录。

录音工具攻坚实录：九连坑

需求很简单：命令行录一段孩子的声音当测试语料。在 macOS 上从零踩到通，每一坑都是可复用的结论。

#现象根因修法（已固化在 tools/record.py）
1永远提示"没找到麦克风"ffmpeg 设备列表每行带 [AVFoundation indev @ 0x…] 前缀，解析把前缀当设备号正则 \[AVFoundation indev @[^\]]*\]\s*\[(\d+)\]\s*(.+)$ 匹配
2按回车停止无效input() 行缓冲 + 无任何过程反馈，用户不知是否在录termios cbreak + select，任意键即停；每秒刷新倒计时
3开始后 0 秒即停"开始"的回车带尾巴按键，被立即当成停止键cbreak 前清缓冲（tcflush）+ 开录 1s 内按键一律视为误触吞掉
40 字节文件、ffmpeg 零报错设备编号漂移：Xiaomi Buds Wi-Fi 连断会重排编号，开到不在通话态的 Wi-Fi 耳机=零帧零错开录瞬间按名字重新解析编号（resolve_index_now），不再用几秒前的旧编号
5倒计时"已收 0KB"但实际在录ffmpeg 默认攒 ~32KB 才落盘-flush_packets 1 实时落盘，字节数才是真话
6停止后脚本崩溃（TimeoutExpired 堆栈）avfoundation 卡住时 ffmpeg 对 SIGINT/SIGTERM 都不响应三级停止：SIGINT(3s)→SIGTERM(3s)→SIGKILL，全部 try 住
7强杀后 WAV 显示 37 小时时长WAV 头长度字段是垃圾值，且 wave 能"成功"打开录完无条件按实际 data 块重写规范 44 字节头（normalize）
8录到全是零终端 App 没有 macOS 麦克风权限（TCC），系统给静音流；语音输入法能用不算数（那是输入法的权限）静音检测 + 明确指引；tccutil reset Microphone <bundle-id> 重置让弹框重现
9权限弹框始终不出现命令行工具不弹框，权限挂宿主 App；被拒过一次的 App 永远静默拒绝保底路径 --from-file：QuickTime/语音备忘录录完转换，完全不碰权限
终态验证（2026-09-21 16:05–16:20）
真人 7.9 秒语音（峰值 6918）→ record.py 采集入库 testdata/latest.wav → 设备通道上传 → 服务端存档 rec_c07c980faf → 童声 TTS 回复 3.8s → 家长端绑定（6 位绑定码/设备码均验证）→ 时间线回听 → 音频回取与本地字节级一致（存档无损） → 44 项契约测试全绿。转写为空属预期（未配 ASR key，降级模式）。

固件侧：站在仓库实测知识上

板级代码全部继承同仓库（ESP32-S3-Touch-AMOLED-1.8）已验证结论，不凭 datasheet 重写——这是本次固件一次编译通过、无需上板调试的底气。固件任务布局：mic(core0,p10) spk(core0,p9) app(core1,p6 状态机) ui(core1,p5 渲染) + WS 内部任务。三处首编译错误的教训：环形缓冲大小必须 2 的幂（取模掩码）、esp_heap_caps.h 别写成 heap_caps.h、esp_websocket_client 新版把 register_events 改名为 esp_websocket_register_events。

冷启动黑屏（必带）AMOLED 电源走 AXP2101 ALDO1，PMU 上电默认关——每次开机先恢复 DC1/ALDO1 再碰屏，否则"日志全正常但屏幕全黑"。
触摸失灵（必带）FT3168 复位脚在 I2C GPIO 扩展器 0x20 bit2，USB 重插后 Hi-Z——须先走释放序列，否则触摸死了还以为代码有 bug。
ES8311 麦克风读全零esp_codec_dev 封装不选模拟麦输入，要手写 0x14/0x17 两个寄存器；codec 双向必须常开（I2S 从机，关一侧另一侧没时钟）。
播放节拍纯硬件I2S 阻塞写驱动做节拍，欠载短等不插静音；空闲必 vTaskDelay——spk 空转曾饿死 IDLE 看门狗。
