手势导航设计：上一条 / 下一条 / 确定 / 返回

Vibecoding 魔杖扩展方案 · 2026-09-22 · 状态：待评审（本地未提交）

§1 这是什么

给 Vibecoding 魔杖（见 主方案）补上「选单导航」能力：agent 抛出选项列表 / 计划评审 / diff 翻页时，用四个手势完成 上一条、下一条、确定、返回，全程不碰键盘。这四个是高频动作——AskUserQuestion 的选项、fzf 列表、y/n 确认——比打字快，而且和已拍板的四个裁定手势（画圈=发送、下劈=接受、横挥=拒绝、双摇=急停）共用同一条识别流水线，只是词汇表从 4 类扩到 6 类，映射按状态机分发。

本文回答三个问题：① 手势怎么设计、怎么映射；② 识别的窗口 / 触发 / 去抖怎么做（与 WakeNet 同构）；③ 实时算力到底够不够（结论：够，且余量很大）。

§2 手势词汇表与状态映射

2.1 词汇表：4 → 6 类（+ 背景）

原 4 类里的「横挥」按左右拆开（互为镜像，CNN 区分无压力），再新增「翻腕」。全部 6 类 + 背景类 = 7 分类：

手势动作IMU 特征（为什么不易混）新增/沿用
画圈手腕画圆某轴角速度完整正弦周期（~0.5–1 Hz），能量包络平滑沿用
下劈竖直向下快劈垂直轴加速度单脉冲 + 横轴角速度尖峰沿用
左挥水平向左快挥水平轴加速度单脉冲（负向起），与右挥镜像横挥拆分
右挥水平向右快挥水平轴加速度单脉冲（正向起）横挥拆分
双摇上下摇两下两个清晰加速度峰 + ~200 ms 节奏间隔沿用
翻腕持杖手旋后翻 90–180°陀螺仪主导：|ω| 大而加速度尖峰小——与其余平动类天然正交新增

2.2 状态 × 手势映射总表（手势 map）

状态手势 → 动作注入按键（tmux send-keys）
选单态（新增）左挥=上一条 · 右挥=下一条 · 下劈=确定 · 翻腕=返回Up · Down · Enter · Escape
确认态（转写评审）画圈=发送 · 左挥/右挥=作废重说Enter · 无注入，仅状态回退
施法中（agent 运行）下劈=接受 y · 左挥/右挥=拒绝 Esc · 双摇=急停 Esc Escy · Escape · Escape Escape
空闲手势只做杖屏反馈，不注入任何按键（防误伤）—
「确定」复用已有的下劈（物理隐喻一致：下劈=拍板）；「返回」用翻腕（新增），语义像「把这一页翻过去」，且陀螺主导的信号与平动类手势正交，是最省训练成本的一个新类。左/右挥在确认态与施法态退化为原「横挥」语义（任一水平挥都算），只在选单态才有方向性——同一个分类器，映射随状态走。

2.3 选单态怎么进出

agent 什么时候在等选择，daemon 并不总是知道。两步走：

  • v0.5（拍板）：双击杖侧键（BtnA）手动进 / 出选单态。简单、可靠、零解析成本，杖屏显示 ☰ 提示当前处于选单态。
  • v1（增强）：daemon 用 tmux capture-pane -p 抓目标窗格文本，命中选项列表特征（数字编号行、AskUserQuestion 的选项卡）自动进入，超时或出现提示符自动退出。识别失败无害——只是没自动进。

选单态下的 Up/Down/Enter/Escape 是 TUI 通用按键：ZCode 选项列表、fzf、vim 弹出菜单、htop 全都吃这套键，所以手势导航天然通吃各种终端交互，不绑定具体 agent。

§3 识别流水线：与 WakeNet 同构

手势识别和唤醒词确实是同一个问题形态——固定长度滑窗 + 触发门限 + 时间去抖，只是流从音频帧换成 IMU 帧。对照表：

WakeNet（音频）手势版（IMU）本方案取值
PDM → 16 kHz PCMBMI270 → 100 Hz 6 轴原始流100 Hz × 6ch = 600 样本/s（已定）
VAD / 能量门加速度能量门（武装/收段）‖a‖−1g 偏差 > 0.25g 持续 ≥30 ms → 武装
log-mel 特征帧原始 6 轴直接进网（IMU 无需手工特征）窗口 0.8 s = 80 帧 × 6ch
滑窗推理（帧移 ~30 ms）滑窗推理（步长 100 ms，仅武装期间）10 Hz 滑窗
unknown / 背景类背景类（拿起、放下、打字震动的负样本）第 7 类，采集时重点喂
连续 N 帧判稳 + 状态锁定top-1 score > 0.8 连续 2 窗（2/3 投票）→ 触发+ 冷却锁定 700 ms

3.1 分段与触发细节

  • 武装（arm）：能量门命中 → 从触发点回看 0.3 s 开始缓存（快挥的先导动作在尖峰前）。
  • 收段（close）：能量回落到门限以下持续 150 ms → 段结束，缓冲补齐 / 截取到固定 0.8 s 窗。
  • 早发（emit-early）：不等收段——滑窗一旦凑够 2/3 投票立即触发。左/右挥这类 300 ms 短动作，从动作开始到杖屏反馈约 250–400 ms，体感「即时」。
  • 冷却锁定：触发后 700 ms 内只缓存不发（一次物理动作只出一条命令）；杖屏箭头反馈 + 蜂鸣 tick 一声。
  • 误触发三件套沿用主方案 §4.5（能量门 + 置信度 + 冷却），这里只是把参数和 WakeNet 对齐写死。

§4 算力账：实时够不够

4.1 部署位置（分两步，均已拍板）

  • v0 / v0.5：分类器跑在 Mac 端 daemon（主方案已拍板的架构），杖端只上行 IMU 裸流（1.2 KB/s）——杖端零算力问题，导航功能先跑起来。
  • v1：分类器与唤醒词一起下沉到杖端（主方案预留的路）。算力账如下。

4.2 杖端预算（ESP32-S3，双核 LX7 @240 MHz）— 精算 + Mac 实测，上板待验

2026-09-22 修订：原"<15% 单核"为纸面估算。现按 wakenet 真实架构精算 MACs、其 C 运行时在 Mac 本机（clang -O2）实测耗时，再外推 S3。ESP32-S3 标量按 2–3 cycle/MAC（80–120 M MAC/s）、ESP-NN 8-bit SIMD 按 3–5× 计；最终数字以上板实测为准（基准脚本已备：wakenet/esp32/stick_s3_bench/，15 分钟出数）。

§5 数据与训练

  • 采集：复用 magic-wand/wakenet 的 record.py 模式——杖插 USB，Mac 端脚本收 'I' IMU 帧，键盘敲标签，按「手势名_序号」落盘。每类 ≥ 50 次 × 3 种姿态（坐姿正握 / 站姿 / 换手），背景类随手日常动作 ≥ 10 分钟（含拿起放下、打字、走路）。
  • 增强：时间扭曲 ±15%、高斯噪声、绕重力轴 ±10° 旋转抖动（模拟握姿差异）、随机左右镜像生成对称样本（注意：镜像会交换左/右挥标签，只用于非方向类）。
  • 训练：沿用 wakenet 流水线（类平衡采样 + QAT + int8 逐通道量化 + C/numpy 对拍）。
  • 验收指标：逐类准确率 > 97%；混淆矩阵重点盯左挥↔右挥（快而敷衍的挥动）和翻腕↔拿起放下（背景类）。

① 左/右挥混淆：用户敷衍时会挥成斜线 → 靠采集时故意混入「快速随便挥」样本 + 镜像类数据增强；仍混则 UX 兜底（选单态左右挥连续误跳只是光标移动，无破坏性）。② 翻腕误触：自然的拿笔/放笔动作接近翻腕 → 背景类负样本重点覆盖；必要时给翻腕加时长下限（> 400 ms 的持续旋转才算）。③ 选单态忘退：双击进入后 30 s 无手势自动退回空闲态，杖屏闪烁提示。
