资料收集与引脚逆向

没有引脚表就没有驱动。这一章讲去哪里找资料，以及怎么从一份原理图 PDF 机器化地提取引脚映射。

2.1 资料清单：拿到板子先收集什么

资料去哪找用来干什么
两份原理图 PDF（主板 9 页 + 接口板 2 页）随板附带 / 卖家网盘引脚映射的唯一权威来源
原厂 Demo 工程（GPIO/LCD/SDRAM 三个）同上时钟树、外设参数、LCD 驱动的「已知正确答案」
WeAct GitHub 组织github.com/WeActStudio找同系列板卡的开源资料
WeAct 的 OpenMV 固件分支github.com/WeActStudio/openmv 的 WeActStudio 分支宝库：板级配置、传感器寄存器表、探测流程、DCMI 极性，全在里面
ST 官方 STM32CubeH7github.com/STMicroelectronics/STM32CubeH7HAL 驱动源码（按 tag 取，如 v1.11.1）
WeAct 的 OpenMV 分支里有 src/omv/boards/WeActStudioSTM32H7xx/omv_boardconfig.h——虽然那是给 MiniSTM32H7xx 板的（引脚不能照抄），但它给出了 XCLK 频率、PLL 配置、各传感器的 VSYNC 极性、I2C 地址等「软件侧真相」，与原理图逆向的结果互相印证后就是高置信度结论。
git clone --depth 1 -b WeActStudio https://github.com/WeActStudio/openmv.git

2.2 为什么不能直接抄相近板卡的固件配置

真实案例：WeAct 自己的固件里 D2=PE0、D3=PE1、D5=PD3。但 OpenMV Plus 带 32MB SDRAM，PE0/PE1/PD3 被 FMC 占用，摄像头数据线被挪到了 PG10/PG11/PB6。如果照抄，现象会是「SCCB 能识别传感器、彩条能出、但真实图像全是均匀噪声」——因为数据线根本没接对。同厂商 ≠ 同引脚，每一块新板都要回到原理图。

2.3 从原理图 PDF 提取引脚映射的方法论

手上有 PDF 没有 netlist 时，用 PyMuPDF 按坐标提取文字 + 几何配对两步走：

第一步：拿到带坐标的文字

import fitz
doc = fitz.open('board.pdf')
words = doc[1].get_text('words')   # (x0, y0, x1, y1, word, ...)

Altium 导出的 PDF 里，MCU 符号的每个引脚都印着一串复用功能文本（形如 PC6/I2S2_MCK/TIM8_CH1/.../DCMI_D0），而网络标签（DCMI_D0）贴在引脚的连线端。

第二步：按 y 中心偏移配对

网络标签与它所属引脚功能串的 y 中心恒差 -2.1 ~ -2.3 pt（同一版图排版规律）。用这个规则配对，比「最近邻」可靠一个数量级——最近邻会把 PG9/PG10、PB5/PB6 这类相邻引脚搞混。

# 伪代码：网络标签 y 中心 ≈ 引脚功能串 y 中心 - 2.1
for net_label in labels:
    for pin_func_string in pins_on_same_side:
        if -3 < (net_center_y - pin_center_y) < -1.4:
            match(net_label, pin_name)   # 如 DCMI_D0 → PC6
视觉大模型看原理图不可靠：MCU 符号上印的复用功能名会当成答案「背出来」（把 DCMI_D8~D13 这些没连接的复用名当成实际连线）。坐标几何方法没有这个问题。

2.4 交叉验证

提取结果必须过两道验证再用：

  • 功能合理性：每个 DCMI 引脚查 AF13 表（如 PG10 AF13 = DCMI_D2 ✓）；控制类引脚（PWDN/RST/XCLK）应为 GPIO/定时器通道
  • 与已知固件对比：与 WeAct 固件的板配置逐脚 diff，差异处必须有解释（本板的差异全部能用「SDRAM 占用」解释）

2.5 Demo 工程里还能白捡什么

  • LCD_TEST：SPI2 全部参数、背光 PWM、时钟树代码、编译宏 TFT96（屏型号）、厂商 lcd.c 显示路径（后面直接整体复用）
  • SDRAM_TEST：FMC 配置与 EXT_SDRAM_ADDR（本教程未用 SDRAM，跑大分辨率时回来抄）
  • GPIO_TEST：最小时钟模板

三个 Demo 都是 CubeMX+Keil 工程，.ioc 文件里的引脚标签（如 PD13.GPIO_Label=LCD_WR_RS）本身就是一份引脚清单，与原理图逆向互为印证。
