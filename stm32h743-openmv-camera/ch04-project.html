工程骨架：从 Keil Demo 到 GCC Makefile

原厂工程是 Keil 的，Mac 跑不了。这一章自建一个等价的 GCC 工程。

4.1 为什么不用 CubeMX + Keil

原厂 Demo 是 CubeMX 生成、Keil MDK 编译的。问题：MDK 是 Windows-only，开发机是 macOS。选择：

  • STM32CubeIDE（有 Mac 版）：可行，但要装整套 Eclipse，且对已有 CubeMX 工程的导入有版本兼容问题
  • GCC + Makefile 自建：透明、可脚本化、复用 Demo 的全部 .c/.h 源码 —— 本教程的选择

代价是要自己解决三样东西：启动文件、链接脚本、HAL 配置。下面逐个讲。

4.2 工程目录结构

CAMERA_LCD_TEST/
├── Makefile               # 构建（源码 wildcard，hal_conf 控制模块开关）
├── STM32H743IIK6.ld       # 链接脚本（内存域 + 帧缓冲固定段）
├── startup_stm32h743xx.s  # GCC 启动文件（来自 ST CMSIS 模板）
├── Core/
│   ├── Inc/  main.h(引脚宏) stm32h7xx_hal_conf.h stm32h7xx_it.h gpio/spi/tim.h
│   └── Src/  main.c gpio.c spi.c tim.c(原厂CubeMX文件) stm32h7xx_it.c system_stm32h7xx.c
├── Cam/                   # ★ 摄像头驱动（本教程核心产出）
│   ├── cam.c / cam.h              # 探测、初始化、DCMI 采集、调试钩子
│   ├── cam_regs.h                 # 板级时钟常量 + 寄存器表声明
│   └── ov7725/5640/2640/7670_regs.c/.h   # 自动生成的寄存器表
├── BSP/ST7735/            # 原厂 LCD 驱动全套（st7735.c lcd.c font.h，原样复用）
├── Drivers/               # HAL v1.11.1 + CMSIS（从 Demo 复制，DCMI 从 CubeH7 v1.11.1 补）
└── tools/                 # dump_frame.sh / frame2png.py（远程验证工具）

4.3 启动文件

GCC 语法向量表 + 复位初始化，不要手写——从 ST 的 CMSIS Device 模板或任意 GCC 构建的 H7 工程里取一份 startup_stm32h743xx.s（本教程从 WeAct 的 openmv 固件仓库直接拿的，768 行）。

4.4 链接脚本要点

MEMORY
{
  ITCMRAM (xrw) : ORIGIN = 0x00000000, LENGTH = 64K
  FLASH   (rx)  : ORIGIN = 0x08000000, LENGTH = 2048K
  DTCMRAM (xrw) : ORIGIN = 0x20000000, LENGTH = 128K
  RAM_D1  (xrw) : ORIGIN = 0x24000000, LENGTH = 256K   /* 数据/bss/栈 */
  RAM_FB  (xrw) : ORIGIN = 0x24040000, LENGTH = 64K    /* 帧缓冲专用段 */
  RAM_D2  (xrw) : ORIGIN = 0x30000000, LENGTH = 288K
  RAM_D3  (xrw) : ORIGIN = 0x38000000, LENGTH = 64K
}
/* 帧缓冲固定地址 + 32 字节对齐 + NOLOAD */
.frame_buffer (NOLOAD) : { . = ALIGN(32); frame_buffer_start = .;
  KEEP(*(.frame_buffer)) . = ALIGN(32); frame_buffer_end = .; } > RAM_FB
为什么帧缓冲要固定在 0x24040000：① MPU 非缓存区需要 2 的幂大小、地址对齐——64 KB @ 固定地址直接满足；② 调试脚本里地址写死，符号挪了也不用改工具。普通 .data/.bss 留在 RAM_D1 低 256 KB。

注意别把 ST 模板里 /DISCARD/ { libc.a libm.a libgcc.a } 那段抄进来——会把 memcpy 等运行时库剥掉，链接报未定义。

4.5 Makefile 要点

CPU = -mcpu=cortex-m7 -mthumb -mfpu=fpv5-d16 -mfloat-abi=hard
DEFS = -DUSE_HAL_DRIVER -DSTM32H743xx -DTFT96     # TFT96=0.96寸屏型号
LDFLAGS = $(CPU) -TSTM32H743IIK6.ld -Wl,--gc-sections \
          --specs=nano.specs --specs=nosys.specs \
          -Wl,--start-group -lc -lm -Wl,--end-group
SRCS = $(wildcard Core/Src/*.c Cam/*.c BSP/ST7735/*.c Drivers/.../Src/*.c)
  • HAL 的每个 .c 被 #ifdef HAL_XXX_MODULE_ENABLED 包着，wildcard 全编 + hal_conf 开关 = 免维护源文件清单
  • -DTFT96：屏型号宏，来自原厂 Keil 工程的 Define 栏（grep Define *.uvprojx 可查）
  • GBK 编码的原厂源码要转 UTF-8 再编（脚本批量 iconv），否则个别字节序列会坑编译器

4.6 HAL 移植

  • 从 LCD_TEST Demo 整目录复制 Drivers/（HAL 1.11.1 + CMSIS）
  • DCMI 驱动 Demo 里没有：从 STM32CubeH7 对应 tag（v1.11.1）单独取 stm32h7xx_hal_dcmi.c/h——版本对齐很重要，API 细节跨版本有差
  • stm32h7xx_hal_conf.h 里按需开模块：DCMI / DMA / I2C / SPI / TIM / GPIO / RCC / FLASH / PWR / CORTEX / EXTI / HSEM
  • 原厂 gpio.c/spi.c/tim.c（CubeMX 产物）是纯 C，直接进工程——这就是「已知正确」的外设初始化（含 LCD_RST 初始拉低等细节）

4.7 一个工程两种构建：对照实验模板

调试黑屏时用同一套 Makefile/启动/链接把原厂 LCD_TEST 的 Core+BSC 原样编成 LCD_TEST_GCC/——GCC 构建能跑原厂逻辑，就把「工具链/链接问题」和「驱动代码问题」一刀切开（第 7 章的决胜实验）。
