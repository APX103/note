摄像头驱动：SCCB 探测与传感器初始化

「找不到 Camera」的正确打开方式：探测时序、识别、四种传感器的配置方法。

5.1 摄像头驱动的分层

          ┌─ 控制面：SCCB(I2C1) ── 寄存器读写（探测/配置/曝光）
应用层 ───┤
          └─ 数据面：XCLK(PA8 PWM) → 传感器 → DVP 8bit → DCMI+DMA → 帧缓冲
                     PWDN(PD7) / RESET(PA10) 电源时序

5.2 XCLK：传感器的心跳（第一个天坑在此）

OV 传感器没有输入时钟时连 SCCB 都不会应答——这就是「找不到 Camera」最常见的根因。XCLK 由 TIM1_CH1（PA8）PWM 生成：

// TIM1 时钟 240 MHz（APB2 120M × 2）
div = 240M / hz;          // 24 MHz → div=10
htim1.Init.Prescaler = 0; htim1.Init.Period = div - 1;
HAL_TIM_PWM_ConfigChannel(&htim1, &oc/*Pulse=div/2*/, TIM_CHANNEL_1);
HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_1);   // TIM1 是高级定时器，会置 MOE
天坑：HAL_TIM_PWM_Init() 只配置定时器，不配置引脚！必须自己 HAL_GPIO_Init 把 PA8 设成 AF1(TIM1)，否则 XCLK 悬空、SCCB 必然无应答。这个坑的完整复盘见第 7 章。

频率策略：先用 12 MHz 探测（所有 OV 都能起振），识别芯片后再切工作频率（OV5640/OV2640/OV7670 → 24 MHz，OV7725 保持 12 MHz）。

5.3 探测流程（OpenMV 同款，实测可靠）

1. PWDN 拉高 10ms → 拉低 10ms          // 电源循环
2. RESET 拉低 10ms → 拉高 10ms          // 先按"低有效"复位
3. I2C 总线扫描 0x08~0x77（IsDeviceReady）
   └─ 无应答？换 RESET 极性再扫；再无？换 PWDN 极性 —— 共 4 种组合
4. 命中地址后读芯片 ID：
   0x30 → reg 0x0A = 0x26 → OV2640
   0x21 → reg 0x0A = 0x77 → OV7725   = 0x76 → OV7670
   0x3C → reg 0x300A = 0x56 → OV5640
H7 专属：I2C 扫描失败后总线可能卡死，__HAL_I2C_DISABLE → 10ms → ENABLE 可救回（OpenMV 注释，实测有效）。另外把 I2C1 内核时钟切到 HSI(64MHz)，时序值 0x10707DBC=100kHz 就与 PCLK 无关了，省心。

5.4 SCCB 就是 I2C

HAL_I2C_Mem_Write(&hi2c1, addr7<<1, reg,  I2C_MEMADD_SIZE_8BIT,  &val, 1, 100);  // 8位寄存器
HAL_I2C_Mem_Write(&hi2c1, addr7<<1, reg,  I2C_MEMADD_SIZE_16BIT, &val, 1, 100);  // 16位(OV5640)

HAL 用 8 位地址形式（7-bit 左移一 位）。OV 的 SCCB 协议与 I2C 兼容到可以直接用 HAL 外设，无需软件模拟。

5.5 寄存器表：不手抄，脚本提取

四种传感器各有一份几十到几百行的初始化表。手抄必错，用脚本从 OpenMV 源码提取（.research/gen_tables.py）：

  • 表里的宏表达式（如 {COM7, COM7_SET_RES(com7, COM7_RES_QVGA)}）原样透传给 C 编译器求值——把解析难题交给编译器
  • 三个坑：① OpenMV 四个 *_regs.h 共用同一个 include guard __REG_REGS_H__，必须改成各不相同的 guard；② SVGA_WIDTH/UXGA_WIDTH 等常量定义在 .c 里不在头文件，要补；③ 表终止符统一 0xFF
  • 板级相关值（PLL 配置随 XCLK 频率）在 cam_regs.h 集中定义：OV5640@24MHz → PLL CTRL2=0x64/CTRL3=0x13

5.6 四种传感器的分辨率配置思路

传感器目标输出配置方法
OV7725160×120QVGA 传感器窗口（HSTART/HSIZE…）+ DSP 自动缩放，HOUTSIZE=w>>2、VOUTSIZE=h>>1
OV5640108×80（等比全视场）时序窗口数学（TIMING_HS/HW/VS/VH + X_INC/Y_INC 2 倍抽取 + ISP 输入窗口缩放），见 5.7
OV2640160×120SVGA(800×600) 基础表 + CTRLI 2 分频 + HSIZE/VSIZE 窗口 + ZMOW/ZMOH DSP 缩放

5.7 OV5640 的窗口数学（移植自 OpenMV，两个改动）

  1. 等比缩放必须用浮点 ratio：ratio = min((640/2)/w, (480/2)/h)，整数除法会让宽高两轴倍率不一致 → 画面变形。ISP 输入窗口 w_mul = w×ratio、h_mul = h×ratio 再居中。
  2. 低光照模式：把 OpenMV 公式的 VTS=268 改成 1620。原理见第 7 章坑 4——帧率从 42 换 17fps，最大快门从 9.6ms 变 58ms，暗光光量 ×6。
OV5640 的 RGB565 输出：0x4300=0x6F + 0x501F=0x01。VSYNC 极性默认高有效（DCMI VSPOL=HIGH）。
