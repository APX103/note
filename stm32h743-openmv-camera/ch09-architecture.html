9.3 六个关键设计决策

#决策替代方案为什么这么选
1传感器端 ISP 缩放（108×80 直接输出）CPU 软件缩放零 CPU 成本、DMA 带宽省 40%；H7 跑软件缩放也够，但能在传感器端解决的不要搬 CPU
2快照模式一帧一停连续+双缓冲+帧同步中断RM0433 保证重使能自动等帧头，天然无撕裂；代码量 1/5
3帧缓冲固定地址 + MPU 非缓存链接器任意放置 + 每帧 Cache 维护一次性配置免心智负担；调试工具地址写死
4显示层整体用原厂路径自写最小驱动黑屏教训：SPI 无回读，自写层出错不可观测；显示是「调通即用」外设
5SWD 调试窗口常驻（状态结构+dbg_ctrl）串口 printf无串口线依赖；读写内存即可热调参；与工具脚本组成可重复实验回路
6寄存器表脚本生成手抄/手打几百行表手抄必错；宏表达式透传给编译器求值，生成器 60 行搞定四种传感器

9.4 主循环骨架（伪代码）

for (;;) {
    now = tick();
    if (ok && cam_capture(500) == 0)                 // 等一帧（快照）
        FillRGBRect(居中, frame_buf + 1, 108, 80);    // +1 字节相位
    else if (!ok) { 显示失败原因; 红灯闪; }

    if (照明开 && now - led_on > 15s) 灯灭;          // 防烫超时
    if (KEY按下) 切换照明;

    if (now - t_last >= 1000) {                       // 1Hz
        fps = frames - frames_last;
        cam_dbg_aec();                                 // 活的曝光/增益读数
        刷新OSD状态条;
    }
}
