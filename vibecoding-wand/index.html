§0决策速览

这个方案的所有"都可以"已经全部定死。原则：Demo 优先，每一项都选最快能玩起来且演示效果最好的那条路。

决策项✅ 定案一句话理由
触发方式v0 = 按住魔杖键说话（PTT）；v1 = 自研唤醒词你说的"按一下然后说话"——PTT 零误触、零功耗、演示最稳；唤醒词引擎已经做好了（33KB、召回 100%），属于白送的升级，放 M5。
魔杖 ↔ 电脑链路USB-C 直连（虚拟串口 CDC），不用 BLE / 不用 WiFi供电+数据一根线、零配对零丢包；16kHz PCM 裸流 32KB/s 对 USB 毫无压力。无线化（WiFi+ADPCM）是 v1.5，不阻塞 Demo。
语音识别Mac 系统自带 SFSpeechRecognizer（免费、无 key）中英文都能用、不用下模型不用申请 API；备选 whisper.cpp（完全离线）。
注入 Agent 的方式首选 tmux send-keys + 剪贴板粘贴，备选 CGEvent 全局键盘CLI Agent（ZCode/Claude Code）本来就跑在 tmux 里；send-keys 无需任何系统权限、可精确指定目标窗格。CGEvent 需要辅助功能权限，留作通吃任意窗口的备胎。
手势识别跑在哪v0 = 电脑端（IMU 原始流上行，daemon 里分类）；v1 下沉到杖上IMU 6 轴 @100Hz 只有 1.2KB/s，上行后训练/调类零部署成本，改手势集当天生效；上板路径（TFLM/C）在魔杖方案里已经铺好。
语音是否直发不直发：转写先进"确认态"，画圈才发送ASR 一定会错（"dark mode"→"达克模式"），确认态让错误止步于杖屏，不污染 agent 会话。这也让手势有了第一个高频用途。
手势集4 个：画圈=发送/继续、下劈=接受、横挥=拒绝、双摇=急停正好覆盖 vibecoding 全部高频操作（Enter / y / Esc / Esc-Esc），IMU 特征轴分布互不重叠。
固件框架Arduino（arduino-cli，已验证工具链）StickS3 刷机全流程在仓库笔记里跑通过；USB CDC On Boot 一个开关搞定。

§1这是什么：90 秒演示脚本

vibecoding 的日常：对着 agent 终端敲 y、按 Esc、偶尔 Esc Esc 急停、再打一段中文需求。这个玩具把全部四个动作换成手势和说话，让"人机结对"变成"施法"。

  1. 开场：tmux 里开着 ZCode（某个真实项目目录），魔杖插在 Mac 上，杖屏一枚 ✦ 待机。
  2. 下咒：按住魔杖侧键说「给这个页面加一个暗色模式开关，放在右上角」，松开。杖屏实时跳动波形。
  3. 确认：1~2 秒后杖屏滚出转写文字 + Mac 右上角通知。画一个圈 = 发送（daemon 把文本写剪贴板、tmux 粘贴 + 回车）；觉得转写稀烂就横挥作废重说。
  4. 施法：agent 开始改代码，杖屏转圈「施法中…」。
  5. 裁定：agent 请求确认时——下劈 = 接受（y），看它写得不顺眼就横挥 = 拒绝（Esc）。
  6. 反噬：agent 跑飞了开始疯狂建文件——摇两下 = 急停（Esc Esc），杖屏红光一闪「法术已打断」。
  7. 收场：全程双手没碰键盘。这就是 vibecoding 魔杖。
为什么这个玩具成立：语音解决"长意图输入"（打一段中文需求很累，说一句很爽），手势解决"高频短确认"（y/Esc 每天几十次，挥手比摸键盘帅）。两个痛点都是真实的，只是被合并进了一根杖里。顺带：演示视频天然适合发抖音。

§2交互与状态机

图 1 · 魔杖 × daemon 联合状态机。「施法中」内部的三种手势裁定：下劈=接受（y）、横挥=拒绝（Esc）、双摇=急停（Esc Esc）；「确认」态里画圈=发送、横挥=作废。空闲态的手势只做杖屏反馈、不注入任何按键——防止误伤正在写的代码。

2.1 手势语义表（4 个）

手势动作IMU 特征（为什么不易混）映射生效状态
画圈手腕画一个圆某轴角速度完整正弦周期（~0.5–1Hz）发送 / 继续（Enter）确认、施法中
下劈竖直向下快劈垂直轴加速度单脉冲 + 横轴角速度尖峰接受（y / 选 1）施法中
横挥水平快速一挥水平轴加速度单脉冲，与下劈轴向正交拒绝（Esc）确认（作废）、施法中
双摇上下摇两下两个清晰加速度峰 + 节奏间隔急停（Esc Esc）施法中

对比远程控灯魔杖的 3 手势集：新增「下劈」并与「横挥」靠轴向区分，采集/训练流水线完全复用，只是类别数 3→4。

§3系统架构

图 2 · 系统架构。魔杖只做「传感器 + 屏幕 + 事件源」，所有智能在 Mac 端 daemon；对 Agent 终端零侵入——这就是 v0 能在三天内做完全部秘密。
设计要点：杖端固件保持「傻」（采音、采 IMU、画屏、发帧），识别/映射/状态全在 daemon。好处：改手势集、换 ASR、换 agent 都只动 Python，固件基本冻结；将来把分类器/唤醒词下沉到杖上（两条路都已铺好）也不改变协议。

§4技术选型：三处分叉怎么定的

4.1 魔杖 ↔ 电脑：USB CDC

维度USB-C CDC ✅BLEWiFi (UDP/WS)
配对/连接管理插上即用，零配对GATT 服务 + 连接参数 + 断连重连一套全要写要配网、管断线重连
音频带宽16kHz 裸 PCM 32KB/s 轻松吞吐勉强、抖动难控，得压缩够，但裸流占空口
供电同一线供电，永远在线电池 + 充电管理电池（WiFi 较耗电）
演示自由度拖一根线（约 1m 活动半径）无线无线
实现成本Arduino "USB CDC On Boot" 一个开关高中（v1.5 再上，加 ADPCM 压缩到 8KB/s）
✅ 定案：v0 用 USB CDC。玩具演示在书桌前完成，一根 USB-C 延长线就是"魔法范围"；真要无线，v1.5 加 WiFi + ADPCM，协议不变。

4.2 语音识别：系统自带 SFSpeechRecognizer

维度SFSpeechRecognizer ✅whisper.cpp云端 API
成本/准备免费，pip 装个 pyobjc 框架包就能调免费，编译 + 下模型（~150MB）要 key 要钱
中英文都支持，混说尚可small 以上不错，tiny 一般最好
延迟录音结束 1~2s 出文字小模型数秒（M 系很快）看网络
离线部分语言走本机，部分需联网（无 key）完全离线否

转写错误有「确认态」兜底（画圈前不上屏进 agent），所以 ASR 不需要顶配——这也是整个方案敢用免费方案的心理底气。

4.3 注入 Agent：tmux send-keys 为主

  • 首选 tmux：CLI agent 用户本来就活在 tmux 里；load-buffer 写剪贴板 → paste-buffer → send Enter 三条命令完成一段长中文注入；send-keys Escape 天然就是拒绝/急停。不需要任何系统权限，也不会误伤别的窗口。
  • 备选 CGEvent（pyobjc 全局键盘事件）：通吃任意窗口（比如网页版 agent），但要辅助功能权限、且依赖焦点位置。Demo 不依赖它。
  • 目标窗格：daemon 配置文件写死 session:window.pane（例如 dev:0.0），并提供一条「指向当前窗格」的 CLI 小命令。

§5通信协议（USB CDC）

一根串口上跑三种帧，统一「类型 + 长度」封包，解析十几行写完：

帧格式: [type:1B 'J'|'A'|'I'|'S'] [len:2B 小端] [payload]
  'J' 控制行(JSON, UTF-8)
  'A' 音频   payload = 16kHz/16bit/单声道 PCM 切片
  'I' IMU    payload = 6×int16 (ax ay az gx gy gz) @100Hz
  'S' 状态   daemon→杖，驱动杖屏 UI
// 杖 → daemon
{"t":"ptt","down":true}          {"t":"ptt","down":false}
{"t":"battery":87}
// daemon → 杖
{"t":"state","s":"review"}       {"t":"asr","text":"给这个页面加一个暗色模式开关…"}
{"t":"gesture","g":"circle"}     // v0 由 daemon 分类后自环（杖端 v1 才发）

波特率概念在 USB CDC 上只是摆设（实际走 USB 全速），32KB/s 音频 + 1.2KB/s IMU 合计带宽占用不到 5%。

§9风险与对策

编号风险对策（预案先写好，现场不临场发挥）
R1SFSpeechRecognizer 首次要麦克风/语音识别权限，或识别率不达标M1 第一小时就验证；不过关 → 切 whisper.cpp small（M 系 CPU 几秒内出结果），协议不变
R2手势误触发把正在编辑的代码改了双层闸门：仅「确认/施法中」两态映射按键，空闲态手势只做屏显；daemon 一键全局开关（或反手一扣放在桌上）
R3tmux 目标窗格找错 / 用户不在 tmux 里跑 agent配置写死窗格 + 「指向当前窗格」小命令；终极兜底切 CGEvent 全局按键（多一次辅助功能授权）
R4ASR 代码术语翻车（dark mode→达克模式）确认态人工把关 + agent 本来就擅长猜模糊意图；可选：转写后过一层术语词典修正
R5USB 线拽着影响演示姿势1m 延长线先顶着；v1.5 WiFi + ADPCM（8KB/s）无绳化，协议不变
R6杖端与 daemon 状态失步（如急停后杖屏还转圈）daemon 是唯一状态源，杖屏纯渲染 'S' 帧；失步超 2s 杖端自动回空闲

§10刻意不做的事

  • ❌ BLE 音频 / LE Audio —— USB 一根线解决的事不配拥有 GATT。
  • ❌ Agent 侧任何改动、插件、hook —— 魔杖对 agent 完全透明（就当它是键盘）。
  • ❌ 多台电脑 / 多 agent 会话路由 —— 就一个 tmux 窗格。
  • ❌ 语音直发（跳过确认态）—— 一次"达克模式"事故就够毁掉演示。
  • ❌ 云端 ASR/TTS、对话式语音（魔杖不会说话，它只施法）。
  • ❌ 真魔杖外形、3D 打杖身 —— 屏幕+棒状本体已经是魔法了，v2 再说。
  • ❌ OTA、低功耗 —— 插着 USB 呢。
